# bpmsoft-agent

Desktop-приложение (Electron) с ИИ-агентом для разработки проектов на BPMSoft — низкокодовой CRM/BPM-платформе. Агент работает с файлами пакетов в `BPMSoft.Configuration/Pkg`: уточняет задачу, показывает план, после подтверждения пишет файлы, сам обновляет и компилирует стенд и проверяет результат. Провайдеры модели — Claude (Claude Agent SDK) и Cursor.

Правила работы над проектом — [`CLAUDE.md`](CLAUDE.md), бэклог — [`BACKLOG.md`](BACKLOG.md), сценарии ручной проверки агента — [`docs/test-runs/`](docs/test-runs/README.md).

## Требования к компьютеру

Уже в установщике: Claude Code и Cursor SDK под платформу, ripgrep, клиент PostgreSQL (библиотека pg), встроенный браузер CRM, pkg_lint.

| Что | Зачем | Без этого |
|---|---|---|
| ОС macOS 13+ (Apple Silicon или Intel) или Windows 10 1809+ x64 | минимум Claude Code | приложение не даст открыть проект |
| Node.js 18+ в PATH | `node scripts/hierarchy.js` (иерархия клиентских схем) и разовые скрипты `node -e` | предупреждение; клиентские схемы агент делает хуже |
| Git for Windows (только Windows) | Git Bash: через него идут команды агента на Cursor; Claude Code без него переходит на PowerShell | на Cursor проект не откроется; на Claude команды будут спрашивать разрешение каждый раз |
| git (по желанию) | `git status` и откат правок в Pkg | предупреждение; агент пропустит эти шаги |

Git Bash ищется по переменной `CLAUDE_CODE_GIT_BASH_PATH`, рядом с `git.exe` из PATH, в `Program Files\Git` и `%LOCALAPPDATA%\Programs\Git`; bash из `System32` (WSL) не используется. На macOS PATH берётся из терминала пользователя, поэтому Node из Homebrew или nvm будет найден.

**Стенд.** Папка приложения должна лежать на диске этого компьютера, а разработка в файловой системе должна быть включена: в `BPMSoft.WebHost.dll.config` (на .NET Framework — `Web.config`) нужны `<fileDesignMode enabled="true" />` и `<add key="UseStaticFileContent" value="false" />`. Без них или без файла конфигурации проект не откроется; приложение покажет, что поменять, и кнопку «Проверить снова».

Сведения об устройстве и результат проверки — в блоке «Об устройстве» на стартовом экране и в файле `environment.json` в папке логов.

Сборка без нотаризации Apple: при первом запуске — правый клик → «Открыть» или «Системные настройки → Конфиденциальность и безопасность».

## Структура

```
packages/
  metadata-core/   # определение структуры приложения BPMSoft
  agent-runtime/   # запуск агента: промпт, база знаний, песочница, инструменты CRM, БД и pkg_lint
    knowledge/     # база знаний агента о metadata BPMSoft: факты <тип>.md и рецепты <тип>-edit.md
    claude-export/ # AGENTS.md и скиллы для Claude Code и Cursor, которые приложение ставит в стенд
  evals/           # эвалы — автотесты поведения агента на тестовом стенде
apps/
  desktop/         # Electron: выбор проекта, чат, история чатов, разрешения, логи
docs/
  test-runs/       # сценарии ручной проверки агента
  superpowers/specs/ # описания устройства крупных возможностей
.claude/skills/    # скиллы для разработки: разбор эвалов и логов агента
```

## Команды

```bash
npm install
npm run build
npm test
```

Эвалы запускаются на тестовом стенде — настройка в [`packages/evals/README.md`](packages/evals/README.md):

```bash
npm run eval -w @bpmsoft-agent/evals
```

## Принципы разработки

**1. Петля исправлений с контрольной точкой.** Агент сам доводит запись до загрузки и компиляции: ошибка своей схемы — исправить и повторить. Инструменты сообщают номер попытки; после 5 неудач или 3 одинаковых ошибок подряд агент останавливается и спрашивает, продолжать ли. Ошибку в схеме, которую в этом чате не меняли, агент не исправляет молча — спрашивает.

**2. Сначала дешёвые детерминированные проверки.** Всё, что можно проверить кодом, проверяет код, а не модель и не стенд: `pkg_lint` (JSON, ресурсы на двух языках, объекты и процессы, SQL-скрипты, скобки в C#) выполняется перед каждым обновлением стенда, и при ошибке на стенд ничего не уходит. Правило в коде одинаково для всех пользователей и не зависит от того, прочитала ли модель нужный файл знаний.

**3. Эвалы — тесты для агента.** Типовые задачи прогоняются автоматически: раннер откатывает тестовые пакеты, ведёт диалог как пользователь (выбирает рекомендованные агентом варианты), убирает данные в БД до и после кейса и проверяет результат. Изменение промпта, знаний, инструментов или модели — повод для прогона; полный прогон — перед сборкой для пользователей. Кейс — всегда ещё не реализованная на стенде задача.

**4. Каждая найденная ошибка становится правилом.** Ошибку закрываем на самом дешёвом уровне: проверка в коде, затем запись в знаниях, затем правило в промпте и кейс эвалов, чтобы она не вернулась незаметно.

**5. Знания общие, наблюдения — со всех.** Приложение не дописывает знания само, иначе у пользователей они разойдутся. Агент оставляет «Наблюдения для базы знаний», разработчик сверяет их с логом и стендом и переносит только подтверждённое. Опровергнутое помечается явно, а не удаляется. Знания обезличены: репозиторий публичный.

**6. Человек в петле по степени риска.** Чтение — без вопросов; запись — по подтверждённому плану; удаление и массовое изменение данных, а также найденные в данных аномалии (дубли, мусор) — только после вопроса пользователю, даже если это вне плана.

**7. Песочница и наблюдаемость.** Агент читает только папку приложения и знания, пишет только в `Pkg`; внешние команды — в песочнице ОС или с подтверждения. Каждый чат пишется в лог (действия, ошибки, токены и стоимость), а разбор логов и прогонов эвалов оформлен скиллами `review-agent-logs` и `check-evals`.
