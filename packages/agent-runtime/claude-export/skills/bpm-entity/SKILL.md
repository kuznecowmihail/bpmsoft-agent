# Объект BPMSoft: колонки, индексы, события

Подскилл вызывается из `bpm-develop` (шаг 3, исследование) и при записи объекта. Порядок работы, план и подтверждение — в `bpm-develop`. Правила стенда — в `CLAUDE.md`.

## Что читать (по порядку)

1. `.claude/skills/bpm-knowledge/metadata-editing.md` — общая механика записи, читай первым перед любой записью объекта.
2. `.claude/skills/bpm-knowledge/metadata-codes.md` — словарь кодов полей `metadata.json`; смотри, когда встречаешь незнакомый код.
3. `.claude/skills/bpm-knowledge/entity.md` — факты: колонки `D2` и их свойства `E*`, схема верхнего уровня, процесс событий объекта `EG1`/`CK2`, флаги событий `D20.FA<N>`, индексы `D6`, ресурсы.
4. `.claude/skills/bpm-knowledge/entity-edit.md` — рецепты: новый объект, колонки любых типов и свойств, override существующего объекта с lookup-колонкой, индексы, изменение и удаление колонок, события объекта, скрипты «Перед сохранением» и «После сохранения», удаление схемы с проверкой зависимостей.

## Колонки и UId

- Колонки стандартных объектов и их UId, типы — в `BPMSoft.Configuration/Autogenerated/Src/<Объект>Schema.<Пакет>.cs`, для залоченных схем без своей папки в `Pkg` — там же. Не угадывай UId.
- Для lookup-колонки нужен UId целевой Entity-схемы (`S4`). Тип колонки — `S2` (GUID из каталога типов). Имена колонок — `A2`.
- Колонки и тип должны совпадать с соседними объектами пакета по стилю.

## Обязательные шаги

- Перед записью — проверь, что объект с таким именем и заголовком не существует в выбранном и соседних пакетах (grep по `"Caption"` в `BPMSoft.Configuration/Pkg/*/Schemas/*/descriptor.json`).
- После каждой записи объекта запусти `node .claude/skills/bpm-knowledge/scripts/pkg-lint.js BPMSoft.Configuration/Pkg/<Пакет>/Schemas/<Объект>` — скрипт сам запускает проверку объекта (`check-entity.js`). Исправь все строки «ОШИБКА» и повтори запуск.
- Серверная логика объекта — в слушателе событий (`bpm-source-code`), а не в процессе событий объекта. Процесс событий (вкладка «События») только читай; новую логику туда не добавляй, если пользователь прямо не попросил именно процесс событий.
- Удаление объекта или колонки — разрушительная операция: сначала проверь ссылки по UId и имени во всём `Pkg`, покажи их пользователю и получи подтверждение (см. `CLAUDE.md`). Данные в БД удаляются только SQL-скриптом после ответа пользователя.

## Что сказать пользователю после записи

Нажать «Обновить из файловой системы». Компиляция нужна, если в проекте менялись C# или объект, на котором завязан код (см. `bpm-develop`, шаг 6). Проверка колонки: открыть объект в Designer или раздел, где колонка видна; SQL-запрос, если нужна проверка записей, — готовым текстом.
