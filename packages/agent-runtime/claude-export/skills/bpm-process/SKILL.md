# Бизнес-процесс BPMSoft

Подскилл вызывается из `bpm-develop` (шаг 3, исследование) и при записи процесса. Порядок работы, план и подтверждение — в `bpm-develop`. Правила стенда — в `CLAUDE.md`.

## Что читать (по порядку)

1. `.claude/skills/bpm-knowledge/metadata-editing.md` — общая механика записи, читай первым.
2. `.claude/skills/bpm-knowledge/process-edit.md` — **сначала чек-лист «Проверка перед сдачей процесса» в начале файла**, он обязателен после каждой записи процесса. Затем рецепт нужного элемента: «Читать данные», «Добавить данные», «Изменить данные», «Удалить данные», «Формула», шлюзы и условные потоки, стартовый сигнал и таймеры, ожидание и генерация сигнала, подпроцесс (в том числе по коллекции), «Связать объект с процессом», «Выполнить действие процесса», преднастроенная и автогенерируемая страницы, «Выполнить задачу», «Открыть страницу редактирования», «Вопрос пользователю» с ветвлением по ответу, «Отправить email», макросы, фильтры, запуск с клиента и из C#, выключение и удаление процесса; правила порядка `BK4` и подписей `Labels`.
3. `.claude/skills/bpm-knowledge/processes.md` — факты: элементы `BK4`, связи и условия `CI*`, параметры `FJ1`/`BP2`, маппинги `BK15` (`GT2`–`GT5`), дорожки, пользовательские задачи.
4. `.claude/skills/bpm-knowledge/metadata-codes.md` — словарь кодов, когда встречаешь незнакомое поле.
5. Шаблоны — `.claude/skills/bpm-knowledge/templates/README.md` и `templates/process/*.json`: бери шаблон элемента, только если в проекте нет своего образца с тем же `J6`.

Для пользовательских действий процесса с C# — подскилл `bpm-user-task`.

## Обязательные правила

- Координаты `BL3`, `CI11`, `CI12` — только целые числа. Дробное значение ломает «Обновить из файловой системы» (см. чек-лист в `process-edit.md`).
- Каждая связь стоит в `BK4` после обеих своих фигур; `CI1`/`CI2` указывают на существующие элементы; `CI11`/`CI12` лежат на краях фигур. После переподключения связи пересчитай оба конца.
- У «Читать данные» для каждой колонки из `ResultCompositeObjectList` есть подпись `BaseElements.<Элемент>.Parameters.ResultCompositeObjectList.<Колонка>.Caption` в обоих языках.
- В фильтрах ссылка на параметр процесса — объект `{"value": "[IsOwnerSchema:false]…"}` в обеих строках: и для Designer, и для выполнения (`dataSourceFilters`).
- Заголовок экземпляра `BK37` — ровно `[#[PropertyValue:Caption]#]`.
- Задание-сценарий не обращается к элементам процесса по имени: значения элементов берёт из параметров процесса через `Get<T>`.
- Проверка «запись найдена» — по `ResultCount` элемента в режиме Count, а не в режиме «первая запись».
- Процесс, который запускается через `ProcessExecutor.Execute`, имеет простой старт. Данные в другой процесс передавай параметрами запуска или подпроцессом, а не через произвольный сигнал.
- Файл процесса `metadata.json` — плоский JSON. Удобнее генерировать его node-скриптом через `JSON.stringify(obj, null, 2)`, чтобы код `CH1` экранировался корректно.
- `ModifiedOnUtc` в `descriptor.json` обновлён (`date +%s000`); ресурсы — на `ru-RU` и `en-US`.
- Процесс событий объекта (`EG1`) этим скиллом не меняй, если пользователь прямо не попросил.

## Обязательные шаги после записи

1. Запусти `node .claude/skills/bpm-knowledge/scripts/pkg-lint.js BPMSoft.Configuration/Pkg/<Пакет>/Schemas/<Процесс>` — скрипт сам запускает проверку процесса (`check-process.js`). Строки «ОШИБКА» исправь, повтори запуск, пока их не останется. Строки «ВНИМАНИЕ» оцени.
2. Перечитай `descriptor.json` и ресурсы: не испорчены ли они.
3. Пройди по пунктам чек-листа из `process-edit.md`, которые скрипт не проверяет (логику процесса).

## Что сказать пользователю после записи

Нажать «Обновить из файловой системы». Компиляция нужна, если менялись процесс и связанный C#; после компиляции — Ctrl+F5. Для проверки запуска: какой сигнал или действие запускает процесс и где видна запись результата; SQL-запрос готовым текстом, если результат в БД.
