# Клиентские схемы: раздел, карточка, деталь, модуль, миксин

Подскилл вызывается из `bpm-develop` (шаг 3, исследование) и при записи клиентской схемы. Порядок работы, план и подтверждение — в `bpm-develop`. Правила стенда — в `CLAUDE.md`.

## Что читать (по порядку)

1. `.claude/skills/bpm-knowledge/metadata-editing.md` — общая механика записи, читай первым.
2. `.claude/skills/bpm-knowledge/metadata-codes.md` — словарь кодов, когда встречаешь незнакомое поле.
3. `.claude/skills/bpm-knowledge/client-schemas.md` — факты: форматы `metadata.json`, `SchemaType`, `Parent`/`ExtendParent`, признак замещения `B7`, словарь строк `B2`, полная иерархия слоёв и применение diff (в том числе одноимённые элементы).
4. `.claude/skills/bpm-knowledge/client-schemas-edit.md` — рецепты: новая карточка, раздел, мини-карточка, деталь, модуль, миксин, Ext-override, стили; замещение карточки, детали, раздела, мини-карточки; атрибуты, методы, правила, валидация, кнопки и меню «Действия», совмещённый режим; наследник своей карточки (`B7` false).

## Обязательный шаг: полная иерархия родителя

До правки собери полную иерархию родителя скриптом:

`APP=<корень стенда> node .claude/skills/bpm-knowledge/scripts/hierarchy.js <ИмяСхемы>`

Корень стенда — папка, где открыт Claude Code (в ней `BPMSoft.Configuration` и `conf`). Для ещё не созданной схемы запускай скрипт на её будущем родителе. Скрипт только читает файлы; вывод сохранять во временный файл не нужно.

Затем найди все карточки объекта:
- замещения с тем же именем;
- отдельные карточки-наследники (по `Parent.Name` в `descriptor.json`);
- привязки в `SysModuleEdit`.

## Правила

- Кнопка действия над записью — и на карточке (отдельное открытие, Ctrl+F5, прямая ссылка), и в разделе (совмещённый режим). Вариант «только в разделе» не предлагай.
- Идентификаторы записей (UId справочников и т.п.) в карточках, модулях, деталях не пиши прямо: вынеси в константы — клиентский Module-модуль; внутри — по вложенному объекту или классу на справочник, одна переменная — одна таблица.
- Тексты, которые видит пользователь, — локализуемые строки `ru-RU` и `en-US`.
- Новые схемы — с префиксом и в стиле соседних схем пакета.
- Замещение чужой боевой схемы или удаление — только с подтверждением пользователя (см. `bpm-develop`).

## Обязательные шаги после записи

- Запусти `node .claude/skills/bpm-knowledge/scripts/pkg-lint.js BPMSoft.Configuration/Pkg/<Пакет>/Schemas/<Схема>` для каждой изменённой схемы. Исправь все строки «ОШИБКА» и повтори запуск.
- Перечитай изменённые файлы.

## Что сказать пользователю после записи

Нажать «Обновить из файловой системы». Для клиентских схем, как правило, компиляция не нужна; после обновления открыть страницу с обновлением Ctrl+F5 и проверить по критериям приёмки (где смотреть — из плана).
