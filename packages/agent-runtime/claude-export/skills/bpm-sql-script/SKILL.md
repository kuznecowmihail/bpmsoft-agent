# SQL-скрипт пакета BPMSoft

Подскилл вызывается из `bpm-develop` (шаг 3, исследование) и при записи скрипта. Порядок работы, план и подтверждение — в `bpm-develop`. Правила стенда — в `CLAUDE.md`.

## Что читать (по порядку)

1. `.claude/skills/bpm-knowledge/metadata-editing.md` — общая механика записи, `ModifiedOnUtc`.
2. `.claude/skills/bpm-knowledge/sql-script.md` — факты: `descriptor.json`, `InstallType`, `DBEngineType`.
3. `.claude/skills/bpm-knowledge/sql-script-edit.md` — рецепт (✅): новый скрипт выполняется при «Обновить из файловой системы», повторно — только после смены `ModifiedOnUtc`.

## Обязательные правила

- Тип СУБД (`DBEngineType`) — из существующих SQL-скриптов в `BPMSoft.Configuration/Pkg`. Если их нет — спроси пользователя.
- Запрос `DELETE` или `UPDATE` — разрушительная операция. Сначала опиши пользователю, какие записи затронет, сколько их и ссылаются ли на них другие записи, и получи подтверждение. Скрипт пиши только после ответа.
- Скрипт должен быть повторно безопасным, если это возможно: проверяй существование записи перед вставкой.
- Не выполняй SQL сам: у тебя нет доступа к БД. Проверочный запрос дай пользователю готовым текстом.
- Новый скрипт — с префиксом и в стиле соседних скриптов пакета; `ModifiedOnUtc` в `descriptor.json` — реальное время (`date +%s000`).

## Обязательные шаги после записи

- Запусти `node .claude/skills/bpm-knowledge/scripts/pkg-lint.js BPMSoft.Configuration/Pkg/<Пакет>/SqlScripts/<Имя скрипта>`. Исправь все строки «ОШИБКА» и повтори запуск.
- Перечитай SQL-файл и `descriptor.json`.

## Что сказать пользователю после записи

Нажать «Обновить из файловой системы»: скрипт выполнится при обновлении. Если скрипт меняли повторно, он выполнится только после смены `ModifiedOnUtc`. Компиляция не нужна. Проверка: SQL-запрос готовым текстом, который покажет результат.
