# Исходный код C# в пакете BPMSoft

Подскилл вызывается из `bpm-develop` (шаг 3, исследование) и при записи C#. Порядок работы, план и подтверждение — в `bpm-develop`. Правила стенда — в `AGENTS.md`.

## Что читать (по порядку)

1. `.claude/skills/bpm-knowledge/platform-api.md` — API платформы: ✅-факты (нужные `using`, системные настройки, кеши и перезапуск, дата и время); `.claude/skills/bpm-knowledge/server-data-api.md` — данные в C#: `Entity`, ESQ, группировка и агрегаты, запросы `Select`/`Insert`/`Update`/`Delete`, транзакции. Сначала здесь.
2. Если в этих файлах нет нужного — `BPMSoft.*.xml` в корне стенда: grep по имени типа или метода (команды — в `platform-api.md`). Файлы большие, целиком не читай.
3. Если и там нет — примеры вызова в `BPMSoft.Configuration/Autogenerated/Src` и в `Pkg`. Не нашёл подтверждения — укажи в плане риск ошибки компиляции.
4. `.claude/skills/bpm-knowledge/source-code.md` — факты: `.cs`, `metadata.json` (плоский JSON), локализуемые строки `B2`.
5. `.claude/skills/bpm-knowledge/source-code-edit.md` — рецепты (✅): класс-помощник, локализуемые строки, REST-сервис и вызов с клиента, вызов из процесса, слушатель событий приложения и `ClassFactory`, подмена платформенного класса через `ReBind`, чтение системной настройки, удаление, частые ошибки компиляции, сообщение в браузер пользователю (`ServerChannel`) и уведомление в «колокольчике» (`Reminding`); `DefaultBinding`.
6. `.claude/skills/bpm-knowledge/server-events-edit.md` — рецепты (✅): где писать серверную логику объекта, слушатель событий объекта — порядок событий, запреты, отмена `e.IsCanceled`, асинхронная операция из слушателя, порядок «скрипт события — слушатель».
7. `.claude/skills/bpm-knowledge/server-background-edit.md` — задания по расписанию (`IJobExecutor`, `AppScheduler`) и фоновые задачи; `.claude/skills/bpm-knowledge/files.md` — файлы и вложения из C# и OData.
8. `.claude/skills/bpm-knowledge/metadata-editing.md` — общая механика записи схем, читай перед записью.
9. `.claude/skills/bpm-knowledge/integration-api.md` — адреса, атрибуты маршрутов и коды ошибок своего REST-сервиса, анонимный сервис, исходящий HTTP.

## Обязательные правила

- Новая серверная логика объекта — в слушателе событий (`server-events-edit.md`). Процесс событий объекта (вкладка «События») не меняй, если пользователь прямо не попросил.
- Тексты, которые видит пользователь (сообщения, подписи, значения по умолчанию), — только локализуемые строки `ru-RU` и `en-US`. Константы в коде — только для технических имён.
- Идентификаторы записей (UId справочников) — в константах: статический класс для серверной логики, по вложенному классу на справочник.
- Не пиши `using` и имена из памяти: только то, что подтверждено `platform-api.md`, XML-документацией или примерами проекта.
- Не меняй `Autogenerated`, `Resources`, `conf`.

## Обязательные шаги после записи

- Запусти `node .claude/skills/bpm-knowledge/scripts/pkg-lint.js BPMSoft.Configuration/Pkg/<Пакет>/Schemas/<Схема>` для каждой изменённой схемы: скрипт проверяет скобки в C# и `metadata.json`. Исправь все строки «ОШИБКА» и повтори запуск.
- Перечитай изменённые `.cs` и `metadata.json`.

## Что сказать пользователю после записи

Нажать «Обновить из файловой системы» и выполнить компиляцию: C# меняется, компиляция обязательна. После компиляции — Ctrl+F5. Если ошибка компиляции — пришли текст ошибки из журнала; разбор — скилл `bpm-troubleshoot`.
