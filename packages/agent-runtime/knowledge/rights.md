## Права в серверном коде
- ✅ по XML-документации: `UseAdminRights` у `EntitySchemaQuery` и у `Entity` — «учитывать права текущего пользователя», по умолчанию `true`. `false` читает и пишет в обход прав. Ставь `false` только осознанно — служебная логика, системные данные — и скажи об этом пользователю; для данных, которые видит пользователь, оставляй значение по умолчанию.
- ✅ Права на операцию (21.10.2026): `UserConnection.DBSecurityEngine.GetCanExecuteOperation("<Код>")` → `bool`; `UserConnection.DBSecurityEngine.CheckCanExecuteOperation("<Код>")` бросает `SecurityException`, если права нет, и для несуществующего кода — «Администрируемая операция с кодом "<Код>" не найдена».
- `UserConnection.AppConnection.SystemUserConnection` — соединение системного пользователя (системная настройка `SystemUser`; обычно `Supervisor`). Записи, созданные через него, получают `CreatedBy` = контакт системного пользователя; права на операции не проверяются (обычный пользователь через него создаёт запись справочника).
- ✅ Сохранение записи справочника (наследника `BaseLookup`) через `Entity.Save` под пользователем без операции `CanManageLookups` — `SecurityException` «Текущий пользователь не имеет прав на запуск администрируемой операции с кодом "CanManageLookups"». Справочники из кода от имени пользователя заполняй через `SystemUserConnection` или выдай роли операцию.
- Запросы `Insert`, `Update`, `Delete` из `BPMSoft.Core.DB` обходят слушатели объекта, журнал изменений и права по записям — `server-data-api.md`, «Запросы `Select`, `Insert`, `Update`, `Delete` (`BPMSoft.Core.DB`)». Нужна бизнес-логика объекта — работай через `Entity` или `DataService`.
