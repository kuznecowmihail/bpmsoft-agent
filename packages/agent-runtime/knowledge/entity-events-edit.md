# Объекты: события объекта — рецепты

Процесс событий объекта (`EG1`/`CK2`), скрипты «Перед сохранением» и «После сохранения», журнал изменений. Новую серверную логику объекта пиши в слушателе событий (`server-events-edit.md`); процесс событий меняй, только если пользователь прямо попросил. Факты о структуре — в `entity-schema.md`; общее для объектов — в `entity-edit.md`.

> ⚠️ Новую логику объекта пиши в слушателе событий (`server-events-edit.md`, «Где писать серверную логику объекта»). Рецепты ниже — чтобы понимать существующий процесс событий проекта и править его по прямой просьбе пользователя. После любой правки объекта запусти `node <каталог знаний>/scripts/check-entity.js <Pkg>/<Пакет>/Schemas/<Объект>` и исправь строки «ОШИБКА».

## ✅ Настроить событие объекта (EG1/CK2, структура полностью раскрыта экспериментом)
Полный цикл ручного создания с нуля проверен. Типы элементов, BL7-константы, заглушки `EG1.BK4`, баг `IL2`/`CD4` у Lane и модель `D20.FA<N>` — в `entity-schema.md`, разделы «ПОДТВЕРЖДЕНО: ручное создание EG1/CK2 с нуля РАБОТАЕТ» и «ПОДТВЕРЖДЕНО (серия из 10 экспериментов): механизм привязки события к чекбоксу — полная модель».

✅ **Несколько событий в одном объекте** (подтверждено в CRM, 09.10.2026: 4 события, каждое — свой подпроцесс): на каждое событие — свой блок `+ MetaData.Schema.EG1.BK4 {...}` с `ProcessSchemaEventSubProcess`, стартовым сообщением и скриптом в `CK2`, плюс своя связь; UId всех подпроцессов и связей — в закрывающем `~ MetaData.Schema.EG1.BK4`. Подпроцессы ставь друг под другом: `BL3` `58;68`, `58;380`, `58;692`, `58;1004` (рамка `BN2` `303;300`). ⚠️ `BL3` элементов внутри `CK2` считается от левого верхнего угла своего подпроцесса, а не от холста: во всех подпроцессах старт `66;121`, скрипт `193;107`. ❌ Опровергнуто: координаты от холста (`66;433` во втором подпроцессе) — элементы оказались под рамкой. У связи внутри подпроцесса `CI11`/`CI12` можно не писать: Designer рисует линию сам.

### ✅ Механизм привязки события к чекбоксу (`D20.FA<N>`)

Соответствие «чекбокс ↔ `D20.FA<N>`» — таблица в `entity-schema.md`, раздел «ПОДТВЕРЖДЕНО (серия из 10 экспериментов): механизм привязки события к чекбоксу — полная модель».

**Практический рецепт**:
1. Возьми структуру `EG1` из `entity-edit.md`, «✅ Создать объект с нуля за один шаг»: `LaneSet` + `Lane` (у Lane `IL2`/`CD4` = UId `LaneSet`), 6 строк `= ...BK4.[...].CK2.[...].BL7 "53818048-..."` для заглушек стандартных событий, свой контейнер события с `StartMessageEvent` и `ScriptTask`, связь `SequenceFlow`. **Не создавай заглушки отдельными записями `+ EG1.BK4 {...}`** — в рабочих файлах их так нет.
2. В закрывающий список `~ EG1.BK4 [...]` внеси UId заглушек (набор по родителю, `entity-schema.md`), UId своего контейнера и UId связи. Позиция своего контейнера в списке на работу события не влияет (проверено серией экспериментов).
3. Имя сигнала `CJ1` — `"<ИмяОбъекта><Действие>"` по таблице в `entity-schema.md`, «ПОДТВЕРЖДЕНО (серия из 10 экспериментов)».
4. **ОБЯЗАТЕЛЬНО добавь флаг `MetaData.Schema.D20.FA<N> = true`** — выбери правильный номер `N` из таблицы выше в зависимости от интересующего события (например для "После сохранения записи" это `FA11`)
5. Без этого флага событие не срабатывает (✅ подтверждено записью в CRM, 30.10.2026). Два одинаковых объекта со скриптом «После сохранения записи» (пишет колонку через `Update`), у одного `+ MetaData.Schema.D20.FA11 true`, у другого нет: после компиляции запись, созданная через DataService `InsertQuery`, получила значение только в объекте с флагом. `InsertQuery` через DataService запускает события объекта.
6. (Опционально, но рекомендуется) Настрой событие через Designer для визуальной проверки, затем скопируй готовую структуру для использования в других объектах

## ✅ Скрипт события: «Перед сохранением» и «После сохранения»
**Подтверждено 05.10.2026** на `TestSrcEntity`: два события в одном объекте (контейнеры по шаблону выше, `CJ1` `TestSrcEntitySaving` и `TestSrcEntitySaved`, флаги `+ MetaData.Schema.D20.FA11 true` и `+ MetaData.Schema.D20.FA12 true`); после «Обновить из файловой системы» и компиляции Designer показал оба события и их скрипты, запись из процесса получила `Description` = «E1 Saving» и дописку в `Note` от `Update`.
- Значение для сохраняемой записи ставь в «Перед сохранением» (`Saving`): `Entity.SetColumnValue("Description", "E1 Saving"); return true;`
- В «После сохранения» (`Saved`) запись уже в БД — `Entity.SetColumnValue` туда не попадёт. Дописывай запросом:
```csharp
var note = Entity.GetTypedColumnValue<string>("Note") + " | E1 Saved: Update";
var upd = new Update(UserConnection, "TestSrcEntity")
	.Set("Note", Column.Parameter(note))
	.Where("Id").IsEqual(Column.Parameter(Entity.PrimaryColumnValue)) as Update;
upd.Execute();
return true;
```
- Слушатель `EntityEventListener` с `OnSaving` на том же объекте срабатывает после скрипта «Перед сохранением»: слушатель видит значения, проставленные скриптом (✅ подтверждено записью в CRM, 21.10.2026; `server-events-edit.md`, «Подпроцесс событий объекта раньше слушателя»). Уточнено: раньше здесь было «отрабатывает вместе».
- «Проверка записи» в Designer у такого объекта показана включённой (`entity-edit.md`, «Объект без собственного события», пункт «Побочный эффект») — на работу не влияет.

## ✅ Журнал изменений объекта
**Подтверждено записью в CRM (21.10.2026).**
- Объект: `"D24": true` в `metadata.json` (в построчном формате — `= MetaData.Schema.D24 true`) и `"IsTrackChangesInDB": "True"` в `properties.json`.
- Каждая колонка, изменения которой нужно журналировать: `"E16": true` в её блоке `D2`. Без `E16` журнал ничего не пишет.
- Обновление из файловой системы и компиляция создают таблицу `Sys<Объект>Log`: служебные `ChangeTrackedId` (Id записи), `ChangeTypeId` (→ `SysEntityChangeType`, например `Updated`), `ChangeTrackedOn`, `ChangeTrackedById`, `ClientIP`, `Request`, плюс колонки объекта (справочные — строками с отображаемым значением). В строке журнала заполнены только колонки с `E16`.
- ✅ Строку журнала пишут добавление (тип «Добавлено») и изменение через сущность: карточка, OData, `Entity.Save`, запросы `DataService` (`InsertQuery`, `UpdateQuery`). ❌ Запрос `Update` в C# (`BPMSoft.Core.DB`) журнал не пишет и слушатели объекта не вызывает (проверено 22.10.2026).
- Выключение `D24` таблицу журнала не удаляет.
