# Шаблоны

Готовые фрагменты из наших тестов, подтверждённых записью в CRM. Нужны, когда в проекте нет своего образца для клонирования. Как вставлять — в соответствующем рецепте *-edit.md; что заменить — в поле about каждого шаблона элемента.

Большие файлы (до 100 КБ) читай частями или переноси в metadata.json node-скриптом, а не перепечатывай вручную: в строках ресурсов бывают длинные значения (иконки base64).

## Элементы процесса — process/*.json
Формат: about (что заменить), j6, bl7, element (запись BK4), mappings (записи BK15 элемента), resources (строки BaseElements.<Имя элемента>.* для ru-RU и en-US). Плейсхолдеры: <UId процесса>, <UId пакета>, <UId дорожки>, <UId элемента>, <UId схемы страницы>, <UId схемы действия>; в папках схем ещё <Id пакета> и <версия платформы> — откуда их брать, `metadata-editing.md`, поля A5 и B8.

| Файл | Элемент | Рецепт (`process-data-edit.md`, `process-tasks-edit.md`) | Проект без своих образцов |
|---|---|---|---|
| read-data.json | «Читать данные» | «Читать данные» | ✅ |
| add-data.json | «Добавить данные» | «Добавить данные» | ✅ |
| change-data.json, delete-data.json | «Изменить данные», «Удалить данные» | «Изменить данные» и «Удалить данные» | ✅ |

| email.json | «Отправить email» | «Отправить email» | ✅ элемент открывается и процесс проходит; письмо без почтового ящика не отправлялось |
| auto-page.json | «Автогенерируемая страница» | «Автогенерируемая страница» | ✅ |

В маппингах `BK15` поле `A2` — имя элемента на момент создания; платформа сопоставляет маппинг с элементом по `GT2`/`GT3`, а Designer при переименовании элемента `A2` маппингов не меняет. Для порядка ставь `A2` = имя своего элемента.

## Наборы данных — data/<папка>/
Наборы регистрации и данных, собранные на проекте без своих пакетов и подтверждённые в CRM (`registration-edit.md`, `data-edit.md`). Скопируй папку в `Pkg/<Пакет>/Data/<Имя набора>/`, в `descriptor.json` — свой `UId` набора, `Name`, `ModifiedOnUtc` (`date +%s000`); `Columns` не меняй. В `data.json` и `Localization/*` замени плейсхолдеры: `<Id записи …>` — новый GUID (ссылки между наборами согласованно), `<UId объекта>`, `<UId схемы раздела>`, `<UId карточки>`, `<UId мини-карточки>`, `<UId схемы детали>`, `<UId объекта детали>`, `<UId объекта справочника>` — UId своих схем, `<Объект>`, `<Раздел>`, `<Код настройки>`, `<текст>` — свои значения, `<Id рабочего места>` — спроси у пользователя. Остальные GUID — константы платформы, их не меняй.

| Папка | Таблица | Что это |
|---|---|---|
| Lookup | `Lookup` | справочник в разделе «Справочники» |
| LookupRecords | наследник `BaseLookup` | записи справочника с переводом |
| SysModuleEntity, SysModule, SysModuleEdit, SysModuleInWorkplace | регистрация раздела | раздел, карточка, мини-карточка, рабочее место |
| SysDetail | `SysDetail` | регистрация детали |
| SysImage | `SysImage` | иконка раздела (SVG в base64) |
| SysSettings, SysSettingsValue | системная настройка | настройка типа «Дробное» и её значение |
