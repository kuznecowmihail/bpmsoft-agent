# Веб-сервисы (ServiceSchemaManager) — подтверждённая модель metadata

✅ Подтверждено на реальных схемах проекта (21 REST-сервис, 137 методов, 53 элемента «Вызвать веб-сервис» в 37 процессах) и скриншотах дизайнера сервиса; ✅ запись сервиса и элемента подтверждена в CRM (21.10.2026, `web-service-edit.md`). Коды полей расшифрованы по данным и по клиентской модели сервиса `[app]/Resources/ui/BPMSoft/manager/service-schema-manager/*.js` (перечисления — `service-enums.js`), а не генератором `metadata-codes.md`. Soap-сервис и вебхук (пункты того же меню добавления в конфигурации) не изучены — 🧪.

## Где лежит и как выглядит в CRM
- Схема: `Pkg/<Пакет>/Schemas/<Имя>/` — `descriptor.json`, `metadata.json`, `properties.json`; `.cs` нет. Ресурсы — `Pkg/<Пакет>/Resources/<Имя>.Service/resource.<culture>.xml`.
- Создаётся в конфигурации: «Добавить» → «Rest-сервис». Карточка сервиса: «Название» (= `Caption`), «Код» (= имя схемы), «Пакет», «URI сервиса» (`IQ1`), «Повторов вызова при ошибках» (`IQ3`), «Тип» (`IQ2`); вкладки «Методы» и «Аутентификация».
- Окно метода: «Название» (подпись), «Код (на английском)» (= `A2` метода), «Адрес метода» (`IT1`), «Полный адрес» (= `IQ1` + `IT1`, не хранится), «Тип запроса» (`IT2`), «Тип содержимого» (`IW2`), «Тайм-аут ответа, мс» (`IR3`), «Использовать аутентификацию»; вкладки «Параметры вызова» (`IR1.IW1`) и «Обработка ответа» (`IR2.IW1`); кнопка «Отправить тестовый запрос».
- Окно параметра: «Название» (подпись), «Тип параметра» (`IU4`), «Код заголовка» / путь (`IU1`), «Код в BPMSoft» (= `A2` параметра), «Обязательный» (`IU7`), «Формат передачи пустых значений» (`IU9`), «Значение по умолчанию» (`IU5`: «Константа» или системная настройка).
- ✅ Если `IU9` нет, поле «Формат передачи пустых значений» в окне параметра пустое (21.10.2026). Designer показывает входные параметры элемента в своём порядке (обязательные первыми), а не в порядке `BP2`.

## descriptor.json
```json
{
  "Descriptor": {
    "UId": "<UId сервиса>",
    "Name": "<Имя>",
    "ModifiedOnUtc": "\/Date(<мс>)\/",
    "ManagerName": "ServiceSchemaManager",
    "Caption": "<Подпись>",
    "DependsOn": []
  }
}
```
`Parent` нет; `DependsOn: []` — у всех 21 сервиса.

## properties.json
```json
{
  "Properties": {
    "BaseUri": "<URI сервиса>",
    "CreatedInVersion": "<версия платформы>",
    "Type": "Rest"
  }
}
```
`BaseUri` дублирует `IQ1` из `metadata.json`.

## metadata.json — формат B (плоский JSON, как у процесса)
Порядок ключей схемы: `ManagerName`, `UId`, `A2`, `A5`, `B1` (`[]`), `B2` (`[]`), `B3` (`[]`), `B6`, `B8`, `IQ1`, `IQ2`, `IQ3` (если не 0), `IQ7`, `IQ4`.

### Сервис (ServiceSchema)
| Код | Свойство | Значения |
|---|---|---|
| `IQ1` | BaseUri | URI сервиса без завершающего `/` |
| `IQ2` | Type | `1` REST (перечисление: 1 REST, 2 SOAP 1.1, 3 SOAP 1.2) |
| `IQ3` | RetryCount | «Повторов вызова при ошибках»; `0` по умолчанию не пишется |
| `IQ4` | ServiceMethods | список методов |
| `IQ7` | ServiceNamespaces | у REST всегда `[]` |

✅ Аутентификация сервиса (22.10.2026, Basic проверен вызовом httpbin `/basic-auth`): `IQ5` = `{"IY1": <тип: 1 Basic, 2 Digest, 3 OAuth 2.0>, "IZ1": {"IV1": "<логин>", "IV2": 1}, "IZ2": {"IV1": "<пароль>", "IV2": 1}}` в схеме перед `IQ7`; у метода, который её использует, — `"IR4": true` («Использовать аутентификацию»). `IV2` — источник, как у значений параметров: `1` константа, `2` системная настройка (`IV1` = код настройки). Константный пароль лежит в `metadata.json` открытым текстом и уходит в git — бери логин и пароль из системных настроек (`IV2: 2`), проверено. ⚠️ Неверный формат `IQ5` (например, строки вместо `{"IV1", "IV2"}`) обновление из файловой системы не роняет, но у сервиса пропадают методы: вызов падает с «Элемент коллекции с именем <Метод> не найден». ⚠️ Digest (`IY1: 2`) на стенде не прошёл: сервис получил 401 от двух тестовых серверов, а `curl --digest` с теми же данными — 200 (22.10.2026). Не предлагай Digest без проверки на целевом сервере. OAuth 2.0 не проверялся; код OAuth — `JB1` (ApplicationId).
- Значение пароля не клади и в набор данных `SysSettingsValue_<Код>` — он тоже в пакете и уходит в git. Создай настройки данными (`data-edit.md`, «Системная настройка») без значения пароля и попроси пользователя ввести пароль в разделе «Системные настройки» (логин можно положить значением). ✅ Для пароля подходит тип «Защищённый текст» (`ValueTypeName` `SecureText`, 22.10.2026): значение хранится в БД зашифрованным, сервис при вызове его расшифровывает (Basic-аутентификация прошла), клиенту через `QuerySysSettings` значение не отдаётся.

### Метод (элемент `IQ4`)
Порядок ключей: `UId`, `A2`, `A3`, `A4`, `IR3`, `IR5`, `IR1`, `IR2`.

| Код | Свойство | Значения |
|---|---|---|
| `A2` | Name | «Код (на английском)»; по нему метод выбирает процесс (`IX2`) |
| `A3`/`A4` | — | UId сервиса |
| `IR3` | RequestTimeout | тайм-аут ответа, мс (в проекте 5000–40000) |
| `IR5` | по набору свойств клиента — SoapAction 🧪 | у REST всегда строка `"null"` |
| `IR1` | Request | запрос |
| `IR2` | Response | ответ |

`IR4` — UseAuthInfo метода («Использовать аутентификацию»), `true`; подробности — выше, «Аутентификация сервиса».

### Запрос и ответ (`IR1`, `IR2`)
Порядок ключей запроса: `IW2`, `IW1`, `IT2`, `IT1`; ответа: `IW2`, `IW1`.

| Код | Свойство | Значения |
|---|---|---|
| `IT1` | Uri | адрес метода относительно `IQ1`, начинается с `/`; сегменты URL — `{имя}`, например `/data/{type}/{operation}` |
| `IT2` | HttpMethodType | 1 GET, 2 POST, 3 PUT, 4 PATCH, 5 DELETE |
| `IW1` | Parameters | параметры запроса или ответа (у ответа может быть `[]`) |
| `IW2` | ContentType | 1 JSON, 2 XML |

### Параметр (элемент `IW1`, вложенный — элемент `IU6`)
Порядок ключей: `UId`, `A2`, `IU1`, `IU2`, `IU9`, `IU3`, `IU7`, `IU8`, `IU4`, `IU5`, `IU6` (необязательные `IU9`, `IU3`, `IU7` пропускаются).

| Код | Свойство | Значения |
|---|---|---|
| `A2` | Name | «Код в BPMSoft»; по нему параметр связан с параметром элемента процесса (`L17`) |
| `IU1` | Path | тело верхнего уровня — JSONPath от корня: `$.field`, `$.params.client_id`; свойство внутри объекта (`IU6`) — имя без `$.`: `name`; заголовок — имя заголовка («Код заголовка»): `Content-Type`; query и сегмент URL — имя (у сегмента совпадает с `{имя}` в `IT1`) |
| `IU2` | DataValueTypeName | `Text`, `Integer`, `Float`, `Boolean`, `DateTime`, `Guid`, `Date`, `Time`, `Object` |
| `IU3` | IsArray | `true` — коллекция; у `Object` — коллекция объектов, у простого типа — массив значений |
| `IU4` | Type | 1 тело, 2 сегмент URL, 3 query-строка, 4 заголовок, 5 cookie |
| `IU5` | DefValue | `{"IV1": <значение или "null">, "IV2": <источник>}`; источник: 1 константа, 2 системная настройка (в проекте только 1); у объектов-коллекций бывает `{"IV1": "null"}` без `IV2` |
| `IU6` | ItemProperties | свойства объекта, те же поля рекурсивно (в проекте до двух уровней вложенности); у простого параметра `[]` |
| `IU7` | IsRequired | `true` — «Обязательный»; `false` не пишется |
| `IU8` | SequenceElementName | всегда `"item"` |
| `IU9` | EmptyValuesPassingFormatName | `EmptyString`, `Null`, `Default`, `DoNotSend`; `"null"` — не задан |

✅ `IU5` с `"IV2": 2` и `"IV1": "<код системной настройки>"` — значение параметра по умолчанию берётся из настройки (22.10.2026: параметр query без значения ушёл со значением настройки).

Пример заголовка с константой: `{"UId": "<UId>", "A2": "ContentType", "IU1": "Content-Type", "IU2": "Text", "IU8": "item", "IU4": 4, "IU5": {"IV1": "application/json", "IV2": 1}, "IU6": []}`.

### Прочее
- `A5` — пакет создания, `B6` — пакет схемы, `B8` и `CreatedInVersion` — версия платформы (общие поля, `metadata-editing.md`). 🧪 У части сервисов проекта `B6` — UId другого пакета, чем папка в `Pkg` (схема переносилась между пакетами); для новой схемы пиши UId своего пакета.

## Ресурсы (`Resources/<Имя>.Service/resource.<culture>.xml`)
Ключи (в проекте больше ничего не встречалось):
- `Caption` — подпись сервиса; `Description` — описание (необязательно);
- `ServiceMethods.<Метод>.Caption` — подпись метода;
- `ServiceMethods.<Метод>.Request.Parameters.<Параметр>.Caption` — подпись параметра запроса;
- `ServiceMethods.<Метод>.Request.Parameters.<Параметр>.ItemProperties.<Свойство>.Caption` — подпись свойства объекта (и глубже: `.ItemProperties.<Свойство>.ItemProperties.<Свойство>.Caption`);
- `ServiceMethods.<Метод>.Response.Parameters.<Параметр>.Caption` и `...Response.Parameters.<Параметр>.ItemProperties.<Свойство>.Caption` — то же для ответа.
`<Метод>`, `<Параметр>`, `<Свойство>` — их `A2`.

### Значения входных параметров (`L8`)
Как у любого параметра процесса (`processes.md`, `process-edit.md`):
- выражение: `{"GS1": 3, "GS2": "[#[IsOwnerSchema:false].[IsSchema:false].[Parameter:{<UId параметра процесса>}]#]", "GS5": "<UId процесса>"}`; результат другого элемента — `[#[IsOwnerSchema:false].[IsSchema:false].[Element:{<UId элемента>}].[Parameter:{<UId параметра>}]#]`; к выражению можно дописать C#, например `.ToString()` после справочного параметра;
- текстовая константа: `{"GS1": 1, "GS5": ...}` без `GS2`, сам текст — в ресурсах процесса `.Value` и `.DisplayValue`;
- коллекция объектов: сам параметр-коллекция `<Коллекция>_In` получает выражение на параметр процесса-коллекцию (`L1` = `651ec16f-…`), а каждое его свойство в `L18` — выражение на соответствующее свойство из `L18` параметра процесса: `[#[IsOwnerSchema:false].[IsSchema:false].[Parameter:{<UId свойства коллекции процесса>}]#]`.

### Маппинги (`BK15`)
У 45 из 53 элементов — четыре маппинга на стандартные параметры (`Success`, `Response`, `StatusCode`, `RequestBody`): `A2` = имя элемента, `GT2` = `[Element:{<UId элемента>}].[Parameter:{<UId параметра>}]`, `GT3` = UId параметра, `GT5` — свой новый UId у каждого маппинга (не константа, `GT4` нет), `GT1` = `{"GS2": "false"}` у `Success`, `{}` у остальных. На входные и выходные параметры маппингов нет.

### Как процесс использует результат
- ✅ Задание-сценарий читает параметры элемента строковым путём: `Get<string>("<Элемент>.Response")`, `Get<int>("<Элемент>.StatusCode")`, `Get<bool>("<Элемент>.Success")`, `Get<string>("<Элемент>.<Параметр>_Out")` (подтверждено записью в CRM, 21.10.2026; в проекте — в 17 процессах). Это не обращение к элементу как к C#-переменной (оно даёт `CS0103`, `process-edit.md`), а путь в `Get<T>`.
- Выходной параметр передают в параметр процесса значением: у параметра процесса `L8` = `{"GS1": 3, "GS2": "[#[IsOwnerSchema:false].[IsSchema:false].[Element:{<UId элемента>}].[Parameter:{<UId параметра _Out>}]#]"}`; для коллекции (`L1` = `651ec16f-…`) у свойств в `L18` — такие же выражения на свойства `_Out`. Другой способ — элемент «Формула» с тем же выражением. ✅ Для текстового `_Out` и `StatusCode` оба способа подтверждены в CRM (21.10.2026, `web-service-edit.md`); коллекция — только на схемах проекта.
- Подпись на диаграмме — запись `Labels` с `A2` = `<Элемент>_label1` и `ParentUId` = UId элемента, как у других элементов.

### Ресурсы процесса для элемента
- `BaseElements.<Элемент>.Caption`;
- `BaseElements.<Элемент>.Parameters.<A2 параметра>.Caption` — у входных и выходных подпись = подпись параметра сервиса; у стандартных — из таблицы выше (en-US: 🧪 смотри в своём проекте);
- `BaseElements.<Элемент>.Parameters.<A2 параметра>.DisplayValue` — читаемое значение (`[#<Подпись параметра процесса>#]`, `[#<Элемент>.<Параметр>#]`), у текстовой константы ещё `.Value`;
- свойства коллекции — `BaseElements.<Элемент>.Parameters.<Коллекция>_In.<Свойство>_In.Caption` и `.DisplayValue` (без слова `ItemProperties`), например `[#<Коллекция>:<Свойство>#]`.

## Не проверено пока
- OAuth 2.0, типы `Float`/`DateTime`/`Guid`/`Time`, тайм-аут элемента `IX3`, XML-содержимое.
- Soap-сервис.
- Вебхуки (по коду платформы, записью не проверено): отдельный тип схемы `WebhookSchemaManager` (на стенде схем нет), представление `VwWebhookV2`, адрес вызова `/webhook/…`, действия — создать запись, удалить запись, прочитать данные, запустить процесс; проверка вызова — Basic/cookie или JWT-токен. Формат `metadata.json` не известен — не пиши вебхук файлами, проси пользователя создать его в конфигурации.
- Белый список исходящих адресов: файл `whitelistUriConfig.json` в корне приложения (путь — ключ `WhitelistUriConfigJsonPath` в `BPMSoft.WebHost.dll.config`), список `WebService` для REST-сервисов, `useDefaultList` подмешивает `defaultWhitelist`. ⚠️ На стенде (22.10.2026) список не ограничивал вызовы REST-сервиса: со списком `WebService` только из `https://httpbin.org` вызов на другой хост ушёл и до, и после перезапуска. Не полагайся на него как на защиту; если проект требует ограничений — уточни у администратора, где они включаются.
- Добавление метода в существующий сервис (рецепт в `web-service-edit.md`, 🧪).
