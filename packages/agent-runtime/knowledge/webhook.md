# Вебхуки (WebhookSchemaManager) — факты

Вебхук — схема пакета, которая публикует входящий HTTP-адрес и по запросу выполняет действия без кода: добавить, изменить, прочитать, удалить запись или запустить процесс. Создаётся в разделе «Вебхуки» дизайнера системы (`WebhookV2Section`, список — представление `VwWebhookV2`). Рецепт файлами — `webhook-edit.md`. Проверено записью в CRM 25.10.2026 (стенд .NET 8).

## ✅ Когда выбирать
- Внешняя система передаёт данные, а логика укладывается в «добавить или изменить запись по полям JSON» или «запустить процесс с параметрами» — вебхук, без C#.
- Нужна своя проверка, ветвление, сложный ответ или вызов изнутри CRM — REST-сервис (`web-service-edit.md`, `integration-api.md`).

## ✅ Файлы и адрес
- Схема с `"ManagerName": "WebhookSchemaManager"`: папка `Schemas/<Имя>/` (`descriptor.json`, `metadata.json`, `properties.json`) и `Resources/<Имя>.Webhook/resource.<culture>.xml`.
- Дизайнер сохраняет вебхук только в БД (`SysSchema`); в `Pkg` файлы появляются после выгрузки пакетов в файловую систему.
- Адрес метода: `<CRM>/webhook/<UId схемы>/<Endpoint>` (на .NET 8 без `/0/`; на .NET Framework 🧪). HTTP-метод — из `IR5`.
- `properties.json`: `CheckClientUrl`, `IsWebhookLoggingEnabled`, `IsBodyWebhookLoggingEnabled` — строки `"False"`/`"True"`, `CreatedInVersion`.

## ✅ metadata.json: коды
Схема (`MetaData.Schema`): `A2` — имя, `A5` — GUID (как у других схем пакета), `B6` — UId пакета, `B8` — версия, `WS1` — проверять адрес клиента, `WS2` — адрес клиента (`"null"`), `WS3` — аутентификация, `WS4` — методы, `WS5`/`WS6` — логирование вебхука и тела.

Аутентификация `WS3`:
- `IY1` — тип: `0` нет, `1` Cookie (в коде BasicCookie), `2` JWT, `3` OAuth 2.0.
- Cookie: `IZ1` логин, `IZ2` пароль, `IZ3` Id пользователя (`SysAdminUnit`), `IZ4` срок действия. Каждое значение — `{ "IV1": <значение>, "IV2": <источник> }`; `IV2`: `0` нет, `1` константа, `2` системная настройка. Значения нет — только `{ "IV2": 1 }`.
- JWT: `JD1` пользователь, `JD2` токен, `JD3` заголовок токена, `JD4` срок. OAuth 2.0: `JB1` приложение, `JB2` пользователь.

Метод (элемент массива `WS4`):
- `UId`, `A2` — код метода, `A3` и `A4` — UId схемы.
- `IR1` — параметры запроса `{ "IW1": [ ... ] }`, `IR2` — параметры ответа (тот же формат).
- `IR4` — Endpoint (часть адреса), `IR5` — HTTP-метод: `1` GET, `2` POST, `3` PUT, `4` PATCH, `5` DELETE; `IR6` — содержимое: `1` JSON, `2` XML.
- `IR7` — ждать ответа: `true` — ответ после выполнения действий; `false` — действия в фоне, ответ сразу.
- `IR8` — действия при получении, `IR9` — опубликован (`true`; ключа нет — не опубликован).

Параметр (элемент `IW1`): `UId`, `A2` — имя, `IU1` — путь JSONPath в теле (`$.name`), `IU3` — тип (`"Text"` …), `IU4` — значение по умолчанию `{ "IV1": "null", "IV2": 1 }`, `IU5` — вложенные свойства, `IU7` — имя элемента последовательности (`"item"`), `IU8` — формат пустых значений (`0`), `IU2` — массив, `IU6` — входной.

Действие (элемент `IR8`):
- `UId`, `A2` — код (`ActionRule1`), `AR1` — тип: `1` запустить процесс, `2` прочитать данные, `3` изменить данные, `4` добавить данные, `5` удалить данные.
- `AR2` — UId объекта.
- `AR5` — колонки новой записи: `[{ "UId": <GUID>, "AP1": <UId колонки объекта>, "AP2": <UId параметра запроса> }]`.
- `AR3`/`AR4` — входы и выходы процесса, `AR6` — фильтр записей (колонка ← параметр), `AR7` — выходы из записи, `AR8` — результат действия.

Ресурсы: `Caption`, `WebhookMethods.<Метод>.Caption`, `WebhookMethods.<Метод>.Request.Parameters.<Параметр>.Caption`, `WebhookMethods.<Метод>.ActionRules.<Действие>.Caption`. Дизайнер выгружает только `ru-RU` — `en-US` добавляй сам.

## ✅ Публикация
- Маршруты вебхуков живут в памяти приложения. При старте платформа публикует все методы с `IR9: true`.
- «Опубликовать» в дизайнере и `POST <CRM>/rest/WebhookService/Publish` с телом `{"WebhookSchemaId": "<UId схемы>", "WebhookMethodId": "<UId метода>"}` публикуют сразу. Через REST признак `IR9` в метаданные не записывается: после перезапуска метод не опубликуется. Снять — `POST <CRM>/rest/WebhookService/Unpublish` с тем же телом.
- Вебхук файлами: `IR9: true` в `metadata.json`, «Обновить из файловой системы», перезапуск приложения — метод отвечает (подтверждено).

## ✅ Аутентификация вызова
- Тип «нет» (`IY1: 0`) пускает без входа, только если в `appsettings.json` включён `UseWebhookAnonymousAuth` (значение — `POST <CRM>/rest/WebhookService/UseAnonymousAuth`; на стенде `false`). Иначе вызов без cookie — 403 «Missing cookie. You need to log in.». 🧪 В анонимном режиме запрос с cookie отклоняется.
- Тип Cookie (`IY1: 1`) с `IZ3.IV1` = Id пользователя: вызов с cookie этого пользователя (вход `AuthService.svc/Login`) — 200, действие выполняется от его имени. Cookie другого пользователя или пустой `IZ3` — 403 «Идентификатор пользователя в cookie не совпадает с ожидаемым по интеграции».
- В дизайнере выбор пользователя на вкладке «Аутентификация» может не сохраниться — проверяй `IZ3.IV1` в метаданных.
- 🧪 JWT: токен выдаёт `POST <CRM>/rest/WebhookService/Token`, нужен секретный ключ (проверка — `IsSecretKeyValid`).

## ✅ Что происходит при вызове
- Тело — JSON; значение параметра берётся по пути `IU1`.
- «Добавить данные» сохраняет запись через `Entity`: события объекта срабатывают (у контакта ФИО разобралось на фамилию и имя).
- `IR7: true` и нет параметров ответа — 200 с пустым телом. Исключение в действиях — 400, текст исключения в теле.
- 🧪 Журнал вызовов — логгеры `WebhookSchema` и `WebhookRequestResponse`, если включено логирование в схеме.
