# Исходный код: серверная логика объекта и слушатель событий — рецепты

Где писать серверную логику объекта и слушатель событий объекта (`EntityEventListener`): события и их порядок, запреты, отмена, асинхронные операции. Создание схемы исходного кода — в `source-code-edit.md`; API платформы — в `platform-api.md`.

## Где писать серверную логику объекта
- Новую серверную логику объекта (проверки и запреты при сохранении и удалении, заполнение колонок, создание связанных записей, журналы изменений) пиши в слушателе событий объекта — разделы ниже. Это решение по умолчанию: слушатель проще читать, ревьюить и отлаживать.
- Процесс событий объекта (вкладка «События», `EG1` в `metadata.json` объекта, `entity-events-edit.md`) умей читать: в проекте там может быть существующая логика, учитывай её, чтобы не задвоить поведение. Новую логику туда не добавляй, даже если пользователь пишет «при сохранении» или «события объекта». Делай процесс событий, только если пользователь прямо просит именно его.
- ✅ Ещё один способ менять базовую логику событий объекта (подтверждено записью в CRM, 23.10.2026): файл `Pkg/<Пакет>/Schemas/<Объект>/<Объект>.cs` рядом с `metadata.json` замещения объекта — `public partial class <Объект>_<Пакет>EventsProcess<TEntity>` с `override` виртуальных методов базового процесса событий (`[app]/BPMSoft.Configuration/Autogenerated/Src/<Объект>.<Пакет>.cs`, например `CalculateDurationOnSaving` у `Activity`). `EG1` в `metadata.json` не нужен: класс `<Объект>_<Пакет>EventsProcess` генерируется для любого замещения. Порядок: файл, свежий `ModifiedOnUtc` замещения, «Обновить из файловой системы», компиляция. Внутри `override` вызывай `base.<Метод>()`, сущность — `Entity`. Перед переопределением проверь в базовом коде, что метод действительно вызывается: базовый обработчик может звать одноимённый метод хелпера, а не процесса.
- Тексты для пользователя (сообщения об ошибках, значения по умолчанию вроде «Без темы», названия создаваемых записей) — только локализуемые строки схемы на ru-RU и en-US (рецепт ниже: `LocalizableString`). Константы в коде допустимы лишь для технических имён: колонки, коды системных настроек, имена схем.

## ✅ Слушатель событий объекта (`EntityEventListener`)
**Подтверждено 05.10.2026** на `TestSrcEntityEventListener` (объект `TestSrcEntity`): запись, созданная из кода, сохранилась с заметкой, которую заполнил слушатель перед сохранением; строка слушателя попала в `Common.log`.
```csharp
namespace BPMSoft.Configuration
{
	using BPMSoft.Core.Entities;
	using BPMSoft.Core.Entities.Events;
	using global::Common.Logging;

	[EntityEventListener(SchemaName = "TestSrcEntity")]
	public class TestSrcEntityEventListener : BaseEntityEventListener
	{
		private static readonly ILog _log = LogManager.GetLogger("Common");

		public override void OnSaving(object sender, EntityBeforeEventArgs e)
		{
			base.OnSaving(sender, e);
			var entity = (Entity)sender;
			var name = entity.GetTypedColumnValue<string>("Name");
			entity.SetColumnValue("Note", "Слушатель S2: " + name);
			_log.Info("TestSrcEntityEventListener.OnSaving: " + name);
		}
	}
}
```
- Файлы схемы — как у любой схемы исходного кода (выше), `B2: []`, если строк нет.
- `BaseEntityEventListener` и атрибут `EntityEventListener` — пространство имён `BPMSoft.Core.Entities.Events`. Переопределяемые методы: `OnSaving`, `OnSaved`, `OnInserting`, `OnInserted`, `OnUpdating`, `OnUpdated`, `OnDeleting`, `OnDeleted` (до события — `EntityBeforeEventArgs`, после — `EntityAfterEventArgs`); всегда вызывай `base.<Метод>(sender, e)`.
- ✅ **Порядок событий** (подтверждено пользователем, 11.10.2026; одинаков для слушателя и процесса событий объекта): изменение — `OnSaving` → `OnUpdating` → `OnUpdated` → `OnSaved`; добавление — `OnSaving` → `OnInserting` → `OnInserted` → `OnSaved`.
- ✅ **Где запрещать.** Запрет — исключение в событии «до»: в `OnSaving`, если проверка нужна при любом сохранении (и добавлении, и изменении); в `OnUpdating` — только при изменении; в `OnInserting` — только при добавлении. Исключение отменяет сохранение. Журнал изменений пиши в событиях «после» (`OnUpdated`, `OnInserted`, `OnSaved`), чтобы при отменённом сохранении он не появлялся.
- Не ветвись по `StoringState` внутри `OnSaving`, если правило касается одного случая: проверку только при изменении пиши в `OnUpdating`, значение по умолчанию только для новой записи — в `OnInserting`. `OnSaving` оставь для правил «при любом сохранении».
- Изменение колонки в `OnSaving`/`OnInserting` попадает в ту же запись без отдельного `Save()`.
- В `OnSaved`/`OnInserted`/`OnUpdated` запись уже записана: `SetColumnValue` в БД не попадёт (по опыту пользователя; для скрипта события объекта ✅ проверено 05.10.2026). Дообновить — запросом `Update` по `Id` или заново получить запись и вызвать `Save()` (повторно запустит события — не допускай рекурсии).
- Слушатель срабатывает на сохранение через приложение (`Entity.Save()`, карточка, процесс), не на прямой SQL.
- В проекте может быть свой базовый слушатель с типизированным `Entity` — поищи наследников `BaseEntityEventListener` в `Pkg`; стандартный `BaseEntityEventListener` работает без зависимостей от проектного кода.
- ✅ **Подпроцесс событий объекта раньше слушателя** (подтверждено записью в CRM, 21.10.2026): скрипт события «Перед сохранением» отрабатывает до `OnSaving` слушателя — слушатель уже видит значение, проставленное скриптом. Значит, финальное слово в событии «до» — за слушателем.
- ✅ **Отмена без ошибки** (21.10.2026): `e.IsCanceled = true;` в `OnInserting` — запись не создаётся, `entity.Save()` возвращает `false`, исключения и сообщения нет. Пользователь не узнает, почему запись не сохранилась, поэтому для запрета с объяснением бросай исключение.
- ✅ **Колонка не загружена** (21.10.2026): у сущности, созданной `CreateEntity` без `SetDefColumnValues()`, чтение колонки, которую не задавали, — `InvalidObjectStateException: Невозможно получить значение колонки <Колонка>, так как она не была загружена`. Это касается и слушателей, и скриптов событий этого объекта. В коде, который создаёт запись, вызывай `SetDefColumnValues()` или задавай колонку явно.
- ✅ **Долгая работа после сохранения — асинхронная операция** (подтверждено записью в CRM, 21.10.2026): сохранение не ждёт её (12 мс вместо 2 с работы операции), операция выполняется от имени того же пользователя.
  ```csharp
  // using BPMSoft.Core; using BPMSoft.Core.Entities.AsyncOperations;
  // using BPMSoft.Core.Entities.AsyncOperations.Interfaces; using BPMSoft.Core.Factories;
  public class <Операция> : IEntityEventAsyncOperation
  {
  	public void Execute(UserConnection userConnection, EntityEventAsyncOperationArgs arguments) {
  		// arguments.EntityId — Id записи; запись уже в БД
  	}
  }
  // в слушателе, OnInserted / OnSaved:
  var asyncExecutor = ClassFactory.Get<IEntityEventAsyncExecutor>(
  	new ConstructorArgument("userConnection", entity.UserConnection));
  asyncExecutor.ExecuteAsync<<Операция>>(new EntityEventAsyncOperationArgs(entity, e));
  ```
  Ошибка внутри операции не вернётся пользователю — пиши её в лог.

✅ **Запрет изменения и удаления, значение по умолчанию** (06.10.2026, `TestTicketCommentEventListener`, объект `TestTicketComment`):

- `OnInserting` — заполнение колонки, если пусто: `entity.SetColumnValue("AuthorId", entity.UserConnection.CurrentUser.ContactId)`
- ✅ Обязательную колонку (`E2: 1`) в `OnInserting` не заполнить при вставке через `DataService` (`InsertQuery`): запрос отклоняется с `RequiredColumnsEmptyValuesException` раньше слушателя (подтверждено записью в CRM, 29.10.2026). Значение при создании для такой колонки задавай значением по умолчанию (`E12`, `entity-columns-edit.md`, «Значение по умолчанию у унаследованной колонки в замещении»)..
- Текст ошибки — локализуемая строка самой схемы исходного кода (ресурсы `Resources/<Схема>.SourceCode/resource.<культура>.xml`): `new LocalizableString(userConnection.Workspace.ResourceStorage, "<Схема>", "LocalizableStrings.<Имя>.Value").ToString()`.
- Значение из БД до изменения читается запросом: `new Select(userConnection).Column("AuthorId").From("<Объект>").Where("Id").IsEqual(Column.Parameter(entity.PrimaryColumnValue)) as Select`, затем `ExecuteScalar<Guid>()` (`using BPMSoft.Core.DB;`).

✅ **Проверено записью в CRM (22.10.2026):**
- Несколько атрибутов на одном классе работают: `[EntityEventListener(SchemaName = "<Объект1>")]` и `[EntityEventListener(SchemaName = "<Объект2>")]` — слушатель вызывается для обоих объектов.
- `[EntityEventListener(IsGlobal = true)]` — слушатель вызывается для записей **всех** объектов; фильтруй по `((Entity)sender).Schema.Name`. Порядок при проверке: сначала слушатель объекта, потом глобальный.
- `OnDeleteFailed(object sender, EntityErrorEventArgs e)` вызывается, когда удаление упало в БД (например, на запись ссылается другая запись): `e.Exception` — `PostgresException`, `e.KeyValue` — ключ. После него `Entity.Delete()` всё равно бросает `DbOperationException` — слушатель ошибку не гасит.
- В слушателе `entity.UserConnection` — соединение, через которое сохраняли: пользователь сервиса или системный пользователь, если запись сохраняли через `SystemUserConnection`.
