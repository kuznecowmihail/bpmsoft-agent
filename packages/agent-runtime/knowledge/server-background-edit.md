## ✅ Задание по расписанию на C# (подтверждено записью в CRM, 24.10.2026)
```csharp
// using System.Collections.Generic; using BPMSoft.Core; using BPMSoft.Core.Scheduler;
public class <Префикс>Job : IJobExecutor
{
	public void Execute(UserConnection userConnection, IDictionary<string, object> parameters)
	{
		// работа; parameters — словарь, переданный при постановке
	}
}

// постановка: из слушателя событий приложения (OnAppStart) или из сервиса
AppScheduler.ScheduleMinutelyJob<<Префикс>Job>("<Группа>", userConnection.Workspace.Name,
	userConnection.CurrentUser.Name, <период в минутах>, parameters, isSystemUser: true);
```
- Имя задания — полное имя класса (`BPMSoft.Configuration.<Класс>`), группа — своя строка. Повторный вызов с тем же классом и группой дубль не создаёт: обновляет период и параметры, расписание сохраняется. Ставить задание при каждом старте приложения (`OnAppStart`, `source-code-edit.md`, «Слушатель событий приложения») безопасно — так делает и код платформы.
- Первый запуск — сразу после постановки, дальше раз в период.
- Задание хранится в БД (`qrtz_job_details`, `qrtz_triggers`, `qrtz_simple_triggers`, планировщик `BPMCRMQuartzScheduler`) и переживает перезапуск и компиляцию. Класс записан как `<полное имя>, BPMSoft.Configuration, Version=<версия платформы>…` — перекомпиляция задание не ломает.
- Параметры приходят с исходными типами: проверены `String`, `Int32`, `Guid`, `Boolean`.
- Журнал — `[app]/Logs/<ГГГГ-ММ-ДД>/Scheduler.log`: `JobStart` и `JobFinish [className:…]`, при исключении — `JobFail` со стеком. Исключение задание не снимает: следующий запуск — по расписанию.
- ✅ От чьего имени (24.10.2026): `isSystemUser: false` — от пользователя из параметра `userName` (кто поставил задание); `isSystemUser: true` — от системного пользователя (системная настройка `SystemUser`, обычно `Supervisor`).
- Другие методы `AppScheduler` (проверены): `DoesJobExist(<имя>, <группа>)`, `IsJobRunning(<имя>, <группа>)`, `RemoveJob(<имя>, <группа>)` → `bool`, `DoesJobGroupExist(<группа>)`; `TriggerJob<<Класс>>(<группа>, <рабочее пространство>, <пользователь>, parameters)` — внеочередной запуск сейчас, расписание не меняется; `ScheduleImmediateJob<<Класс>>(…)` — один запуск, после него задания нет.
- Расписание по cron в коде платформы: `AppScheduler.CreateClassJob<<Класс>>(<имя>, <группа>, UserConnection)` + `new CronTriggerImpl(<имя триггера>, <группа>, <cron>)` + `AppScheduler.Instance.ScheduleJob(job, trigger)` под проверкой `DoesJobExist`; образцы — `[app]/BPMSoft.Configuration/Autogenerated/Src`, поиск по `CreateClassJob<`. 🧪 не проверялось.

### ⚠️ Удаление класса задания
Сначала сними задание (`RemoveJob`), потом удаляй схему. Если задание осталось, после компиляции оно раз в период падает с `JobFail … InstanceActivationException: Ошибка создания экземпляра класса "BPMSoft.Core.IJobExecutor"` (`Scheduler.log`) и остаётся в расписании. Снять без кода — SQL (SQL-скрипт пакета или запрос пользователя); внешних ключей между таблицами `qrtz_*` нет, удаляй из всех:
```sql
DELETE FROM qrtz_simple_triggers WHERE sched_name = 'BPMCRMQuartzScheduler' AND trigger_group = '<Группа>';
DELETE FROM qrtz_cron_triggers WHERE sched_name = 'BPMCRMQuartzScheduler' AND trigger_group = '<Группа>';
DELETE FROM qrtz_triggers WHERE sched_name = 'BPMCRMQuartzScheduler' AND trigger_group = '<Группа>';
DELETE FROM qrtz_job_details WHERE sched_name = 'BPMCRMQuartzScheduler' AND job_group = '<Группа>';
```
✅ После такого удаления задание перестало запускаться без перезапуска приложения (24.10.2026).

## ✅ Фоновая задача (подтверждено записью в CRM, 24.10.2026)
```csharp
// using System; using BPMSoft.Core; using BPMSoft.Core.Tasks;
public class <Префикс>TaskParameters
{
	public Guid RecordId { get; set; }
}

public class <Префикс>Task : IBackgroundTask<<Префикс>TaskParameters>, IUserConnectionRequired
{
	private UserConnection _userConnection;

	public void SetUserConnection(UserConnection userConnection)
	{
		_userConnection = userConnection;
	}

	public void Run(<Префикс>TaskParameters parameters)
	{
		// работа с _userConnection
	}
}

// запуск из сервиса или слушателя
BPMSoft.Core.Tasks.Task.StartNewWithUserConnection<<Префикс>Task, <Префикс>TaskParameters>(
	new <Префикс>TaskParameters { RecordId = <Id> });
```
- Вызов возвращает управление сразу (проверено: 32 мс при задаче на 3 с); задача выполняется в другом потоке уже после ответа сервиса, `UserConnection` у неё — пользователя, который её запустил (проверено под администратором и под обычным пользователем, 24.10.2026).
- Параметры — обычный класс со свойствами, атрибуты сериализации не нужны (так и в коде платформы); простой тип (`Guid`) тоже подходит.
- Пиши `BPMSoft.Core.Tasks.Task` полностью: в коде платформы так или `Core.Tasks.Task`, чтобы не спутать с `System.Threading.Tasks.Task`.
- Исключение в `Run` пользователь не видит: оно только в `[app]/Logs/<ГГГГ-ММ-ДД>/ActorSystem.log` (`ERROR ActorSystem - <текст>` со стеком). Повторного запуска нет.
- `Task.StartNew<…>` — вариант без `UserConnection`; для работы с данными код платформы использует `StartNewWithUserConnection`.
