## ✅ Создать REST-сервис
Шаблон из подтверждённого теста — `templates/process/web-service-schema/` (descriptor, metadata, properties, ресурсы; плейсхолдеры `<UId схемы сервиса>`, `<UId пакета>`). Бери его, если в проекте нет своего сервиса.
1. Папка `Pkg/<Пакет>/Schemas/<Имя>/`, три файла:
   - `descriptor.json` — новый `UId`, `Name`, `ModifiedOnUtc` (`date +%s000`), `"ManagerName": "ServiceSchemaManager"`, `Caption`, `"DependsOn": []`;
   - `properties.json` — `BaseUri` (тот же, что `IQ1`), `CreatedInVersion` (`<версия платформы>`, `metadata-editing.md`, поле `B8`), `"Type": "Rest"`;
   - `metadata.json` — плоский JSON, ключи в порядке из `web-service.md`: `ManagerName`, `UId` (= `UId` дескриптора), `A2` (= имя), `A5` (`<Id пакета>`, `metadata-editing.md`, поле A5), `B1`/`B2`/`B3` = `[]`, `B6` (UId пакета), `B8` (версия), `IQ1`, `IQ2: 1`, `IQ3` (только если повторы нужны), `IQ7: []`, `IQ4` — методы.
2. Метод: `{"UId": "<новый>", "A2": "<Метод>", "A3": "<UId сервиса>", "A4": "<UId сервиса>", "IR3": 30000, "IR5": "null", "IR1": {"IW2": 1, "IW1": [<параметры запроса>], "IT2": <1 GET | 2 POST | 3 PUT | 4 PATCH | 5 DELETE>, "IT1": "/<адрес>"}, "IR2": {"IW2": 1, "IW1": [<параметры ответа>]}}`.
3. Параметр: `{"UId": "<новый>", "A2": "<Код в BPMSoft>", "IU1": "<путь>", "IU2": "Text", "IU8": "item", "IU4": <1 тело | 2 сегмент URL | 3 query | 4 заголовок>, "IU5": {"IV1": "null", "IV2": 1}, "IU6": []}`. Путь (`IU1`) тела — `$.<поле>`, свойства внутри объекта — `<поле>`; заголовка — его имя; сегмента URL — имя из `{имя}` в `IT1`. Обязательный — `"IU7": true` после `IU2`/`IU9`/`IU3`; массив — `"IU3": true`; объект — `"IU2": "Object"`, `"IU3": true`, свойства в `IU6`, `"IU5": {"IV1": "null"}`. Константа по умолчанию — `"IU5": {"IV1": "<значение>", "IV2": 1}`.
4. Ресурсы `Pkg/<Пакет>/Resources/<Имя>.Service/resource.ru-RU.xml` и `resource.en-US.xml`: `Caption`, `ServiceMethods.<Метод>.Caption`, `ServiceMethods.<Метод>.Request.Parameters.<Параметр>.Caption`, `...ItemProperties.<Свойство>.Caption`, `ServiceMethods.<Метод>.Response.Parameters.<Параметр>.Caption`.
5. Секреты (ключи API, токены) не пиши константой в схему: репозиторий пакета уходит в git. Передавай их из процесса (значение из системной настройки) или через значение по умолчанию из системной настройки (`IU5` = `{"IV1": "<код настройки>", "IV2": 2}`, ✅); логин и пароль сервиса — так же через `IQ5` (`web-service.md`, «Аутентификация сервиса»).
6. Пользователь: «Обновить из файловой системы», открыть сервис в конфигурации, у метода «Отправить тестовый запрос». Сам сервис компиляции не требует; процесс с заданием-сценарием — компилировать. В окне метода «Полный адрес» показывает и query-параметры: `https://<хост>/post?source={значение}`.

## ✅ Добавить метод или параметр в существующий сервис
Дописать объект в `IQ4` или в `IW1` нужного метода (новые `UId`), строки подписей в оба ресурса, обновить `ModifiedOnUtc`. Процессы, которые уже вызывают метод, новый параметр сами не получат: в их элементы его добавляет Designer при открытии или ты — по правилам ниже.
✅ Проверено: второй метод (копия существующего с новыми `UId` всех вложенных объектов и своим `A2`) и новый параметр запроса в `IW1` загрузились «Обновить из файловой системы» без компиляции; подписи `ServiceMethods.<Метод>.Caption` и `...Request.Parameters.<Параметр>.Caption` попали в `SysLocalizableValue`. ✅ Вызов нового метода из процесса (подтверждено записью в CRM): сервис создан файлами с одним методом и загружен, второй метод дописан файлами и загружен «Обновить из файловой системы» без компиляции; Designer процесса показал оба метода по подписям `ServiceMethods.<Метод>.Caption`, параметр запроса и параметр ответа нового метода; процесс выполнился, значение `_Out`-параметра записалось элементом «Добавить данные». Элемент получил `IX2` = `A2` нового метода.

## ✅ Вызвать REST-сервис из C#
**Подтверждено записью в CRM.**
```csharp
using BPMSoft.Configuration.ServiceSchema;
using BPMSoft.Core.Factories;
…
var client = ClassFactory.Get<IServiceSchemaClient>();
var response = client.Execute(UserConnection, "<Имя сервиса>", "<A2 метода>",
	new Dictionary<string, object> { { "<A2 параметра>", <значение> } });
// response.Success, response.StatusCode, response.Body — тело ответа строкой
```
- Ключи словаря — «Код в BPMSoft» (`A2`) параметров запроса; параметр без значения получает значение по умолчанию (`IU5`, в том числе из системной настройки).
- Работает под обычным пользователем; ошибка HTTP не бросает исключение — смотри `Success` и `StatusCode` (например, 401 без аутентификации).
- Сервису с аутентификацией (`web-service.md`, «Аутентификация сервиса») логин и пароль подставляются сами.

## ✅ Удалить сервис
Как любую схему (`metadata-editing.md`, «Удаление схемы»): папки `Schemas/<Имя>/` и `Resources/<Имя>.Service/`. Перед удалением найди по всему `Pkg` элементы процессов с `IX1` = UId сервиса и предупреди пользователя.

✅ Подтверждено записью в CRM: удалены папки сервиса и процесса, который его вызывал (схем, ресурсов), после «Обновить из файловой системы» обе схемы исчезли из конфигурации CRM.
