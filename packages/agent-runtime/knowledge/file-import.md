# Импорт из Excel — факты

Мастер «Импорт данных» раздела: как открыть, что он делает с записями, где лежат параметры и результат, каким должен быть файл. Проверено записью в CRM (импорт контактов, стенд .NET 8).

## ✅ Как открыть
- Пункт «Импорт данных» в меню раздела открывает мастер `<CRM>/Nui/ViewModule.html?vm=FileImportWizard#FileImportModule/FileImportStartPage/<Id сессии>/<Объект>` (`<Id сессии>` — новый GUID). Адреса страниц — `browser-check.md`, «Адреса страниц».
- Право на импорт — системная операция `CanImportFromExcel` (`rights.md`, «Системные операции»).
- Шаги: файл и объект → теги → колонки (сопоставление по заголовку колонки файла и подписи колонки объекта, автоматически) → параметры дублей → выполнение → «Загружено N из M записей в исходном файле».

## ✅ Файл
- Только `.xlsx`, первая строка — заголовки колонок.
- Строки ячеек — в общей таблице строк (`xl/sharedStrings.xml`), как сохраняет Excel. Файл со строками прямо в ячейках (`t="inlineStr"`, так пишут некоторые генераторы) мастер считает пустым: «Файл пустой. Убедитесь, что файл содержит заголовки колонок, значения, и повторите попытку.».

## ✅ Что происходит с записями
- Каждая строка сохраняется через `Entity.Save` в фоновом процессе импорта: события объекта, слушатели и процессы по сигналу срабатывают как при сохранении из карточки (у контакта ФИО разобралось на фамилию и имя, мобильный телефон попал в средства связи). Автор записей — пользователь, запустивший импорт.
- Логика в событиях объекта выполняется для каждой строки — тяжёлая логика замедляет импорт. 🧪 Системная настройка `RunProcessesInBackgroundOnFileImport` включает сохранение в фоновом режиме (`EntitySaveConfig.SetForceBackgroundMode`).
- Каждый импорт создаёт тег «Загрузка данных <дата> <время>» в объекте тегов раздела (у контактов — `ContactTag`) и привязывает к нему загруженные записи.
- Дубли: на шаге «Параметры дублей» отмечаются ключевые колонки. Без ключевых колонок каждая строка — новая запись: повторный импорт того же файла создал вторые копии всех контактов. Правила дублей — `duplicates.md`.

## ✅ Где смотреть результат
- `FileImportParameters` — строка на сессию, `Id` = `<Id сессии>` из адреса мастера. Запросы к таблицам — `crm-db.md`, «Данные из БД CRM».
- `ImportParameters` — JSON: `rootSchemaUId`, `columns[]` (`source` — заголовок в файле, `destinations[]` → `columnName`, `isKey` — ключевая колонка), `importedRowsCount`, `notImportedRowsCount`, `totalRowsCount`, `chunkSize`, `authorId`.
- `Stage` — этап (`4` после завершения), `FileData` — сам файл.
- 🧪 Ошибки отдельных строк — журнал импорта (в успешном импорте не проверялся). Общие ошибки выполнения — `errors.md`.

## 🧪 Расширение импорта
- Класс импорта (`FileImporter`, пакет FileImport) поднимает события `ImportEntitySaving`, `ImportEntitySaved`, `BeforeImportEntitiesSave`, `AfterImportEntitiesSave`, `ImportEntitySaveError`, `ColumnProcessError`.
- Логику, которая нужна и при импорте, и при обычном сохранении, пиши в слушателе объекта (`server-events-edit.md`), а не в событиях импорта.
