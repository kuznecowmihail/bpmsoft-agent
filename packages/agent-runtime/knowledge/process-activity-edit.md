**Предзаполнение полей (`RecordColumnValues`)** — тот же формат, что `RecordDefValues` у «Добавить данные» (`process-data-edit.md`): элемент на колонку, `columnMetaPath` = UId колонки, `schemaUId` = UId объекта; текст-константа — `isLczValue` в `L8`, текст прямо в `GT1` и ресурсы `BaseElements.<Элемент>.Parameters.RecordColumnValues.Value.<ItemUId>.value` / `.displayValue`; макрос — `Source 3`. Набор колонок произвольный: Designer по умолчанию кладёт туда свои поля, их можно заменить любыми колонками объекта. UId колонок базового объекта — в `Autogenerated/Src/<Объект>Schema.Base.cs`, тип текстовой колонки `MediumText` — `ddb3a1ee-07e8-4d62-b7a9-d0e618b00fbd`.
- `Web` контрагента после сохранения остался пустым в одном проекте (остальные поля сохранились). На базовой платформе ✅ `Web`, заданный в карточке контрагента до сохранения (так делает предзаполнение), сохраняется и копируется в средства связи (`AccountCommunication`); то же при вставке через DataService. Пустой `Web` — проектная доработка (замещение `Account` или его карточки, синхронизация средств связи): проверь её в проекте, прежде чем полагаться на предзаполнение `Web`.

- ✅ **Не ждать выполнения задачи** (подтверждено в CRM): у «Выполнить задачу» нет настройки «не ждать». Решение — отдельный процесс с «Выполнить задачу», который задание-сценарий запускает для каждой записи через `UserConnection.ProcessEngine.ProcessExecutor.Execute("<Процесс>", parameters)`: вызов возвращает управление, как только задача создана. Подпроцесс по коллекции так не работает — родитель ждёт выполнения всех задач.
- ✅ **Связь задачи с записью**: «Выполнить задачу» заполняет только колонки активности, зарегистрированные как связи в `EntityConnection` (`SysEntitySchemaUId` — объект `Activity`): для них элемент получает динамические параметры (`ProcessUserTaskUtilities.SynchronizeActivityConnectionParameters` в `Autogenerated/Src`). Свою справочную колонку `Activity` без такой регистрации элемент не заполняет. Проставь её после элемента заданием-сценарием по выходу `CurrentActivityId`: `CreateEntity` → `FetchFromDB(<Id активности>)` → `SetColumnValue("<Колонка>Id", <Id записи>)` → `Save(false)`. Регистрация колонки в `EntityConnection`, чтобы элемент заполнял её сам, — 🧪 не проверено.
- ✅ **Незавершённая задача**: у справочника статусов активности `ActivityStatus` есть логическая колонка `Finish` — признак завершённого статуса; незавершённые активности отбирай фильтром `Status.Finish = false`, а не по списку статусов.
- ✅ **Срок задачи «до конца дня»**: формула в целочисленный параметр `(int)([#SysVariable.CurrentDateTime#].Date.AddDays(1).AddMinutes(-1) - [#SysVariable.CurrentDateTime#]).TotalMinutes`; `Duration` задачи — ссылка на этот параметр (`GS1: 3`, в параметре и в маппинге), `DurationPeriod` = 0 (минуты).
