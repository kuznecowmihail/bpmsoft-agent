# API платформы для C#: где искать и проверенные факты

Для серверного кода: схемы исходного кода, слушатели событий, свои действия процесса. Здесь — какой `using` нужен, где посмотреть сигнатуру метода и значения перечислений. Рецепты целиком — в `source-code-edit.md` и `user-task-edit.md`.

## Порядок поиска API
1. ✅-факты этого файла — используй сразу, без поиска.
2. XML-документация платформы `[app]/BPMSoft.*.xml` — официальная поставка, лежит рядом с DLL в любой установке; основной файл — `BPMSoft.Core.xml`, общие типы — `BPMSoft.Common.xml`.
3. Примеры вызова в `[app]/BPMSoft.Configuration/Autogenerated/Src` и в `Pkg` — как метод реально вызывают и какие `using` стоят рядом.
4. `[app]/ResourcesCore` — декомпилированный код платформы, если папка есть (в реальном проекте её обычно нет).
5. Подтверждения нет нигде — не угадывай: укажи в плане риск ошибки компиляции.

## Как читать XML-документацию
- Каждый элемент — `<member name="<префикс>:<полное имя>">` с описанием в `<summary>`, `<param>`, `<returns>`.
- Префикс: `T:` — тип (класс, интерфейс, перечисление), `M:` — метод или конструктор (`#ctor`), `P:` — свойство, `F:` — поле или значение перечисления, `E:` — событие.
- Пространство имён для `using` — всё, что стоит перед именем класса: `T:BPMSoft.Core.Entities.Entity` → `using BPMSoft.Core.Entities;`.
- Параметры метода — полными именами типов в скобках: `M:BPMSoft.Core.Entities.Events.BaseEntityEventListener.OnSaving(System.Object,BPMSoft.Core.Entities.EntityBeforeEventArgs)`.
- Описаны не все типы. Если строки `T:` нет, пространство имён видно по именам методов типа (`M:...`) или по ссылкам `cref="T:..."`.

Команды (вместо `[app]` — корень приложения; файлы большие — ищи точечно, целиком не читай):
```bash
# пространство имён типа
grep -ho 'name="T:[A-Za-z.]*\.EntitySchemaQuery"' [app]/BPMSoft.*.xml
# тип не описан — пространство имён по ссылкам на него
grep -ho 'cref="T:[A-Za-z.]*\.UserConnection"' [app]/BPMSoft.Core.xml | sort -u
# методы класса с параметрами
grep -o 'name="M:BPMSoft.Core.Entities.EntitySchemaManager\.[^"]*"' [app]/BPMSoft.Core.xml
# описание конкретного метода
grep -n -A6 'name="M:BPMSoft.Core.Configuration.SysUserInfo.GetCurrentDateTime"' [app]/BPMSoft.Core.xml
# значения перечисления
grep -o 'name="F:BPMSoft.Common.OrderDirectionStrict\.[^"]*"' [app]/BPMSoft.Common.xml
```

## Частые операции
- ✅ Создать запись: `userConnection.EntitySchemaManager.GetInstanceByName("<Объект>")` → `schema.CreateEntity(userConnection)` → `SetDefColumnValues()` → `SetColumnValue(...)` → `Save(false)`. Рецепт — `source-code-edit.md`, «Создать связанную запись после вставки».
- ✅ Прочитать одно значение из БД: `new Select(userConnection).Column("<Колонка>").From("<Объект>").Where("Id").IsEqual(Column.Parameter(id)) as Select`, затем `ExecuteScalar<T>()`.
- ✅ Изменить запись без событий объекта: `new Update(userConnection, "<Объект>").Set("<Колонка>", Column.Parameter(value)).Where("Id").IsEqual(Column.Parameter(id)) as Update`, затем `Execute()` (`entity-edit.md`, скрипт «После сохранения»).
- ✅ Выборка записей `EntitySchemaQuery` (07.10.2026, `TestTicketStatsService`, без ResourcesCore): `new EntitySchemaQuery(UserConnection.EntitySchemaManager, "<Объект>") { UseAdminRights = false }`; колонка справочника через точку — `var column = esq.AddColumn("TestPriority.Name"); column.Name = "TestPriorityName";`, значение — `entity.GetTypedColumnValue<string>(column.Name)`; фильтры — `esq.CreateFilterWithParameters(FilterComparisonType.Equal, "<Колонка>", value)`, `esq.CreateIsNullFilter("<Колонка>")`, `esq.CreateIsNotNullFilter("<Колонка>")`; группа «ИЛИ» — `new EntitySchemaQueryFilterCollection(esq, LogicalOperationStrict.Or) { <фильтр>, <фильтр> }`, затем `esq.Filters.Add(...)`; сортировка — `esq.AddColumn("<Колонка>").OrderByDesc(<позиция сортировки 1, 2…>)`; первые N записей — `esq.RowCount = N`; результат — `esq.GetEntityCollection(UserConnection)`. Агрегация (`AggregationTypeStrict`) не проверена: количество посчитано в памяти.
- ✅ Ответ REST-метода объектом (07.10.2026, `TestTicketStatsService`): классы с `[DataContract]`, свойства с `[DataMember(Name = "<имя в JSON>")]` (`using System.Runtime.Serialization;`); при `BodyStyle = WebMessageBodyStyle.Wrapped` клиент получает `{"<Метод>Result": {<поля по Name>}}`, `List<T>` — массивом объектов.
- ✅ Группировка в запросе (подтверждено в CRM, 09.10.2026): колонки группировки — обычные `esq.AddColumn("<Справочник>.Id")`, `esq.AddColumn("<Справочник>.Name")`; агрегаты — `esq.AddColumn(esq.CreateAggregationFunction(AggregationTypeStrict.Count, "Id"))` и `esq.AddColumn(esq.CreateAggregationFunction(AggregationTypeStrict.Sum, "<Колонка>"))`; `esq.PrimaryQueryColumn.IsAlwaysSelect = false`; сортировка — `column.OrderByDesc(<позиция>)`; чтение — `GetEntityCollection`. ❌ `AddColumn("Id")` с `SummaryType = AggregationType.Count` рядом с `<Справочник>.Id` отдаёт в агрегат Id справочника — `GetTypedColumnValue<int>` падает с `FormatException` (09.10.2026).
- ✅ Новая ли запись (в `OnSaving`): `entity.StoringState == StoringObjectState.New`.
- ✅ Вставка запросом, без событий объекта (07.10.2026, `TestTicketEventListener` → `TestTicketPriorityLog`): `new Insert(userConnection).Into("<Объект>").Set("<Колонка>Id", Column.Parameter(value))…`, затем `Execute()`. `Id` и `CreatedOn` можно не задавать — заполнились сами; `CreatedBy`/`ModifiedBy` при вставке запросом не проверялись. Пустое значение справочника не передавай — пропусти его `Set` (так сделано и проверено).
- ✅ Старое значение колонки после сохранения (07.10.2026, тот же слушатель): в `OnUpdated(object sender, EntityAfterEventArgs e)` — `e.ModifiedColumnValues`, коллекция `EntityColumnValue` (`Name`, `OldValue`); колонки нет в коллекции — значение не менялось. Для справочной колонки имя — с суффиксом `Id` (`x.Name == "<Колонка>Id"`; ✅ на реальных схемах проекта и в `Autogenerated/Src`, журнал смены статуса заработал 08.10.2026); `OldValue` приводи через `is Guid`. `ModifiedColumnValues` в XML-документации нет — найден по примерам в `Pkg` (проектный базовый слушатель). Вариант из `Autogenerated/Src` — `entity.GetTypedOldColumnValue<T>("<Колонка>")` в `OnSaving` — ✅ (08.10.2026, проверка изменения срока).
- Текущее время: `userConnection.CurrentUser.GetCurrentDateTime()` — по XML-документации текущее время, переведённое в часовой пояс пользователя. 🧪 Подходит ли оно для записи в колонки даты и времени или нужен `DateTime.UtcNow` — см. `source-code-edit.md`, не проверено при поясе профиля, отличном от UTC. Смещение пояса пользователя — `UserConnection.CurrentUser.GetTimeZoneOffset()` (`TimeSpan`, с учётом летнего времени); 🧪 проверено только при поясе UTC.
- Системная настройка, `ClassFactory` и `ReBind`, слушатель событий приложения — `source-code-edit.md`.

## Чего нет в XML-документации
- `StoringObjectState` — не описан совсем (значения — выше).
- Типы `UserConnection`, `EntitySchemaManager`, `SysUserInfo`, `EntityBeforeEventArgs` не имеют строки `T:`, но их методы (`M:`) и ссылки (`cref`) есть — пространство имён находится по ним.
- `EntityAfterEventArgs.ModifiedColumnValues`, `Entity.GetTypedOldColumnValue` / `GetColumnOldValue` — только в примерах `Pkg` и `Autogenerated/Src` (свойство `EntityColumnValue.OldValue` в XML есть).
