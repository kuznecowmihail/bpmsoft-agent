# Проверка реализации во встроенном браузере CRM

Инструменты `crm_browser_*` (включаются пользователем в настройках) открывают CRM в панели справа в окне приложения. Здесь — как проверять быстро, за несколько действий.

## ✅ Адреса страниц (13–14.10.2026, 29.10.2026)
- Страницы — `/Nui/ViewModule.aspx` или `/Nui/ViewModule.html` с частью после `#`, без `/0/` (.NET 8). Дизайнеры открываются по обоим: `/Nui/ViewModule.aspx?vm=DcmDesigner#case/<UId>` и `/Nui/ViewModule.html?vm=DcmDesigner#case/<UId>` (✅ подтверждено записью в CRM (29.10.2026)). Префикс `/0/` ломает только адреса с `?vm=`: `/0/Nui/ViewModule.aspx?vm=…` переходит на `ViewModule.html` без `vm` (пустая оболочка, дизайнера нет), `/0/Nui/ViewModule.html?vm=…` — пустая страница (✅ подтверждено записью в CRM (29.10.2026)). Адрес без `vm` с `/0/` открывается: `…/0/Nui/ViewModule.aspx#CardModuleV2/<Схема>/add` переходит на `/Nui/ViewModule.html#…` с сохранением части после `#` (✅ подтверждено записью в CRM (29.10.2026)). Дизайнер процесса: `/Nui/ViewModule.aspx?vm=SchemaDesigner#process/<UId схемы>` (✅ 14.10.2026, `process-run-edit.md`).
- Дизайнер объекта: `/ClientApp/#/EntitySchemaDesigner/<UId схемы>` открывается (✅ подтверждено записью в CRM (29.10.2026)); `ViewModule.aspx?vm=EntitySchemaDesigner#entity/<UId>` даёт пустую страницу.
- Конфигурация пакетов: `/ClientApp/#/WorkspaceExplorer`. «Обновить из файловой системы» — «Действия» → «Обновить пакеты из файловой системы»; результат — диалог «Изменения» (списки «Добавлено», «Изменено») или «Изменений не найдено» (✅ подтверждено записью в CRM (29.10.2026)). Что попадает в `Pkg` без выгрузки пакетов: `metadata-editing.md`, «Что дизайнеры пишут в файлы».
- Раздел: `#SectionModuleV2/<Схема раздела>/`.
- Карточка записи: `#CardModuleV2/<Схема карточки>/edit/<Id>`; Id — запросом к БД (`crm-db.md`), если доступ включён.
- Новая запись: `#CardModuleV2/<Схема карточки>/add` — для проверки без сохранения.
- Карточку-наследника можно открыть без регистрации в `SysModule*` (`client-pages-edit.md`, «Создать новую карточку (Page) с нуля»; регистрация — `registration.md`).
- При переходе только по части после `#` заголовок окна обновляется с задержкой — ориентируйся на текст страницы, а не на заголовок.

## ✅ Кэш после обновления
- После «Обновить из файловой системы» правка клиентской схемы может не появиться: страница берётся из кэша браузера. Первое открытие после обновления инструментом сбрасывает кэш само; если обновлял пользователь — открой с `fresh: true`.
- Открытие страницы инструментом всегда загружает её заново, даже если меняется только часть адреса после `#`: иначе в памяти остаются старые модули схем и после исправления видна прежняя ошибка.
- Кеши сервера и приложения — `platform-api.md`, «Кеши и перезапуск».

## ✅ Как найти элемент
- Сначала `crm_browser_text` без селектора: весь текст страницы — подписи полей, кнопки, значения. Обычно этого хватает.
- ⚠️ Первое чтение после перезапуска CRM: сразу после компиляции с перезапуском `crm_browser_text` может вернуть пустой текст, а заголовок остаться «BPMSoft», хотя ошибок загрузки нет. Повтори чтение через несколько секунд — страница уже открыта. Не делай вывод «не работает» по первой пустой выдаче.
- ✅ Во вкладке без фокуса `innerText` пуст: читай `textContent`.
- Поле на карточке ищи по подписи из текста страницы и по `[id*='<Колонка>']`.
- Элементы страницы могут быть помечены атрибутом `data-item-marker` с именем элемента из схемы. Селектор `[data-item-marker="<Колонка>"]` используй, только если он уже сработал на этой странице: маркер не всегда совпадает с именем колонки. ⚠️ На новой карточке (`/add`) по нему не нашлось поле шапки, у которого имя в diff совпадает с колонкой, хотя подпись была в тексте страницы.
- Кнопка — по видимому тексту: `crm_browser_click` с параметром `text`.
- ✅ Поле-справочник: список значений открывается кликом по `[id*='<Колонка>'] input`. Селектор `[data-item-marker='<Колонка>']` поле не нашёл, а `[data-item-marker*='<Колонка>']` попал в подпись.
- ⚠️ Выбранное значение справочника в текст страницы не попадает, видно только на снимке; пункты открытого списка в тексте есть. Проверяя автозаполнение или фильтр справочника, открывай список (`crm_browser_click` по полю) и читай пункты, а текущее значение смотри снимком.
- ✅ Флажок переключается кликом по `[id*='<Колонка>CheckBoxEdit']`. Клик по тексту подписи и по `[data-item-marker="<Колонка>"]` флажок не переключает.
- ✅ Подсказка у поля: значок «?» нажался кликом по составному селектору `[data-item-marker="<Колонка>"] .info-button, [id*="<Колонка>"] [class*="tip"], [id*="<Колонка>"] [class*="info"]`. 🧪 Какой из вариантов совпал — не установлено. Текст подсказки после клика есть в полном тексте страницы (`crm_browser_text` без селектора).
- Не перебирай CSS-классы наугад: если элемент не найден по тексту и `id*=`, сделай один снимок и посмотри вёрстку.

### ✅ Проверить деталь на карточке (14.10.2026)

Порядок без перебора селекторов. `<Деталь>` — ключ детали из блока `details` карточки, он входит в `id` её контейнера.

1. Открыть карточку, перейти на вкладку: `crm_browser_click` по названию вкладки (параметр `text`).
2. Деталь по умолчанию свёрнута: `crm_browser_text` с селектором `[id*='<Деталь>'] .ts-controlgroup-container` вернёт только заголовки колонок, без строк. Это не ошибка и не пустая деталь.
3. Раскрыть деталь — клик по стрелке: `crm_browser_click` с селектором `[id*='<Деталь>'] .ts-controlgroup-marker`. Клик по названию детали и по `.ts-controlgroup-caption` не работает: такого элемента нет.
4. После раскрытия читать `[id*='<Деталь>'] .ts-controlgroup-container` — в тексте будут заголовки колонок и строки. Отдельная строка реестра — `[id*='<Деталь>'] .grid-listed-row` (до раскрытия её нет).
5. Что должно быть в детали, бери запросом к БД (`crm_db_query`) и сверяй с этим текстом — это быстрее, чем искать признаки в разметке.

Селекторы `.grid-empty`, `[data-item-marker='emptyGridMessage']` и `[data-item-marker='<Деталь>']` на детали не работают. Исходники платформы (`BaseDetailV2.js` и соседние) для такой проверки читать не нужно.

## ✅ Что проверять по типу правки
- Поле на карточке: подпись и значение есть в тексте карточки; «только для чтения» — по снимку или по признаку недоступности у элемента поля (найденного по подписи, см. «Как найти элемент»). Правила полей — `client-rules.md`.
- Кнопка: есть в тексте карточки; клик по видимому тексту. Сообщение (`showInformationDialog`) читается следующим `crm_browser_text`, закрывается кнопкой «ОК»; латинское «OK» не находится, нужна кириллица.
- Валидация: при сохранении `validate()` прекращает проверку на первом незаполненном обязательном поле, поэтому сообщения остальных полей не появятся. Для проверки своего сообщения бери запись, где все прочие обязательные поля заполнены. Сама схема валидации — `client-pages-edit.md`, «Атрибуты, методы, правила, валидация и кнопка на карточке».
- Сообщение валидации у поля «дата и время» встречается в тексте страницы дважды — по разу для даты и времени; это не два разных сообщения.
- Ошибка в клиентском коде: `crm_browser_console` — текст ошибки и файл; модуль с синтаксической ошибкой не загружается, страница пустая (`errors.md`).
- Ошибка `Cannot read properties of undefined (reading 'entitySchemaName')` в `SchemaBuilderV2.js` значит, что модуль схемы раздела или карточки не загрузился; первопричина — в соседней ошибке консоли, например `SyntaxError` в JS схемы.
- Какой код схемы реально загружен в браузер, видно по адресу из вкладки сети: `/configuration/<хеш><культура>/<Схема>.js` — открой его в `crm_browser_open` и прочитай `crm_browser_text`. По этому адресу русские строки показываются кракозябрами: текст читается как Latin-1. Проверяй по ключу строки или по латинской части кода, а не по русскому тексту.
- Вызов сервиса: `crm_browser_network` с `filter` по имени сервиса — адрес `POST /rest/<Сервис>/<Метод>`, код ответа и тело ошибки (✅ адрес без `/0/` на .NET 8). Формат и заголовки — `integration-api.md`, «Свой REST-сервис: адреса и ошибки». Если ошибку не удаётся воспроизвести, сначала сверь вызов в файле схемы с тем, что ушло в сеть: страница могла быть старой.
- Панель стадий кейса на карточке (контейнер `DcmActionsDashboardContainer`) — `dcm-edit.md`, «Новый кейс файлами».
- Проверка без изменения данных: новую запись открывай по адресу `…/add` и не сохраняй; поля на существующих записях не меняй.
- 🧪 `crm_browser_screenshot` сразу после `crm_browser_open` может вернуть `UnknownVizError` (дважды подряд, в том числе после паузы 10 с и открытия без `fresh`). Снимок получился позже, после чтения текста, консоли и сети. Не проверено, что именно помогает: если снимок не получился, сначала читай `crm_browser_text` и `crm_browser_console`, потом повтори снимок.
- ✅ подтверждено на реальных схемах проекта (30.10.2026): у открытой существующей записи вверху кнопка «Закрыть». После любой правки поля появляются «Сохранить»/«Отмена», а в заголовке вкладки префикс «Редактирование: ». Возврат значения к исходному не возвращает «Закрыть»: карточка не сравнивает с исходным значением. Признак годится для вопроса «были ли правки», но не «отличаются ли значения».
- ✅ подтверждено записью в CRM (30.10.2026): «Отмена» на новой карточке (`…/add`) после ввода значения закрыла её без вопроса «Сохранить изменения?» и вернула на предыдущую страницу; запись не создалась. Перевод окна на `about:blank` после «Отмены» не подтверждён.

## Шум в консоли (не ошибки правки)
- «Cannot enable prod mode after platform setup», «BPMConstructor Debug mode is OFF» — сообщения платформы, есть на любой странице.

## 🧪 Совмещённый режим раздела
Клик по записи в реестре во встроенной панели открыл отдельную карточку, а не карточку справа от реестра (наблюдение 13.10.2026; возможно, из-за ширины панели, не разбирались). Критерии про совмещённый режим проверяет пользователь — так и напиши в итоге, не трать на это действия.
