# Проверка реализации во встроенном браузере CRM

Инструменты `crm_browser_*` (включаются пользователем в настройках) открывают CRM в панели справа в окне приложения. Здесь — как проверять быстро, за несколько действий.

## ✅ Адреса страниц (13.10.2026)
- Все страницы — `/Nui/ViewModule.aspx` с частью после `#`; на стенде .NET Core без `/0/`.
- Раздел: `#SectionModuleV2/<Схема раздела>/`.
- Карточка записи: `#CardModuleV2/<Схема карточки>/edit/<Id>`; Id — запросом к БД, если доступ включён.
- Новая запись: `#CardModuleV2/<Схема карточки>/add` — для проверки без сохранения.
- При переходе только по части после `#` заголовок окна обновляется с задержкой — ориентируйся на текст страницы, а не на заголовок.

## ✅ Кэш после обновления
После «Обновить из файловой системы» правка клиентской схемы может не появиться: страница берётся из кэша браузера. Первое открытие после обновления инструментом сбрасывает кэш само; если обновлял пользователь — открой с `fresh: true`.

Открытие страницы инструментом всегда загружает её заново, даже если меняется только часть адреса после `#`: иначе в памяти остаются старые модули схем и после исправления видна прежняя ошибка (✅ 13.10.2026).

## ✅ Как найти элемент
- Сначала `crm_browser_text` без селектора: весь текст страницы — подписи полей, кнопки, значения. Обычно этого хватает.
- Элементы страницы помечены атрибутом `data-item-marker` с именем элемента из схемы: поле — `[data-item-marker="<Колонка>"]`, кнопка — по её имени из diff. Точечный текст или клик — по этому селектору. ⚠️ 13.10.2026: на новой карточке (`/add`) поле шапки, у которого `name` в diff совпадает с колонкой, по `[data-item-marker="<Колонка>"]` не нашлось, хотя подпись была в тексте страницы. Маркер поля не всегда равен имени — ищи поле по тексту подписи (`crm_browser_text` без селектора), а селектор используй, только если он уже сработал на этой странице.

### ✅ Проверить деталь на карточке (14.10.2026)

Порядок без перебора селекторов. `<Деталь>` — ключ детали из блока `details` карточки, он входит в `id` её контейнера.

1. Открыть карточку, перейти на вкладку: `crm_browser_click` по названию вкладки (параметр `text`).
2. Деталь по умолчанию свёрнута: `crm_browser_text` с селектором `[id*='<Деталь>'] .ts-controlgroup-container` вернёт только заголовки колонок, без строк. Это не ошибка и не пустая деталь.
3. Раскрыть деталь — клик по стрелке: `crm_browser_click` с селектором `[id*='<Деталь>'] .ts-controlgroup-marker`. Клик по названию детали и по `.ts-controlgroup-caption` не работает: такого элемента нет.
4. После раскрытия читать `[id*='<Деталь>'] .ts-controlgroup-container` — в тексте будут заголовки колонок и строки. Отдельная строка реестра — `[id*='<Деталь>'] .grid-listed-row` (до раскрытия её нет).
5. Что должно быть в детали, бери запросом к БД (`crm_db_query`) и сверяй с этим текстом — это быстрее, чем искать признаки в разметке.

Селекторы `.grid-empty`, `[data-item-marker='emptyGridMessage']` и `[data-item-marker='<Деталь>']` на детали не работают. Исходники платформы (`BaseDetailV2.js` и соседние) для такой проверки читать не нужно.

- Не перебирай CSS-классы наугад: если элемент не найден по тексту и `data-item-marker`, сделай один снимок и посмотри вёрстку.
- ✅ Поле-справочник на карточке (15.10.2026): список значений открывается кликом по `[id*='<Колонка>'] input`. Селектор `[data-item-marker='<Колонка>']` поле не нашёл, а `[data-item-marker*='<Колонка>']` попал в подпись.
- ✅ Подсказка у поля (15.10.2026): значок «?» нажался кликом по составному селектору `[data-item-marker="<Колонка>"] .info-button, [id*="<Колонка>"] [class*="tip"], [id*="<Колонка>"] [class*="info"]`; какой из вариантов совпал — не установлено. Текст подсказки после клика есть в полном тексте страницы (`crm_browser_text` без селектора).

## ✅ Что проверять по типу правки
- Поле на карточке: подпись и значение есть в тексте карточки; «только для чтения» — по снимку или по признаку недоступности у элемента с `data-item-marker` поля.
- Кнопка: есть в тексте карточки; клик по видимому тексту; сообщение (`showInformationDialog`) читается следующим `crm_browser_text`, закрывается кнопкой «ОК».
- Ошибка в клиентском коде: `crm_browser_console` — текст ошибки и файл; модуль с синтаксической ошибкой не загружается, страница пустая.
- Ошибка `Cannot read properties of undefined (reading 'entitySchemaName')` в `SchemaBuilderV2.js` значит, что модуль схемы раздела или карточки не загрузился; первопричина — в соседней ошибке консоли, например `SyntaxError` в JS схемы (✅ 13.10.2026).
- Какой код схемы реально загружен в браузер, видно по адресу из вкладки сети: `/configuration/<хеш><культура>/<Схема>.js` — открой его в `crm_browser_open` и прочитай `crm_browser_text` (✅ 13.10.2026).
- Вызов сервиса: `crm_browser_network` с `filter` по имени сервиса — адрес `POST /rest/<Сервис>/<Метод>`, код ответа и тело ошибки (✅ адрес без `/0/` на стенде .NET Core, 13.10.2026). Если ошибку не удаётся воспроизвести, сначала сверь вызов в файле схемы с тем, что ушло в сеть: страница могла быть старой.
- Проверка без изменения данных: новую запись открывай по адресу `…/add` и не сохраняй; поля на существующих записях не меняй.

## Шум в консоли (не ошибки правки)
- «Cannot enable prod mode after platform setup», «BPMConstructor Debug mode is OFF» — сообщения платформы, есть на любой странице.

## 🧪 Совмещённый режим раздела
Клик по записи в реестре во встроенной панели открыл отдельную карточку, а не карточку справа от реестра (13.10.2026, не разбирались почему — возможно, из-за ширины панели). Критерии про совмещённый режим проверяет пользователь — так и напиши в итоге, не трать на это действия.

⚠️ Первое чтение после перезапуска CRM (14.10.2026): сразу после компиляции с перезапуском `crm_browser_text` может вернуть пустой текст, а заголовок остаться «BPMSoft», хотя ошибок загрузки нет. Повтори чтение через несколько секунд — страница уже открыта. Не делай вывод «не работает» по первой пустой выдаче.

⚠️ Выбранное значение справочника (14.10.2026): уже выбранное значение поля-справочника в текст страницы не попадает, видно только на снимке; пункты открытого списка в тексте есть. Проверяя автозаполнение или фильтр справочника, открывай список (`crm_browser_click` по полю) и читай пункты, а текущее значение смотри снимком.

- ⚠️ **Проверка валидации** (14.10.2026): при сохранении `validate()` прекращает проверку на первом незаполненном обязательном поле, поэтому сообщения остальных полей не появятся. Для проверки своего сообщения бери запись, где все прочие обязательные поля заполнены.
- Флажок на карточке переключается кликом по `[id*='<Колонка>CheckBoxEdit']`. Клик по тексту подписи и по `[data-item-marker="<Колонка>"]` флажок не переключает. Кнопка окна сообщения — `text: "ОК"` кириллицей, латинское «OK» не находится (14.10.2026).
- Сообщение валидации у поля «дата и время» встречается в тексте страницы дважды — по разу для даты и времени; это не два разных сообщения (14.10.2026).
- Модуль схемы, открытый по адресу `/configuration/<хеш><культура>/<Схема>.js`, показывает русские строки кракозябрами: текст читается как Latin-1. Проверяй по ключу строки или по латинской части кода, а не по русскому тексту (14.10.2026).
