# Вебхуки (WebhookSchemaManager) — рецепты

Коды метаданных, публикация и аутентификация — `webhook.md`.

## ✅ Новый вебхук файлами (подтверждено записью в CRM 25.10.2026)
Образец — вебхук проекта (grep `"ManagerName": "WebhookSchemaManager"` в `Pkg/*/Schemas/*/descriptor.json`). Если его нет — шаблон ниже: выгрузка дизайнера, метод POST добавляет контакт с ФИО из поля `name`.

1. `Schemas/<Имя>/descriptor.json`:
```json
{
  "Descriptor": {
    "UId": "<UId схемы>",
    "Name": "<Имя>",
    "ModifiedOnUtc": "\/Date(<date +%s000>)\/",
    "ManagerName": "WebhookSchemaManager",
    "Caption": "<Заголовок>",
    "DependsOn": []
  }
}
```
2. `Schemas/<Имя>/properties.json`:

4. `Resources/<Имя>.Webhook/resource.ru-RU.xml` и `resource.en-US.xml` (обе локали, формат — `metadata-editing.md`): ключи `Caption`, `WebhookMethods.Method1.Caption`, `WebhookMethods.Method1.Request.Parameters.name.Caption`, `WebhookMethods.Method1.ActionRules.ActionRule1.Caption`.
5. «Обновить из файловой системы», затем перезапуск приложения: при старте публикуются методы с `IR9: true`. Без перезапуска — `POST <CRM>/rest/WebhookService/Publish` (`webhook.md`).
6. Проверка: вход под пользователем из `IZ3`, затем `POST <CRM>/webhook/<UId схемы>/<endpoint>` с телом `{"name": "<значение>"}` и его cookie — ответ 200, запись в БД. Без cookie — 403.

## Изменить и удалить
- 🧪 Изменить метод: правка `metadata.json`, новый `ModifiedOnUtc`, обновление и перезапуск (маршрут строится при публикации).
- ✅ Удалить (25.10.2026): снять публикацию (`POST <CRM>/rest/WebhookService/Unpublish` — адрес сразу отвечает 404), удалить папки `Schemas/<Имя>/` и `Resources/<Имя>.Webhook/` по порядку из `metadata-editing.md`, «Удаление схемы», «Обновить из файловой системы» — схема удаляется из БД («Удалено»).
