# Данные пакета (Data) — подтверждённая модель metadata

## ⚠️ ПОДТВЕРЖДЕНО: структура данных и формат metadata для Data-схем

Собрано на реальных наборах данных проекта: справочник с локализацией и без неё. Дополнительно подтверждено перечислением платформы `SysPackageSchemaDataInstallType`.

## Общее

- **Назначение**: данные (обычно строки справочников/лукапов), которые переносятся из конфигурации между стендами при установке пакета — **НЕ структура схемы**, а **КОНКРЕТНЫЕ ЗНАЧЕНИЯ строк таблицы БД**, зафиксированные в файлах пакета.
- **Структура папки**: `Pkg/<Пакет>/Data/<Имя>/`
  - `descriptor.json` — метаданные пакета данных + список колонок
  - `data.json` — сами данные (строки)
  - `filter.json` — существует у каждого примера, но во всех проверенных примерах пустой (0 байт или только перенос строки); назначение/структура не установлены
  - `Localization/` — **опциональная подпапка**, появляется ТОЛЬКО если среди колонок данных есть локализуемые текстовые колонки (например `Name`/`Description`); содержит файлы `data.<culture>.json`
  - **НЕТ папки `Resources/`** — Data-схемы используют отдельный механизм локализации через подпапку `Localization/` внутри самой Data-схемы, а не через ресурсные XML-файлы в `Resources/` (как Entity/Process/ClientUnitSchema). Подтверждено сравнением двух примеров: `AccountOwnership` (есть текстовые локализуемые колонки, есть подпапка `Localization/` с тремя файлами `data.ru-RU.json`/`data.en-US.json`/`data.es-ES.json`) vs `Lookup_NotificationTemplate` (нет локализуемых колонок, папки `Localization/` нет).

## `descriptor.json`

Структура (ключ `"Descriptor"`, как у большинства типов, в отличие от SqlScript):

```json
{
  "Descriptor": {
    "UId": "fb5074eb-a2c7-b5c2-a075-6ee5cb60772e",
    "Name": "AccountOwnership",
    "ModifiedOnUtc": "\/Date(1790154047000)\/",
    "InstallType": 0,
    "Schema": {
      "UId": "ce243c2c-b7d3-4dc4-b474-ab24c677801b",
      "Name": "AccountOwnership"
    },
    "Columns": [
      {
        "ColumnUId": "9e53fd7c-dde4-4502-a64c-b9e34148108b",
        "IsForceUpdate": true,
        "IsKey": false,
        "ColumnName": "Description",
        "DataTypeValueUId": "ddb3a1ee-07e8-4d62-b7a9-d0e618b00fbd"
      },
      {
        "ColumnUId": "ae0e45ca-c495-4fe7-a39d-3ab7278e1617",
        "IsForceUpdate": false,
        "IsKey": true,
        "ColumnName": "Id",
        "DataTypeValueUId": "23018567-a13c-4320-8687-fd6f9e3699bd"
      }
    ]
  }
}
```

### Поля:

- **`Schema.UId` / `Schema.Name`** — UId и имя **ЦЕЛЕВОГО объекта** (Entity-схемы), **В КОТОРУЮ загружаются эти данные** (например `AccountOwnership` — реальный справочник; `BaseLookup` — универсальный справочник BPMSoft).
- **`Columns`** — массив, **ОПИСЫВАЕТ ШАБЛОН данных** (какие колонки участвуют):
  - `ColumnUId` — совпадает с UId колонки целевого объекта (из metadata.json целевой Entity-схемы, поле `D2` — см. `entity.md`)
  - `ColumnName` — имя колонки (например `"Id"`, `"Name"`, `"Description"`)
  - `DataTypeValueUId` — GUID типа данных (тот же каталог, что `S2` у колонок объекта в metadata.json)
  - **`IsKey`** — `true` ТОЛЬКО у колонки `Id` (подтверждено на обоих примерах); используется для поиска/сопоставления существующей записи при повторной установке/обновлении пакета
  - **`IsForceUpdate`** — булево; управляет тем, обновляется ли существующая запись при повторном применении данных:
    - `false` — у `Id` (ключ никогда не перезаписывается, только используется для поиска)
    - `true` — у всех остальных колонок (значение ВСЕГДА перезаписывается при повторной установке)
- **`InstallType`** — **ПОЛНОСТЬЮ ПОДТВЕРЖДЕНО** (enum платформы `BPMSoft.Common.SysPackageSchemaDataInstallType`), это enum с **ТРЁМ значениями** (НЕ путать с 4-значным enum SQL-скриптов): ✅ Проверено 05.10.2026: при «Обновить из файловой системы» строки загружает только `0`; наборы с `1` и `2` строк не добавляют.
  - `0` = **Install** (устанавливается при КАЖДОЙ установке пакета — самый частый случай — почти все наборы)
  - `1` = **FirstInstall** (устанавливается ТОЛЬКО при первой установке пакета, не переустанавливается повторно; вероятно для начальных seed-данных, которые пользователь мог сам изменить после первой установки — редкий случай, 2 файла)
  - `2` = **Update** (устанавливается/обновляется при ОБНОВЛЕНИИ пакета на более новую версию — 13 файлов)
- **`ModifiedOnUtc`** — время последнего изменения в формате `"\/Date(<миллисекунды_с_эпохи_Unix>)\/"` (см. `metadata-editing.md`); **ОБЯЗАТЕЛЬНО** должно обновляться на реальный текущий момент при создании или изменении набора данных

## `data.json`

Структура:

```json
{
  "PackageData": [
    {
      "Row": [
        { "SchemaColumnUId": "ae0e45ca-c495-4fe7-a39d-3ab7278e1617", "Value": "04992e36-958e-476a-8824-06c7192c6eed" },
        { "SchemaColumnUId": "bd9ec46e-6371-466e-87ec-1adf995e47c7", "Value": "null", "DisplayValue": "" },
        { "SchemaColumnUId": "e86949e7-1ee6-4277-8e20-982a9c673fdb", "Value": false }
      ]
    }
  ]
}
```

### Поля:

- **`PackageData`** — массив; одна запись `Row` на каждую строку таблицы данных, которая должна быть установлена
- **`Row`** — массив пар `{SchemaColumnUId, Value}`:
  - `SchemaColumnUId` — соответствует `ColumnUId` из `Columns` в `descriptor.json`
  - `Value` — значение колонки:
    - Для GUID/чисел/строк — литерал (например `"04992e36-958e-476a-8824-06c7192c6eed"`)
    - Для пустого lookup — строка `"null"` (буквально, не JSON `null`)
    - Для булевых — `true`/`false` (JSON-булево, не строка)
  - **`DisplayValue`** — ✅ **ОБЯЗАТЕЛЬНО у каждой lookup-колонки** (в `descriptor.json` у колонки `"DataTypeValueUId": "b295071f-7ea9-4e62-8d1a-919bf3732ff2"`, а также у колонок-изображений): человекочитаемое значение выбранной записи (например `"Россия"`), для пустой ссылки или записи без отображаемого значения — строка `"null"` или `""` (как в образце). У остальных типов поля нет. **Подтверждено ошибкой установки**: без `DisplayValue` у lookup-ячейки «Обновить из файловой системы» пишет по набору «Добавлено/Ошибка: При попытке чтения свойства "DisplayValue" получено значение ""» (28.09.2026, наборы регистрации раздела `TestColumns`). ~~Ранее считалось опциональным~~ — опровергнуто.

## `Localization/data.<culture>.json`

### Когда появляется

Подпапка `Localization/` появляется **ТОЛЬКО если среди колонок данных есть локализуемые текстовые колонки** (например `Name`/`Description` как в `AccountOwnership`). Если все колонки нелокализуемые (как в `Lookup_NotificationTemplate`), папку `Localization/` создавать не нужно.

### Структура

Один отдельный файл на каждую культуру (например `data.ru-RU.json`, `data.en-US.json`, `data.es-ES.json`):

```json
{
  "PackageData": [
    {
      "Row": [
        { "SchemaColumnUId": "ae0e45ca-c495-4fe7-a39d-3ab7278e1617", "ColumnName": "Id", "Value": "04992e36-958e-476a-8824-06c7192c6eed" },
        { "SchemaColumnUId": "736c30a7-c0ec-4fa9-b034-2552b319b633", "ColumnName": "Name", "Value": "ЮЛ" },
        { "SchemaColumnUId": "9e53fd7c-dde4-4502-a64c-b9e34148108b", "ColumnName": "Description", "Value": "" }
      ]
    }
  ]
}
```

### Отличия от основного `data.json`:

1. Содержит ТОЛЬКО `Id` (ключ для сопоставления строки с основными данными) + ЛОКАЛИЗУЕМЫЕ текстовые колонки (`Name`/`Description` в примере) — **НЕ включает** нелокализуемые колонки типа `Country`/`RecordInactive`, которые остаются только в основном `data.json`
2. КАЖДАЯ строка `Row` дополнительно содержит поле `"ColumnName"` рядом с `SchemaColumnUId` (в основном `data.json` поля `ColumnName` НЕТ, только `SchemaColumnUId`+`Value`)
3. Один отдельный файл на каждую культуру — сколько культур поддерживается в пакете, столько файлов `data.<culture>.json` должно быть в подпапке `Localization/`

## Не проверено пока

- **Точное назначение/структура `filter.json`** — существует во всех примерах, но пустой (0 байт или только перенос строки); практическое применение и структура при заполнении не установлены
- ✅ `IsForceUpdate` (05.10.2026, `Lookup_TestSrcEntity`): `true` — значение из файла перезаписывает БД у существующей записи; `false` — значение пишется только при вставке новой записи, у существующей не меняется.
- **Наличие других полей в `descriptor.json` или `data.json`** — на двух проверенных примерах структура полей стабильна; возможны другие поля в более сложных или специализированных Data-схемах
