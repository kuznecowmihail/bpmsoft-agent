# Данные в серверном коде (C#): Entity, ESQ, запросы, транзакции

Проверенные приёмы работы с данными из схем исходного кода, слушателей, своих действий и заданий-сценариев процесса. `using` и поиск API — `platform-api.md`; права и работа в обход прав — `rights.md`, «Права в серверном коде»; системные настройки и кеши — `platform-api.md`.

## Запись через `Entity`
- ✅ Создать запись: `userConnection.EntitySchemaManager.GetInstanceByName("<Объект>")` → `schema.CreateEntity(userConnection)` → `SetDefColumnValues()` → `SetColumnValue(...)` → `Save(false)`. Рецепт — `server-events-edit.md`, «Создать связанную запись после вставки».
- ✅ (21.10.2026): сигнатура `Entity.Save(bool validateRequired = true, bool setColumnDefValue = true)`; есть ещё `Save(EntitySaveConfig)` (свойства `ValidateRequired`, `SetColumnDefValue`, `SetForceBackgroundMode`). `Save(false)` в рецептах — сохранить без проверки обязательных колонок; значения справочных колонок по умолчанию при этом подставляются. С проверкой обязательных — `Save()`. В коде платформы встречаются именованные вызовы `Save(validateRequired: false)` и `Save(setColumnDefValue: false)` — так понятнее, пиши так же. Опровергнуто: прежняя запись «первый параметр — `setColumnDefValue`» — её вывели из порядка тегов `<param>` в XML-документации, а он обратный порядку аргументов.
- ✅ Запись через `Entity` (21.10.2026): `entity.FetchFromDB(id)` → `bool` (перегрузки по колонке `FetchFromDB("<Колонка>", value)` и по словарю условий); `entity.Delete()` → `bool`, с событиями объекта; `entity.ExistInDB(id)` и `ExistInDB("<Колонка>", value)`; `esq.GetEntity(uc, id)` для несуществующего Id возвращает `null`.
- ✅ Новая ли запись (в `OnSaving`): `entity.StoringState == StoringObjectState.New`.
- ✅ Старое значение колонки после сохранения (07.10.2026, тот же слушатель): в `OnUpdated(object sender, EntityAfterEventArgs e)` — `e.ModifiedColumnValues`, коллекция `EntityColumnValue` (`Name`, `OldValue`); колонки нет в коллекции — значение не менялось. Для справочной колонки имя — с суффиксом `Id` (`x.Name == "<Колонка>Id"`; ✅ на реальных схемах проекта и в `Autogenerated/Src`, журнал смены статуса заработал 08.10.2026); `OldValue` приводи через `is Guid`. `ModifiedColumnValues` в XML-документации нет — найден по примерам в `Pkg` (проектный базовый слушатель). Вариант из `Autogenerated/Src` — `entity.GetTypedOldColumnValue<T>("<Колонка>")` в `OnSaving` — ✅ (08.10.2026, проверка изменения срока).

## ESQ (`EntitySchemaQuery`)
- ✅ Выборка записей `EntitySchemaQuery` (07.10.2026, `TestTicketStatsService`): `new EntitySchemaQuery(UserConnection.EntitySchemaManager, "<Объект>") { UseAdminRights = false }`; колонка справочника через точку — `var column = esq.AddColumn("TestPriority.Name"); column.Name = "TestPriorityName";`, значение — `entity.GetTypedColumnValue<string>(column.Name)`; фильтры — `esq.CreateFilterWithParameters(FilterComparisonType.Equal, "<Колонка>", value)`, `esq.CreateIsNullFilter("<Колонка>")`, `esq.CreateIsNotNullFilter("<Колонка>")`; группа «ИЛИ» — `new EntitySchemaQueryFilterCollection(esq, LogicalOperationStrict.Or) { <фильтр>, <фильтр> }`, затем `esq.Filters.Add(...)`; сортировка — `esq.AddColumn("<Колонка>").OrderByDesc(<позиция сортировки 1, 2…>)`; первые N записей — `esq.RowCount = N`; результат — `esq.GetEntityCollection(UserConnection)`. Агрегация (`AggregationTypeStrict`) не проверена: количество посчитано в памяти.
- ✅ ESQ «есть / нет связанных записей» (21.10.2026): `esq.Filters.Add(esq.CreateExistsFilter("[<Деталь>:<Колонка связи>].Id"))` и `esq.CreateNotExistsFilter(…)`.
- ✅ Группировка в запросе (подтверждено в CRM, 09.10.2026): колонки группировки — обычные `esq.AddColumn("<Справочник>.Id")`, `esq.AddColumn("<Справочник>.Name")`; агрегаты — `esq.AddColumn(esq.CreateAggregationFunction(AggregationTypeStrict.Count, "Id"))` и `esq.AddColumn(esq.CreateAggregationFunction(AggregationTypeStrict.Sum, "<Колонка>"))`; `esq.PrimaryQueryColumn.IsAlwaysSelect = false`; сортировка — `column.OrderByDesc(<позиция>)`; чтение — `GetEntityCollection`. ❌ `AddColumn("Id")` с `SummaryType = AggregationType.Count` рядом с `<Справочник>.Id` отдаёт в агрегат Id справочника — `GetTypedColumnValue<int>` падает с `FormatException` (09.10.2026).
- ✅ ESQ в задании-сценарии процесса (11.10.2026): фильтры `FilterComparisonType.GreaterOrEqual`/`Less` по дате и времени, группа «ИЛИ» (`LogicalOperationStrict.Or`) из `esq.CreateIsNullFilter("<Колонка>")` и `Equal ""` для пустого текста, колонка `"Responsible.Id"` под своим именем — скомпилировалось и отработало; хватило стандартных `using` процесса.
- Регистр строк на PostgreSQL: фильтр ESQ `FilterComparisonType.Equal` по строке **не учитывает** регистр (`"консультация"` находит «Консультация»); `Select … .Where("<Колонка>").IsEqual(Column.Parameter("консультация"))` и SQL-скрипт — **учитывают**.

## Запросы `Select`, `Insert`, `Update`, `Delete` (`BPMSoft.Core.DB`)
- Запросы работают напрямую с таблицей: слушатели объекта, журнал изменений и права по записям не срабатывают — `rights.md`, «Права в серверном коде».
- ✅ Прочитать одно значение из БД: `new Select(userConnection).Column("<Колонка>").From("<Объект>").Where("Id").IsEqual(Column.Parameter(id)) as Select`, затем `ExecuteScalar<T>()`.
- ✅ `Select` (21.10.2026): `new Select(uc).Distinct().Column("<Таблица>", "<Колонка>").From("<Таблица>").InnerJoin("<Таблица2>").On("<Таблица2>", "<Колонка связи>").IsEqual("<Таблица>", "Id") as Select`; количество — `.Column(Func.Count("Id"))` и `ExecuteScalar<int>()`; условие-подзапрос — `.Where().Exists(<Select>)` и `.Where().Not().Exists(<Select>)`, связь подзапроса с внешней таблицей — `.Where("<Таблица2>", "<Колонка связи>").IsEqual("<Таблица>", "Id")`; список значений — `.Where("Id").In(Column.Parameters(<List<Guid>>))`; первые N — `.Top(N)`; сортировка — `.OrderByDesc("<Колонка>")`.
- ✅ Вставка запросом, без событий объекта (07.10.2026, `TestTicketEventListener` → `TestTicketPriorityLog`): `new Insert(userConnection).Into("<Объект>").Set("<Колонка>Id", Column.Parameter(value))…`, затем `Execute()`. `Id` и `CreatedOn` можно не задавать — заполнились сами; `CreatedBy`/`ModifiedBy` при вставке запросом не проверялись. Пустое значение справочника не передавай — пропусти его `Set` (так сделано и проверено).
- ✅ Изменить запись без событий объекта: `new Update(userConnection, "<Объект>").Set("<Колонка>", Column.Parameter(value)).Where("Id").IsEqual(Column.Parameter(id)) as Update`, затем `Execute()` (`entity-events-edit.md`, скрипт «После сохранения»).
- ✅ Удаление запросом, без событий объекта (21.10.2026): `new Delete(uc).From("<Таблица>").Where("<Колонка>").IsEqual(Column.Parameter(value)) as Delete`, затем `Execute()` — возвращает число удалённых строк.

## Транзакции и чтение строк
- ✅ Транзакция (подтверждено записью в CRM, 21.10.2026): `using (DBExecutor executor = UserConnection.EnsureDBConnection()) { executor.StartTransaction(); …; executor.CommitTransaction(); }`, при ошибке — `executor.RollbackTransaction()`. Запросы внутри транзакции выполняй с этим executor: `query.Execute(executor)`, `select.ExecuteScalar<T>(executor)`, `select.ExecuteReader(executor)`. `Entity.Save()` между `StartTransaction` и `RollbackTransaction` откатывается вместе с транзакцией. Есть `StartTransaction(IsolationLevel)`.
- ✅ Чтение строк (21.10.2026): `using (DBExecutor executor = UserConnection.EnsureDBConnection()) { using (IDataReader reader = select.ExecuteReader(executor)) { while (reader.Read()) { var value = reader.GetColumnValue<string>("<Колонка>"); } } }`.
