# Объекты: колонки и индексы — рецепты

Добавить, изменить и удалить колонку, колонки любых типов и свойств, колонка активности на свой объект, индексы. Создание объекта, замещение и удаление — в `entity-edit.md`; коды полей колонки `D2`/`E*` — в `entity.md`. После записи объекта вызови `pkg_lint` и исправь все строки ОШИБКА.

## ✅ Подтверждено экспериментом: добавить простую колонку (без lookup)
1. В `Schemas/<Объект>/metadata.json` добавить перед завершающим `~ MetaData.Schema.D2 [...]`:
```
+ MetaData.Schema.D2 {
  "UId": "<новый GUID>",
  "A2": "<ИмяКолонки>",
  "A3": "<UId объекта>",
  "A4": "<UId объекта>",
  "A5": "<любой существующий A5 из этого же файла>",
  "S2": "<GUID типа данных, см. таблицу в crm-db.md>"
}
```
2. Дописать `<новый GUID>` в конец списка `~ MetaData.Schema.D2 [...]`.
3. В `Resources/<Объект>.Entity/resource.ru-RU.xml` и `resource.en-US.xml` добавить `<Item Name="Columns.<ИмяКолонки>.Caption" Value="<Подпись>" />` (ресурсы обязательны в обоих языках, не только ru-RU).
4. Открыть объект в Designer и проверить, что колонка отображается без ошибок.

**Подтверждено на практике**: колонка `ManualWrite` (простой текст) успешно создана этим способом на тестовом объекте `TestEntity`, включая подпись — см. `entity.md`.

## ✅ Колонка активности на свой объект: связь в `EntityConnection`

**Подтверждено в CRM.** Справочная колонка `Activity` → `<Объект>` (замещение `Activity`) сама по себе не делает активности связанными с записью. Пока колонки нет в `EntityConnection`, карточка `<Объект>` пишет в консоль `Column<Колонка> was not found in EntityCollection for Activity schema` (поиск колонки в `DcmPageMixin.js`), а деталь «Email» на карточке не раскрывается. После регистрации колонки предупреждение уходит, деталь показывает письма записи или «Нет данных». Та же регистрация нужна, чтобы «Выполнить задачу» заполнял колонку (см. `process-activity-edit.md`, «Связь задачи с записью»).

Регистрация — SQL-скрипт в пакете (`sql-script-edit.md`), повторный запуск не добавляет вторую строку. `c449d832-a4cc-4b01-b9d5-8a12c42a9f89` — UId объекта `Activity` (платформа); `<UId колонки>` — `UId` колонки в `metadata.json` замещения `Activity`. Пример для PostgreSQL:
```sql
INSERT INTO public."EntityConnection" ("SysEntitySchemaUId", "ColumnUId", "Position")
SELECT 'c449d832-a4cc-4b01-b9d5-8a12c42a9f89'::uuid, '<UId колонки>'::uuid,
	COALESCE((SELECT MAX("Position") + 1 FROM public."EntityConnection"
		WHERE "SysEntitySchemaUId" = 'c449d832-a4cc-4b01-b9d5-8a12c42a9f89'::uuid), 0)
WHERE NOT EXISTS (SELECT 1 FROM public."EntityConnection"
	WHERE "SysEntitySchemaUId" = 'c449d832-a4cc-4b01-b9d5-8a12c42a9f89'::uuid
		AND "ColumnUId" = '<UId колонки>'::uuid);
```

## ✅ Добавить индекс (`D6`)
**Подтверждено**: два индекса, написанные вручную, показались в Designer корректно. Блоки индексов — после закрывающего `~ MetaData.Schema.D2 [...]`, затем закрывающий список индексов:
```
+ MetaData.Schema.D6 {
  "UId": "<GUID индекса>",
  "A2": "IX_<Объект>_<Колонка>_Unique",
  "A3": "<UId объекта>",
  "A4": "<UId объекта>",
  "A5": "<Id пакета>",
  "F1": false,
  "F2": true,
  "F4": [
    {
      "UId": "<GUID колонки индекса>",
      "A2": "IndexColumn_<Колонка>",
      "A3": "<UId объекта>",
      "A4": "<UId объекта>",
      "A5": "<Id пакета>",
      "G1": "<UId колонки из D2>"
    }
  ]
}
~ MetaData.Schema.D6 ["<GUID индекса>"]
```
`F2: true` — «Уникальный» (для обычного индекса не пиши поле). Колонок в `F4` может быть несколько, их порядок = порядок в индексе. `"G2": 1` на колонке `F4` — «По убыванию» (без поля — «По возрастанию»). Поменять сортировку у существующего индекса: `+ MetaData.Schema.D6.["<UId индекса>"].F4.["<UId колонки индекса>"].G2 1` (✅ проверено).

## ✅ Изменить или удалить существующую колонку
**Подтверждено**: все правки ниже после «Обновить из файловой системы» показались в Designer корректно.
- **Подпись** — только в `resource.ru-RU.xml` и `resource.en-US.xml` (`Columns.<Колонка>.Caption`), `metadata.json` не трогать.
- **Свойство колонки** — строкой журнала в конец `metadata.json` (так пишет Designer; последняя запись побеждает):
  - сменить тип: `= MetaData.Schema.D2.["<UId колонки>"].S2 "<GUID нового типа>"` (проверено: строка неограниченной длины → строка 250, `ddb3a1ee-07e8-4d62-b7a9-d0e618b00fbd`);
  - сделать обязательной: `+ MetaData.Schema.D2.["<UId колонки>"].E2 1`;
  - снять обязательность (убрать любое свойство): `- MetaData.Schema.D2.["<UId колонки>"].E2`.
  Путь в квадратных скобках работает и для вложенных элементов: `D6.["<UId индекса>"].F4.["<UId колонки индекса>"].G2`.
- **Удалить колонку, созданную этим пакетом**: убрать её блок `+ MetaData.Schema.D2 {...}`, убрать её UId из закрывающего списка `~ MetaData.Schema.D2 [...]`, убрать её подписи из обоих `resource.*.xml`, и проверить, что UId колонки больше нигде не встречается (индексы `F4.G1`, `D3`/`D4`/`D11`–`D14`/`D21`, код скриптов по имени). Строки `- MetaData.Schema.D2.["<UId>"]` в проекте не встречается ни разу — такой способ не нужен.
- ✅ Колонка выведена на карточку: ещё удали её элемент `insert` из `diff` карточки и сдвинь `index` у соседних элементов того же контейнера; затем «Обновить из файловой системы» и компиляция.
- ❌ Физическая колонка после удаления или смены типа не остаётся прежней до отдельной актуализации структуры БД: «Обновить из файловой системы» сразу удаляет колонку из таблицы и меняет её тип.
- ⚠️ ✅ Смена типа колонки с данными теряет несовместимые значения без ошибки (подтверждено записью в CRM): строка 50 со значением `abc` после смены типа на «Целое число» и обновления стала `0`, в `PackagesSynchronization.log` нет ни ошибки, ни предупреждения. Перед сменой типа колонки, где есть данные, предупреди пользователя; если данные нужны — новая колонка, перенос значений SQL-скриптом, затем удаление старой колонки.
- Перед правками — `ModifiedOnUtc` в `descriptor.json` (см. `metadata-editing.md`).

## Значение по умолчанию у унаследованной колонки в замещении

✅ Подтверждено записью в CRM. Колонка объявлена в родителе (например, справочная колонка базового объекта), в замещении её ещё нет. Допиши в конец `metadata.json` замещения две строки:

    = MetaData.Schema.D2.["<UId колонки>"].A4 "<UId замещения>"
    + MetaData.Schema.D2.["<UId колонки>"].E12 {"FB1":1,"FB2":"<Id записи справочника>"}

После «Обновить из файловой системы» и компиляции новая карточка показывает значение, а `InsertQuery` без этой колонки сохраняет запись со значением по умолчанию. Если колонка в замещении уже переопределена (в файле есть строки `D2.["<UId колонки>"]…`), хватило одной строки `+ …E12 …` (подтверждено записью в CRM). Нужна ли строка `A4`, когда колонки в замещении ещё нет, отдельно не проверено — пиши обе. Значение по умолчанию срабатывает и у обязательной колонки (`E2: 1`), когда запись создают без неё: см. `server-events-edit.md`.
