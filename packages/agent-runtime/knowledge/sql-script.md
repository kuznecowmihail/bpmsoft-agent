# SQL-скрипт пакета (SqlScript) — модель metadata

Статусы: ✅ подтверждено записью или запросом, 🧪 не проверено. Рецепты создания и правки — `sql-script-edit.md`.

## Общее
- `descriptor.json` — корневой ключ `"SqlScript"`, а не `"Descriptor"`. Единственный тип схем с таким исключением.
- Папка схемы содержит ТОЛЬКО `descriptor.json` и `<Name>.sql`. Нет `properties.json`, `metadata.json`, `resources.json`. Подтверждено сканированием SQL-скриптов проекта: ни у одного нет папки ресурсов.
- Тип схемы определяется папкой `SqlScripts/` пакета, а не полем в `descriptor.json`.
- Ресурсов и локализации нет: скрипт не имеет `Caption` и UI, правило двух языков на него не распространяется.

## descriptor.json

```json
{
  "SqlScript": {
    "UId": "<UId скрипта>",
    "Name": "<Имя скрипта>",
    "DBEngineType": 2,
    "InstallType": 1,
    "ModifiedOnUtc": "\/Date(<ModifiedOnUtc>)\/",
    "DependsOn": []
  }
}
```

Поля:
- `UId` — GUID скрипта.
- `Name` — совпадает с именем папки `SqlScripts/<Name>/`; только латиница, цифры и подчёркивание.
- ✅ `DBEngineType` — enum `BPMSoft.Common.DBEngineType`: `0` MSSql, `1` Oracle, `2` PostgreSql. `2` — самый частый на PostgreSQL-стендах. `0` встречается редко, вероятно это старые MSSql-скрипты.
- ✅ `InstallType` — enum `BPMSoft.Core.Packages.SysPackageSqlScriptInstallType`:
  - `0` — `BeforePackage`: до установки пакета (редко);
  - `1` — `AfterPackage`: после установки пакета (самый частый);
  - `2` — `AfterSchemaData`: после установки данных схемы пакета (`data.md`, «Data или SQL-скрипт»; ✅ подтверждено записью в CRM (29.10.2026): скрипт перезаписал значение, которое набор поставил в том же обновлении);
  - `3` — `UninstallApp`: при удалении приложения или пакета (очень редко).
- `ModifiedOnUtc` — ОБЯЗАТЕЛЬНО текущий момент в формате `"\/Date(<миллисекунды>)\/"` (`date +%s000`). Захардкоженное значение рассинхронизирует историю. Меняется при каждом изменении, по которому скрипт должен выполниться заново (см. «Выполнение»).
- ✅ `DependsOn` — скрипты, которые должны выполниться раньше этого (подтверждено записью в CRM, 21.10.2026). Элемент массива — `{ "UId": "<UId скрипта>", "Name": "<имя скрипта>" }`. После «Обновить из файловой системы» связь записывается в `SysSqlScriptDependency` (`SysSqlScriptId` → `DependOnSqlScriptId`). Скрипт из `DependsOn` выполнился раньше зависящего, даже если по алфавиту он последний. Удаление скрипта из пакета удаляет и связь.

Полей `Caption` и `ManagerName` у SQL-скрипта нет.

## .sql-файл
- Содержит ТОЛЬКО SQL-команды (`SELECT`, `UPDATE`, `INSERT`, `DELETE`, `CREATE`, `DROP`, `ALTER`…), без JSON-обёртки. Может быть однострочным или многострочным.
- Выполняется движком из `DBEngineType` как есть. Для PostgreSql (`2`) допустимы PL/pgSQL-блоки `DO $$ ... END $$ LANGUAGE plpgsql`. Для MSSql и Oracle — их диалект.
- Скрипт работает в контексте БД пакета, видит все таблицы и может создавать таблицы, индексы, функции и триггеры.
- Пример (PostgreSql), простой `UPDATE` с подзапросом:
  ```sql
  UPDATE "AdminUnitFeatureState"
  SET "FeatureState" = 1
  WHERE "FeatureId" = (
      SELECT "Id" from "Feature" WHERE "Code" = '<КодФункции>'
  )
  ```

  - при следующих обновлениях без изменений — нет (после двух таких обновлений строка одна);
  - после смены только `ModifiedOnUtc` в `descriptor.json` (текст `.sql` тот же) — выполнился снова.
- ✅ 06.10.2026: смена текста `.sql` вместе с `ModifiedOnUtc` — скрипт выполнился заново с новым текстом.

- ✅ подтверждено записью в CRM (29.10.2026): скрипт пакета выполняется одной транзакцией. Если последний оператор упал (`DROP TABLE` заблокирован внешним ключом), предыдущие `DELETE` того же скрипта откатываются. «Обновить из файловой системы» показывает скрипт как «Добавлено/Ошибка» с текстом PostgreSQL (`2BP01`, `errors.md`). `SysPackageSqlScript.LastError` при этом пустой, в том числе после последующего успешного запуска.
- Проверка выполнения — `crm-db.md`, «Данные из БД CRM»: `SysPackageSqlScript` (`NeedInstall = false` у выполненного).

## Ресурсы
✅ Ни у одного скрипта проекта нет папки `Resources/<Name>.SqlScript/`. Логика: SQL-скрипт — техническое, нелокализуемое содержимое, как индексы и функции БД. Поэтому файлы `resource.ru-RU.xml` и `resource.en-US.xml` для скрипта не создаются, в отличие от Entity, Process, SourceCode и ClientUnit.

## 🧪 Не проверено пока
- Может ли одна папка `SqlScripts/<Name>/` содержать несколько `.sql`-файлов. На примерах встречается только одна пара.
- Поведение `InstallType: 0` (BeforePackage). Редко встречается, точный механизм не подтверждён.
