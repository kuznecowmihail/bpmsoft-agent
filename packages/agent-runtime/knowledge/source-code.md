# Исходный код (SourceCodeSchemaManager) — подтверждённая модель metadata

## Структура и формат metadata.json для SourceCode-схем

Собрано на реальных схемах исходного кода проекта (веб-сервис и слушатель событий) — структура одинакова.

## Общее
- `descriptor.json` → `ManagerName: "SourceCodeSchemaManager"`. Поля `Parent` нет: у SourceCode-схем нет наследования, это именованный кусок кода, зарегистрированный в системе. `Caption` обычно совпадает с `Name` (человекочитаемое имя не отличается от технического кода).
- Папка схемы: `descriptor.json`, `properties.json`, `metadata.json`, `<Name>.cs`. В отличие от Entity, где `.cs` пустой, `.cs`-файл содержит реальный C#-код целиком (полный класс с namespace, using и атрибутами). Похож на ClientUnitSchema, где код тоже лежит отдельным файлом (`.js`).
- `properties.json` — `{"Properties": {"CreatedInVersion": "<версия>"}}` (обёртка `Properties` есть у всех схем проекта).
- `metadata.json` — плоский JSON-снимок (Формат B), а не построчный diff-журнал (`=`/`+`/`~`/`-`). Весь файл — один JSON-объект `{"MetaData": {"Schema": {...}}}` без построчных операций сохранения. Это отличает SourceCode от большинства Entity-схем и много Process-схем, но совпадает с форматом, встречающимся у некоторых Process-примеров (см. примечание в `metadata-editing.md`) и у ClientUnitSchema (Формат B).

## `metadata.json` — структура верхнего уровня

Содержимое: `{"MetaData": {"Schema": {...}}}`. Поля верхнего уровня `MetaData.Schema`:

- `ManagerName`: `"SourceCodeSchemaManager"` — постоянно.
- `UId` — UId самой схемы (используется везде в проекте как идентификатор этого кода).
- `A2` — имя схемы, совпадает с `Name` в `descriptor.json` и с именем `.cs`-файла.
- `A5` — `<A5 как у соседних схем пакета>` (`metadata-editing.md`, поле A5). По коду платформы это CreatedInPackageId (`metadata-codes.md`), но в реальных файлах значения не совпадают ни с одним UId пакета стенда (✅ проверено 29.10.2026).
- `B6` — UId пакета (та же семантика, что у Entity/Process).
- `B8` — версия BPMSoft создания/правки — совпадает с `properties.json.CreatedInVersion`.
- `B2` — ✅ локализуемые строки схемы (`{UId, A2: <ключ>, A3, A4: <UId схемы>, A5}`), значения — в ресурсах `LocalizableStrings.<Ключ>.Value`; непусто у части схем проекта, подтверждено записью 05.10.2026. `B1`, `B3` — пустые у всех схем проекта.
- `HD1` — UId родителя схемы (`ParentSchemaUId` в `metadata-codes.md`). Почти у всех схем исходного кода реального проекта — `50e3acc0-26fc-4237-a095-849a1d534bd3`, у единичных — другие значения или поля нет. Опровергнуто: прежний вывод «фиксированная константа» был сделан по двум примерам.

## Реальный код (`.cs`-файл)

В отличие от Entity, где `.cs`-файл пустой, SourceCode-схема содержит реальный полноценный C#-класс:
- `namespace BPMSoft.Configuration` тоже встречается в реальном коде; классы одного пространства видят друг друга без `using`.
- Стандартные `using`-директивы, например `using BPMSoft.Core;`; `BaseService` (REST-сервис) — `using BPMSoft.Web.Common;`.
- REST-сервис: `[ServiceContract]` на классе, `[WebInvoke]` на методе, класс наследует `BaseService`. Образец — `source-code-edit.md`, «Создать схему исходного кода с нуля».
- Оба варианта пространства встречаются в реальном коде: `namespace BPMSoft.Configuration.<Пространство>` (чаще) и `namespace BPMSoft.Configuration`. Из вложенного пространства к классам `BPMSoft.Configuration` обращайся через `using` или полное имя.
- Базовый класс REST-сервиса — `BaseService` из `BPMSoft.Web.Common` (`using BPMSoft.Web.Common;`). `using BPMSoft.Web;` в реальных файлах не встречается.
- Методы класса с реальной реализацией логики.
- Код компилируется в `Autogenerated` при сборке пакета — то есть SourceCode-схема — это, по сути, просто **именованный, зарегистрированный в системе C#-файл**, доступный из других мест проекта (например из `ScriptTask`/`UserTask` через `using`-директиву с этим пространством имён).

## Ресурсы (`Pkg/<Пакет>/Resources/<ИмяСхемы>.SourceCode/resource.<culture>.xml`)

Тот же общий механизм, что и у процессов/объектов/клиентских схем (см. `processes.md`/`entity.md`/`client-schemas.md`):
- `Caption` — заголовок/подпись SourceCode-схемы (только один элемент, самой схемы, не под-элементов — в отличие от сложных типов типа Entity/Process, где может быть иерархия подписей).
- Формат: `<Item Name="Caption" Value="<Подпись>" />` внутри `<Items>`.
- Как для любого типа схемы (`metadata-editing.md`), создавай и обновляй оба файла, `resource.ru-RU.xml` и `resource.en-US.xml`, даже если система обойдётся без одного из них.
