### Подключение агента к CRM: обновление, компиляция, просмотр интерфейса

**Статус:** ✅ выполнено 13.10.2026: части 1 и 2 сделаны, инструменты используются в прогонах 6–10 (`docs/test-runs/`) и в эвалах.

**Зачем.** Сейчас после записи в `Pkg` агент просит пользователя нажать «Обновить из файловой системы» и «Компилировать», а потом пересказать ошибки. Если агент сам дёрнет эти действия на стенде и прочитает результат, цикл «записал → обновил → скомпилировал → проверил» замыкается без пользователя: ошибки компиляции и загрузки агент видит сразу и исправляет их сам (по правилу «исправление своей ошибки без нового плана»). Вторая часть — агент открывает интерфейс CRM и DevTools: смотрит, как выглядит страница, ошибки консоли браузера и сетевые запросы.

Перед вызовом инструмент запоминает размер файла лога, после вызова читает только дописанное (если за это время сменились сутки — и файл из новой папки), и прикладывает к ответу агенту выдержку:

### Доступ агента к БД CRM (только чтение)

**Статус:** ✅ выполнено 12.10.2026 для PostgreSQL: этапы 1–3 сделаны, инструмент используется в прогонах 5–10 и в эвалах. Не сделано — MS SQL.

**Зачем.** Часть данных есть только в БД, а не в пакетах: Id рабочих мест (`SysWorkplace`), записи базовых справочников, текущие значения системных настроек, регистрация разделов из залоченных пакетов. Сейчас агент просит пользователя выполнить SQL и прислать результат.

#### Как сделать
1. **Инструмент внутри приложения, без отдельного процесса.** Модуль `packages/agent-runtime/src/db/` (`crmDbTool.ts`, `sqlGuard.ts`, `connectionString.ts`) работает в процессе Electron. Claude получает его как in-process MCP-инструмент (`createSdkMcpServer`, имя `mcp__crm_db__crm_db_query`), Cursor — как `local.customTools` (`crm_db_query`; MCP разрешается только при включённом доступе, свои MCP-серверы пользователя не подгружаются — `settingSources: []`).
2. **Учётные данные агент не видит.** Приложение само читает строку `db` из `ConnectionStrings.config` открытой папки приложения; хост, порт, пользователь из настроек и пароль из Keychain переопределяют её (для стенда в docker и отдельного пользователя только для чтения). Для агента файл по-прежнему запрещён песочницей.
3. **Только чтение:** один запрос `SELECT`/`WITH` (комментарии и строки вырезаются перед проверкой), запрещены слова изменения данных и настроек, `SELECT … INTO`, `FOR UPDATE/SHARE`, функции выхода за пределы БД и служебные (`dblink`, `pg_read_file`, `lo_*`, `*_to_xml`, `set_config`, `pg_sleep` и др.), таблицы `pg_authid`, `pg_shadow`, `pg_settings` и др. Запрос выполняется в `BEGIN TRANSACTION READ ONLY` и всегда откатывается.
4. **Ограничения:** тайм-аут 10 с, не больше 200 строк (обёртка `LIMIT 201`), значения длиннее 300 символов обрезаются, колонки вида password/hash/salt/token/secret маскируются; даты отдаются строкой, как в БД.
5. **Настройки:** «Доступ агента к БД CRM» (по умолчанию выключен), «Спрашивать перед каждым запросом» (по умолчанию выключено; карточка разрешения с SQL), кнопка «Проверить подключение». Раздел промпта про БД добавляется только при включённом доступе.
6. **Прозрачность:** каждый запрос, число строк, время и ошибка — в логе чата (`db_query`, в `.md` строка «🗄 Запрос к БД»).

#### Риски
- **Права строки подключения.** Основная учётная запись CRM обычно может писать — защита держится на проверке запроса и транзакции «только чтение»; надёжнее отдельный пользователь только для чтения.
- **Персональные данные в LLM.** Результаты уходят провайдеру модели — лимит строк, маскирование, подтверждение запросов.
- **Нагрузка на сервер БД** — тайм-аут и лимит строк.
- **Сеть.** Приложение подключается с машины пользователя только к хосту из строки подключения; никаких других хостов и серверов.

### Остановка агента кнопкой «Стоп»

**Статус:** 🧪 реализовано 16.10.2026, ждёт ручной проверки (`docs/test-runs/run-12.md`).

**Зачем.** долгий ход нельзя было прервать без перезапуска приложения.

**Как.**
- сигнал отмены во всех провайдерах: Claude — interrupt, через 5 с abort; Cursor — run.cancel без повторов;
- инструменты: run_shell убивает дерево процессов, crm_db_query закрывает соединение, обновление и компиляция CRM прерывают только ожидание;
- ждущие карточки разрешений отклоняются;
- через 10 с после стопа чат разблокируется даже при зависшем SDK;
- следующее сообщение получает пометку о прерванном ходе.

**Риски.** операция на стенде продолжается после стопа; поведение interrupt/cancel проверено только по типам SDK.

### Исходники платформы из DLL для агента

**Статус:** план, ждёт решения по открытым вопросам.

**Зачем.** Иногда агенту нужно понять механизм платформы, которого нет ни в XML-документации `BPMSoft.*.xml`, ни в `Autogenerated`: порядок вызовов, внутренние проверки, значения по умолчанию. Папки с исходниками платформы в реальных проектах нет.

**Что известно.** Рядом с DLL платформы на стенде лежат `.pdb`, поэтому декомпилированный код получается с нормальными именами. Платформенные сборки `BPMSoft.*` весят единицы мегабайт.

#### Как сделать
1. **Декомпилятор.** ILSpy в версии для командной строки (`ilspycmd`, открытая лицензия, ставится как .NET global tool). Декомпилируем только сборки платформы `BPMSoft.*`, без кода конфигурации проекта: он и так есть в `Autogenerated`.
2. **Где хранить.** Не в папке логов (это журналы, их чистят), а в папке данных приложения: `<папка данных приложения>/platform-src/<хеш BPMSoft.Core.dll>/<сборка>/…`. Ключ — хеш DLL, а не стенд: стенды на одной версии платформы используют одну копию, новая версия получает свою папку. Имена стендов в пути не нужны.
3. **Когда делать.** Кнопка в настройках «Подготовить исходники платформы» или предложение при открытии проекта, если копии для этой версии ещё нет. Это фоновая задача приложения, а не агента (порядка минуты). Декомпиляция «по требованию» отдельным инструментом агента возможна только для Claude — у Cursor нет своих инструментов, поэтому основной путь — готовая папка, она работает для всех провайдеров.
4. **Доступ агента.** Папка добавляется только на чтение: в `readRoots` и `sourceRoots` песочницы Claude (как папка большого вывода SDK) и в правила чтения Cursor. Запись туда запрещена.
5. **Промпт.** «Исходники платформы — для понимания механизмов. Факт подтверждай в CRM; в знания пиши без ссылок на исходники». Порядок поиска API: `platform-api.md` → `BPMSoft.*.xml` → `Autogenerated` и `Pkg` → исходники платформы.
6. **Управление.** В настройках — список подготовленных версий с размером и кнопкой удаления.

#### Риски
- **Лицензия — главный.** Лицензионное соглашение BPMSoft может запрещать декомпиляцию. До реализации нужно разрешение владельца лицензии или юриста.
- **Чтение вне CRM.** Агент получает только одну папку под управлением приложения, только на чтение. В ней код платформы, без данных и настроек стенда.
- **Публичный репозиторий.** Исходники никогда не попадают в репозиторий и в знания — только подтверждённые факты без ссылок на исходники.
- **Зависимость от инструментов.** Нужны .NET и `ilspycmd`. Если их нет — понятное сообщение, агент работает как сейчас, по `BPMSoft.*.xml`.
- **Качество кода.** Асинхронный код и итераторы декомпилируются тяжело; для понимания механизма этого достаточно.
- **Объём.** Порядка 100–200 МБ текста на версию платформы; старые версии удаляются из настроек.
