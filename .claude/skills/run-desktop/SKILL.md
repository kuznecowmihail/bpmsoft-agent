# Запуск и проверка desktop-приложения

`driver.mjs` запускает собранное приложение `apps/desktop` через Playwright (`_electron`), выполняет сценарий команд и закрывает приложение. Профиль приложения изолирован: временные userData и папка логов, настоящие «Недавние», ключи и настройки пользователя не затрагиваются.

## Порядок

1. **Зависимости.** `playwright-core` — в devDependencies `apps/desktop`; если `node_modules/playwright-core` нет — `npm install` в корне репозитория. Браузеры Playwright не нужны: используется Electron из `node_modules/electron`.
2. **Сборка.** Драйвер запускает `apps/desktop/out`, а не исходники — после каждой правки пересобери:
   ```bash
   npm run build -w @bpmsoft-agent/metadata-core && npm run build -w @bpmsoft-agent/agent-runtime && npm run build -w @bpmsoft-agent/desktop
   ```
   Правка только в `apps/desktop` — достаточно последней команды.
3. **Сценарий.** Весь сценарий — в одном вызове (между вызовами Bash приложение не живёт). Команды — аргументами или построчно через stdin:
   ```bash
   printf '%s\n' launch "stand off" pick "ss card" | node .claude/skills/run-desktop/driver.mjs
   ```
4. **Смотри скриншоты.** Драйвер печатает пути `screenshot: …png` — открой каждый через Read. Вывод `text` не заменяет скриншот: вёрстку, цвета и перекрытия видно только на картинке.
5. **Отчёт.** Пользователю — что проверено и что видно на скриншотах; пути к ним — если попросит.

## Команды

| Команда | Что делает |
|---|---|
| `launch [--minimal-path]` | Запускает приложение и ждёт первое окно (~3 с). `--minimal-path` — PATH только из системных папок: моделирует компьютер без Node и других программ. |
| `stand [имя] on\|off` | Создаёт тестовый стенд в папке прогона: `BPMSoft.Configuration/Pkg/TestPkg/Schemas` и `BPMSoft.WebHost.dll.config` с включённым (`on`) или выключенным (`off`) режимом разработки в файловой системе. Имя по умолчанию — `stand-on` / `stand-off`. |
| `pick [папка]` | Подменяет нативный диалог выбора папки и нажимает «Открыть проект». Без аргумента — последний созданный `stand`. |
| `click <текст>` | Клик по первому элементу, содержащему текст. |
| `wait <мс>` | Пауза. |
| `ss <имя>` | Скриншот окна в `<папка прогона>/<имя>.png`. |
| `text [селектор]` | Видимый текст элемента (по умолчанию `body`). |
| `eval <js>` | Выражение в renderer (`window.api.*` доступен), результат — JSON. |
| `close` | Закрывает приложение (и так закрывается в конце сценария). |

Строки с `#` пропускаются. При ошибке драйвер снимает `error.png`, закрывает приложение и выходит с кодом 1. Папка прогона — новая во временной папке ОС (печатается первой строкой `out:`), или из переменной `RUN_DESKTOP_OUT`.

## Типовые проверки

- Стартовый экран: `launch`, `ss start`.
- Карточка «Не включён режим разработки в файловой системе»: `launch`, `stand off`, `pick`, `ss card`.
- Открытие проекта и чат: `launch`, `stand on`, `pick`, `ss chat`.
- Нет Node на компьютере: `launch --minimal-path`, `ss nonode` — в «Об устройстве» должна быть проблема.

## Подводные камни

- **Сначала сборка.** Без `npm run build` проверяется старая версия из `out/` — правка «не работает».
- **Путь к Electron** драйвер берёт из пакета `electron` (`require('electron')`): на macOS это `node_modules/electron/dist/Electron.app/Contents/MacOS/Electron`, на Windows — `node_modules/electron/dist/electron.exe`. Свой путь в коде не пиши.
- **Нативный диалог** Playwright не нажимает. `pick` подменяет `dialog.showOpenDialog` в main-процессе (`app.evaluate`) и только потом нажимает «Открыть проект».
- **Изоляция профиля.** Драйвер передаёт `--user-data-dir=<папка прогона>/userData` и `BPMSOFT_AGENT_LOG_DIR=<папка прогона>/logs`. Без них приложение пишет в настоящий userData пользователя (недавние проекты, ключи, настройки) и `environment.json` в его папку логов (на macOS `~/Library/Logs/bpmsoft-agent`). Если всё же запускал без изоляции — убери тестовые проекты из «Недавних»: `eval window.api.removeRecentProject('<путь>')`.
- **PATH.** Неупакованное приложение не вызывает `loadLoginShellPath`: PATH берётся из окружения запуска. Поэтому `--minimal-path` моделирует отсутствие Node, а обычный запуск видит PATH твоего терминала, а не login shell пользователя.
- **Не запускай агента в чате.** Это стоит денег, а стенд общий. В изолированном профиле нет ключей — провайдер не настроен, и это нормально.
- **«Об устройстве» раскрывается сам**, если есть проблемы; `click Об устройстве` в этом случае его сворачивает. Сначала сними скриншот или проверь `aria-expanded` у кнопки.
- **`click` ищет по подстроке** и берёт первый элемент: текст вроде «Проверить снова» есть и в карточке режима, и в «Об устройстве». Уточняй текст или используй `eval` с `document.querySelector`.
- **Скриншоты в двойном масштабе** на Retina (окно ~1100×760 → картинка ~2200×1520).
- **Windows.** Драйвер кроссплатформенный (пути через `path.join`, `--minimal-path` оставляет `System32`), но проверен только на macOS.
- **Тестовый стенд** — пустышка: годится для экрана открытия, карточки режима и пустого чата; CRM, БД и компиляцию на нём не проверить.
