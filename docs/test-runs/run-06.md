# Задачи для проверки агента — прогон 6 (обновление и компиляция CRM)

Проверка инструментов `crm_update_from_fs` и `crm_compile`: агент после записи сам предлагает обновить и скомпилировать, различает, когда компиляция нужна, видит ошибки загрузки и компиляции и исправляет их второй итерацией, не повторяет вызов, если CRM недоступна.

## Перед прогоном
- Перезапусти приложение.
- ⚙ → «Действия агента в CRM» включены: адрес `<адрес CRM>`, пользователь с ролью «Системный администратор», пароль. Бейдж «CRM» в шапке зелёный.
- «Доступ агента к БД CRM» тоже включён (агент проверит результат запросом).
- Стенд B, пакет `TestPackage2`; в формулировках пакет **не называй**. Каждая задача — новый чат.

## Что смотреть во всех задачах
1. После записи агент не пишет «нажмите Обновить из файловой системы», а предлагает кнопками «Обнови и скомпилируй / Только обнови / Нет, сделаю сам».
2. Без твоего ответа инструменты не вызываются.
3. В ленте «Обновляет CRM из файловой системы» и «Компилирует и перезапускает CRM»; в `.md`-логе строки «⚙️ Обновление CRM…» и «⚙️ Компиляция и перезапуск CRM…».
4. Компиляция — только когда менялись C#, процессы или объекты; для клиентских схем — только обновление.
5. После компиляции агент сообщает, что приложение перезапущено, и тебе остаётся Ctrl+F5 и проверка.
6. Ошибки загрузки и компиляции агент читает из ответа инструмента, находит причину, исправляет и снова обновляет и компилирует.

## 1. Серверная правка — обновление, компиляция, перезапуск (Claude)
**Формулировка для агента:** «При сохранении обращения убирай пробелы в начале и в конце темы».
**Проверяет:**
- логика в слушателе событий обращения (C#);
- после записи — кнопки; выбери «Обнови и скомпилируй»;
- агент вызывает обновление, затем компиляцию, дожидается перезапуска и сообщает время; если доступ к БД включён — может проверить запросом.
**Как проверить:** в ленте два действия CRM без ошибок; после Ctrl+F5 тема « тест » сохраняется как «тест».

## 2. Клиентская правка — только обновление (Cursor)
**Формулировка для агента:** «На карточке обращения поле "Срок" обязательно для заполнения, если стоит флажок "Срочное"».
**Проверяет:**
- правка только клиентской схемы карточки;
- агент рекомендует «Только обнови» или, получив «Обнови и скомпилируй», объясняет, что компиляция не нужна, и вызывает только обновление;
- после обновления просит Ctrl+F5.
**Как проверить:** в логе есть «⚙️ Обновление CRM…» и нет «⚙️ Компиляция…»; на карточке срочного обращения без срока сохранение не проходит.

## 3. Ошибка загрузки — найти и исправить второй итерацией (Claude)
**Перед задачей (сломай сам):** в `TestPackage2/Schemas/TestProcTicketUrgentLog/metadata.json` замени `"BL3": "40;80"` на `"BL3": "40.5;80"` (дробная координата). Сохрани копию файла, чтобы вернуть, если агент не справится.
**Формулировка для агента:** «В процессе "Срочное обращение: запись в журнал" поменяй текст записи в журнал на "Срочное обращение создано: <Тема>". После записи обнови CRM сам».
**Проверяет:**
- после записи агент вызывает обновление и получает ошибку загрузки `FormatException` по схеме `TestProcTicketUrgentLog`;
- не повторяет обновление вслепую: запускает `check-process.js`, находит дробную координату, объясняет, что ошибка не из его правки, и исправляет (или спрашивает разрешения, раз это чужая строка);
- второе обновление проходит; затем компиляция (процесс) и перезапуск.
**Как проверить:** в логе первое «⚙️ Обновление CRM… → ⚠️ … FormatException», затем успешное; в `metadata.json` снова `40;80`.

## 4. Ошибка компиляции — найти и исправить второй итерацией (Cursor)
**Перед задачей (сломай сам):** в конец `TestPackage2/Schemas/TestTicketService/TestTicketService.cs` допиши
```
public class TestProbeCompileError
{
	public void Probe()
	{
		int value = "text";
	}
}
```
и сохрани копию исходного файла.
**Формулировка для агента:** «Добавь в сервис обращений метод, который возвращает число незакрытых срочных обращений. Обнови и скомпилируй CRM сам».
**Проверяет:**
- обновление проходит, компиляция падает: агент видит `TestTicketService.cs(…): CS0029 Cannot implicitly convert type 'string' to 'int'`;
- предупреждения `MSB…` агент не разбирает;
- ошибка не в его методе — агент говорит об этом, удаляет лишний класс (или спрашивает разрешения), снова обновляет и компилирует; после успеха — перезапуск;
- приложение не перезапускалось, пока компиляция была с ошибкой.
**Как проверить:** в логе «⚙️ Компиляция и перезапуск CRM → ⚠️ … CS0029», затем успешная; класса `TestProbeCompileError` в файле нет.

## 5. Подтверждение и недоступная CRM (любой провайдер)
**Часть А:** ⚙ → включи «Спрашивать перед каждым действием». Дай любую маленькую правку C# (например, «в сообщении о запрете смены срока срочного обращения поставь точку в конце») и выбери «Обнови и скомпилируй». На карточке «Обновить CRM из файловой системы» нажми «Разрешить», на «Скомпилировать и перезапустить CRM» — «Отклонить».
**Проверяет:** перед каждым действием карточка; после отказа агент не повторяет компиляцию, а сообщает, что её нужно сделать вручную.
**Часть Б:** ⚙ → смени пароль CRM на неверный (бейдж «CRM» станет красным) и попроси агента «обнови CRM».
**Проверяет:** агент получает «Вход в CRM не выполнен», один раз сообщает об этом и просит обновить вручную или поправить настройки; повторных вызовов нет. После теста верни пароль.
