# Задачи для проверки — прогон 14 (проверка окружения)

Проверяем проверку окружения при запуске: блок «Об устройстве» на стартовом экране, файл `environment.json` в логах, стоп-карточки при выключенном режиме файловой системы и отсутствии конфига стенда, предупреждения про Node.js и Git Bash, а также выбор Git Bash на Windows.

## Перед прогоном
- Собери и перезапусти приложение: `npm run build -w @bpmsoft-agent/agent-runtime`, затем `npm run dev -w @bpmsoft-agent/desktop` (или собранное приложение).
- Заданы оба ключа: Claude и Cursor.
- Стенд — отдельный тестовый пакет `<Пакет>`. Агенту даём только задачи на чтение, схемы не создаём.
- Перед правкой конфига стенда сделай его копию рядом (например, `BPMSoft.WebHost.dll.config.bak`). Правки делаем только в файле стенда, копию не трогаем.
- Во время прогона не запускай эвалы и не обновляй стенд из других окон: стенд общий.
- Логи: `~/Library/Logs/bpmsoft-agent/` (macOS) или `<userData>/logs/` (Windows); файл `environment.json` лежит в этой папке.

## 1. Блок «Об устройстве»
**Проверяет:** сведения об устройстве и результат проверки на стартовом экране.
**Как проверить:**
- на стартовом экране есть блок «Об устройстве»: ОС, чип (Apple Silicon / Intel / Rosetta), CPU, RAM, версия приложения и Electron;
- проверки ОС, Node и git показаны с версиями (или с понятной причиной, если чего-то нет);
- `environment.json` появился в папке логов и содержит те же сведения.

## 2. Режим файловой системы выключен
**Проверяет:** стоп-карточку и повторную проверку.
**Как проверить:**
- в конфиге стенда установи `<fileDesignMode enabled="false" />`, открой проект;
- проект не открывается, вместо него карточка с путём к файлу конфигурации, двумя строками о том, что поменять, и кнопкой копирования;
- верни `<fileDesignMode enabled="true" />`, нажми «Проверить снова» — проект открывается.

## 3. UseStaticFileContent = true
**Проверяет:** второй ключ конфига и список проблем.
**Как проверить:**
- установи `<add key="UseStaticFileContent" value="true" />` при корректном `fileDesignMode`;
- поведение то же, что в задаче 2: проект не открывается;
- в списке проблем указан только этот ключ;
- верни `value="false"`, нажми «Проверить снова» — проект открывается.

## 4. Закомментированный fileDesignMode
**Проверяет:** что комментарий не считается включением режима.
**Как проверить:**
- замени строку на `<!-- <fileDesignMode enabled="true" /> -->`, остальные ключи оставь корректными;
- режим считается выключенным: проект не открывается, в списке проблем есть `fileDesignMode`;
- верни строку без комментария и нажми «Проверить снова».

## 5. Нет конфига стенда
**Проверяет:** карточку при отсутствии файла конфигурации.
**Как проверить:**
- сделай копию папки приложения стенда без `BPMSoft.WebHost.dll.config` (на .NET Framework — без `Web.config`) и открой её в приложении;
- карточка «Не найден конфиг стенда» с путём, где файл ожидался;
- после проверки удали копию папки.

## 6. Нет Node.js
**Проверяет:** предупреждение о Node и повторную проверку без остановки работы.
**Как проверить:**
- запусти приложение с PATH без `node`: на macOS временно переименуй симлинк `node` или запусти приложение из терминала с урезанным PATH;
- проект открывается; в шапке ⚠️ «Окружение»; в попапе подсказка и ссылка «Скачать»;
- верни `node` в PATH, перезапусти приложение (или нажми «Проверить снова») — предупреждение пропадает.

## 7. Windows без Git Bash
**Проверяет:** блокировку Cursor, предупреждение для Claude и поведение поля ввода при переключении провайдера.
**Как проверить:**
- на Windows без Git Bash выбери Cursor и открой проект: проект не открывается, причина в тексте карточки;
- выбери Claude и открой проект: проект открывается с предупреждением про Git Bash;
- в «Настройках» под выбором провайдера есть предупреждение;
- в открытом проекте переключись на Cursor: поле ввода неактивно, рядом написана причина.

## 8. Windows с Git for Windows по умолчанию
**Проверяет:** выбор Git Bash, когда в PATH только `Git\cmd`.
**Подготовка:** установлен Git for Windows по умолчанию; в PATH только `Git\cmd`, `bash.exe` в PATH нет.
**Как проверить:**
- выбери Cursor и открой проект: проект открывается без ошибок про Git Bash;
- попроси агента выполнить `date` и `node -v`: команды выполняются через Git Bash, а не через WSL;
- в `environment.json` путь к Git Bash указывает на папку Git for Windows, а не на `System32`.
