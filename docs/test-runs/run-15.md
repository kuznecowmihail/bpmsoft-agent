# Задачи для проверки — прогон 15 (экспорт через MCP-сервер bpmsoft)

Проверяем экспорт в стенд после перехода с `crm.js` на MCP-сервер `bpmsoft`: какие файлы появляются в стенде, подключается ли сервер в Claude Code и Cursor, работают ли инструменты CRM и БД, и что меняется при выключенном доступе к БД. Отдельно проверяем Windows.

## Перед прогоном
- Собери и перезапусти приложение: `npm run build -w @bpmsoft-agent/agent-runtime`, затем `npm run dev -w @bpmsoft-agent/desktop` (или собранное приложение).
- В приложении заданы CRM, включён доступ к БД, настроены Claude и Cursor. Нажми «Установить скиллы» для тестового стенда.
- Стенд — тестовый, работаем в пакете `<Пакет>`. Тестовые схемы создаём только с префиксом `Test…`, после проверки удаляем.
- `node` доступен в PATH: MCP-сервер запускается через него.
- Во время прогона не запускай эвалы и не обновляй стенд из других окон: стенд общий.

## 1. Файлы в стенде
**Проверяет:** состав файлов экспорта и отсутствие старого CLI.
**Как проверить:**
- в корне стенда есть `.mcp.json`, `.cursor/mcp.json` и `.claude/bpmsoft-agent.local.json`;
- в `settings.local.json` нет переменных `BPMSOFT_CRM_*`;
- файла `crm.js` в стенде нет, в том числе в `.claude/skills/bpm-knowledge/scripts/`.

## 2. Claude Code: подключение сервера
**Проверяет:** подключение `bpmsoft` без вопроса о доверии и то, что переменные окружения не попадают в сессию.
**Как проверить:**
- открой стенд в Claude Code и выполни `/mcp`: сервер `bpmsoft` подключён;
- запиши, появился ли вопрос о доверии к серверу проекта (ожидаем: нет);
- в сессии выполни `printenv | grep BPMSOFT`: вывод пустой.

## 3. Claude Code: CRM и БД
**Проверяет:** инструменты обновления, компиляции, запросов и входа в браузер.
**Как проверить:**
- попроси агента создать тестовую схему в `<Пакет>` с префиксом `Test…`;
- `crm_update_from_fs` выполняется без вопроса о подтверждении;
- `crm_compile` спрашивает подтверждение; после подтверждения компиляция проходит;
- `crm_request` к сервису `DataService` возвращает ответ;
- `crm_db_query` на вопрос «сколько записей в SysSettings» возвращает число;
- `crm_browser_login` открывает страницу входа; вход в браузере выполняешь ты, агент пароль не вводит.

## 4. Cursor: подключение и те же шаги
**Проверяет:** видимость сервера в Cursor и тайм-аут компиляции.
**Как проверить:**
- открой Settings → MCP: сервер `bpmsoft` виден; запиши, пришлось ли включать его вручную;
- повтори шаги из задачи 3 в Cursor;
- для `crm_compile` запиши время компиляции и результат. Если компиляция обрывается по тайм-ауту, запиши точный текст ошибки.

## 5. Доступ к БД выключен
**Проверяет:** что `crm_db_query` пропадает из набора инструментов и агент работает через REST.
**Как проверить:**
- в приложении выключи доступ к БД и заново нажми «Установить скиллы»;
- в новой сессии `crm_db_query` в списке инструментов отсутствует;
- спроси агента о данных (например, сколько записей в SysSettings): он идёт через `crm_request`, а не пытается вызвать `crm_db_query`.

## 6. Windows
**Проверяет:** запуск сервера и пути с обратными слешами.
**Как проверить:**
- повтори задачи 1–4 на Windows;
- в `.mcp.json` команда запуска `node`, путь к `bpmsoft-mcp.js` записан с обратными слешами, сервер запускается без ошибок;
- запиши, что показывают `/mcp` в Claude Code и Settings → MCP в Cursor.

---

## Итог
- Для каждой задачи отметь результат и то, что видно в интерфейсе.
- Если сервер не подключился, приложи текст из `/mcp` и первые строки логов приложения: `~/Library/Logs/bpmsoft-agent/` (macOS) или `<userData>/logs/` (Windows).

## После прогона
- Удали тестовые схемы `Test…` из `<Пакет>`: папки в `Pkg`, затем «Обновить из файловой системы».
- Если выключал доступ к БД для задачи 5, включи его обратно.
