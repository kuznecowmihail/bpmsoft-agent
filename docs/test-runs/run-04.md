# Задачи для проверки агента — прогон 4

Короткая проверка после последних доработок, на основе задач 1–3 прогона 3: пакет спрашивается отдельно, объект ищется по названию среди пакетов проекта, порядок событий слушателя и где запрещать, запрет чтения файлов с секретами (`ConnectionStrings.config`), исходников платформы в знаниях больше нет, процесс «не ждать выполнения задачи».

## Общие правила
- Перед прогоном перезапусти приложение.
- Стенд B, пакет `TestPackage2`; в формулировках пакет **не называй** — агент должен спросить его отдельно.
- Каждая задача — новый чат.

## Что смотреть
1. Первый ответ агента — только вопрос о пакете (кнопками), без вопросов по требованиям; вопросы по требованиям — после ответа.
2. «Обращение» агент находит в пакетах проекта (`TestTicket`), не предлагает поля базового `Case`.
3. Агент не читает `ConnectionStrings.config`: в логе нет обращений к нему; если нужен тип СУБД — спрашивает у тебя.
4. В плане и рисках нет упоминаний `ResourcesCore`; источник API — `platform-api.md` и `BPMSoft.*.xml`.
5. Скрипты проверки (`check-entity.js`, `check-process.js`) запущены после записи; Claude не спрашивает разрешений на запись в Pkg; кнопки «Делай / Нужны правки» после плана.
6. Кругов «ошибка → правка» — 0.

## 1. Правила обращения, кнопка и SQL-скрипт (Claude)
**Формулировка для агента:** «Для обращений: срок у срочного обращения менять нельзя — сообщение "Срок срочного обращения менять нельзя"; при создании обращения без типа ставить тип "Вопрос"; при изменении срока писать в историю "Срок изменён: <старый> → <новый>"; на обращении кнопка "Продлить срок на день", видна только у незакрытого обращения с заполненным сроком; и SQL-скрипт пакета, который всем существующим обращениям без типа ставит "Вопрос"».
**Проверяет:**
- пакет спрошен отдельным первым сообщением, объект — `TestTicket` из пакета проекта;
- запрет только на изменении — в `OnUpdating` (не в `OnSaving`); тип по умолчанию при создании — в `OnInserting`; строка истории — в событии «после» (`OnUpdated`), чтобы при отменённом сохранении её не было;
- логика в слушателе, а не на вкладке «События»; все тексты — локализуемые строки ru/en;
- кнопка и на карточке, и в разделе;
- для SQL-скрипта агент не читает `ConnectionStrings.config`, а спрашивает тип СУБД (или берёт его из существующих скриптов пакета) и пишет скрипт под неё.
**Как проверить:** срочное обращение — смена срока запрещена, у несрочного срок меняется и в истории появляется строка; новое обращение без типа получает «Вопрос»; кнопка видна в совмещённом режиме, после Ctrl+F5 и по прямой ссылке; скрипт проставил тип старым обращениям; в логе чата нет `ConnectionStrings`.

## 2. Процесс с задачами без ожидания (Cursor)
**Формулировка для агента:** «Процесс "Контроль срочных обращений" каждый будний день в 8:00 и вручную: для каждого срочного незакрытого обращения ставит ответственному задачу "Срочное обращение <Тема>" сроком 2 часа и не ждёт её выполнения; если у обращения уже есть незавершённая такая задача — вторую не ставит; в конце пишет число поставленных задач в параметр "Итог" и в Common.log».
**Проверяет:**
- пакет спрошен отдельно, объект — `TestTicket`, «срочное» и «незакрытое» — по полям `TestTicket`, а не `Case`;
- «не ждать выполнения» — по рецепту знаний: отдельный процесс с «Выполнить задачу», запускаемый для каждого обращения через `ProcessExecutor.Execute` (не подпроцесс по коллекции);
- таймер по будням, подсчёт, `check-process.js` после записи;
- кнопки подтверждения после плана (если Cursor не поставит блок — запасные кнопки приложения).
**Как проверить:** ручной запуск — задачи у ответственных по срочным незакрытым обращениям, процесс завершается сразу, не дожидаясь задач; повторный запуск не дублирует задачи; «Итог» и строка в `Common.log` с числом; таймер в дизайнере.
