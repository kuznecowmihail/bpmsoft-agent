# Задачи для проверки агента — прогон 3

Проверяем доработки после прогона 2: серверная логика объекта в слушателе, локализуемые тексты, кнопка действия в двух схемах, поиск объекта из задачи среди пакетов проекта, работа без лишних запросов разрешения в Claude, чтение шаблонов из знаний в командах генерации, запасные кнопки «Делай / Нужны правки», скрипт проверки объекта `check-entity.js`.

## Общие правила
- Перед прогоном перезапусти приложение.
- Стенд B, пакет `TestPackage2` (объект «Обращение» `TestTicket` уже есть); новые схемы — с префиксом `Test`.
- Новая задача — новый чат. Провайдер указан у каждой задачи; задачи 1 и 4 повтори на втором провайдере, если будет время.
- После задачи — «Обновить из файловой системы», компиляция при C#, Ctrl+F5.

## Что смотреть в каждом прогоне
1. Claude не спрашивает разрешения на запись файлов в Pkg (только на удаление, git и сторонние программы).
2. Нет ошибок хука «Команда с записью затрагивает путь вне Pkg» при генерации из шаблонов и запуске скриптов проверки.
3. После плана всегда есть кнопки «Делай / Нужны правки» — от агента или запасные от приложения.
4. После записи агент запускает `check-process.js` (процессы) и `check-entity.js` (объекты) и сдаёт с «0 ошибок».
5. Тексты для пользователя — в локализуемых строках на двух языках, в коде нет русских строк сообщений.
6. Число кругов «ошибка → правка» — цель 0.

## 1. Логика объекта — в слушателе, тексты — локализуемые (Claude)
**Формулировка для агента:** «Для обращения: при сохранении, если ответственный не заполнен, подставлять текущего пользователя; закрытое обращение (заполнено "Решение") нельзя изменить — сообщение "Закрытое обращение нельзя изменить"; при смене ответственного писать в историю обращения строку "Ответственный изменён: <старый> → <новый>"».
**Проверяет:** агент находит «обращение» среди объектов пакетов проекта (TestTicket в TestPackage2), а не базовый `Case`, и рекомендует его; новую логику пишет в слушатель, а не на вкладку «События»; читает существующий слушатель и процесс событий обращения и не задваивает поведение; сообщение и текст строки истории — локализуемые строки схемы ru/en; Claude не спрашивает разрешения на запись в Pkg.
**Как проверить:** три сценария на карточке; в `.cs` нет русских текстов сообщений, в `resource.*.xml` слушателя — строки на двух языках; вкладка «События» обращения не изменилась.

## 2. Кнопка действия над записью (Cursor)
**Формулировка для агента:** «В разделе "Обращения" добавь кнопку "Эскалировать" для открытого обращения: ставит "Срочное", пишет в историю "Эскалировано пользователем <контакт>" и показывает сообщение "Обращение эскалировано"; кнопка видна только у незакрытого и несрочного обращения».
**Проверяет:** кнопка и на карточке (`LeftContainer`), и в разделе (`CombinedModeActionButtonsCardLeftContainer`) без отдельной просьбы; вариант «только в разделе» агент не предлагает; видимость общим признаком; подписи и сообщение — локализуемые строки в обеих схемах; после плана кнопки подтверждения.
**Как проверить:** кнопка видна в совмещённом режиме, после Ctrl+F5 на открытой карточке и при переходе по прямой ссылке на запись; пропадает у срочного и закрытого; тексты на английском интерфейсе — английские.

## 3. Процесс из шаблонов знаний (Claude)
**Формулировка для агента:** «Процесс "Напоминание об обращениях" по таймеру каждый будний день в 9:00 и вручную: находит незакрытые обращения со сроком на сегодня и для каждого ставит ответственному задачу "Проверить обращение <Тема>" элементом "Выполнить задачу" со сроком до конца дня, не дожидаясь её выполнения; в конце пишет в комментарий-итог процесса число найденных обращений».
**Проверяет:** генерация процесса node-скриптом с чтением шаблонов `templates/process/*.json` прямо в той же команде — без блокировок хука; `check-process.js` в той же или отдельной команде — без блокировок; Claude не спрашивает разрешений на запись в Pkg; подсчёт через режим Count; таймер по будням; «Выполнить задачу» без ожидания (агент сам выбирает, как не ждать выполнения, и объясняет).
**Как проверить:** ручной запуск ставит задачи по нужным обращениям; таймер в дизайнере; в логе чата нет «Запрос разрешения» на запись и нет «PreToolUse:Bash hook error».

## 4. Новый объект и проверка объекта скриптом (Cursor)
**Формулировка для агента:** «Создай объект "Комментарий обращения" (TestTicketComment): Обращение (ссылка, обязательная), Текст (неограниченная строка, обязательная), Автор (контакт, по умолчанию текущий), Внутренний (логическое); отображаемое значение — Текст; деталь "Комментарии" на карточке обращения, редактируемая в реестре; автор заполняется на сервере, если пуст».
**Проверяет:** агент запускает `check-entity.js` после записи объекта и исправляет строки «ОШИБКА» до ответа; многострочные блоки `+ MetaData.Schema.D2 {…}` закрыты `}` в начале строки; все колонки в `~ MetaData.Schema.D2`; подписи колонок на двух языках; автор — в слушателе, не в процессе событий.
**Как проверить:** объект загрузился с колонками, деталь работает, автор подставляется.
**Вторая часть (делаешь сам, в том же чате после «работает»):** в `metadata.json` нового объекта сдвинь закрывающую `}` одного блока `D2` на два пробела, «Обновить из файловой системы» и напиши агенту: «колонка пропала после обновления». Ожидание: агент запускает `check-entity.js`, находит незакрытый блок и исправляет сразу, без нового плана.
