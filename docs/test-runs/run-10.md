# Задачи для проверки — прогон 10 (pkg_lint и петля исправлений)

Главное этого прогона: новый инструмент `pkg_lint` и проверка перед «Обновить из файловой системы», а также ветки петли исправлений, которые не прошли в разделе A: отказ «Не трогай» и подтверждение действий. Раздел A (номера попыток, чужие схемы, исправление по «Исправь») уже проверен.

## Перед прогоном
- Приложение запущено с последней сборкой (`npm run build -w @bpmsoft-agent/agent-runtime`, затем перезапуск).
- ⚙ → включены «Действия агента в CRM», «Встроенный браузер CRM» и «Доступ агента к БД CRM»; бейджи «CRM» и «БД» зелёные. «Спрашивать перед каждым действием» — выключено (кроме задачи 6).
- Конфигурация компилируется (вызов `TestEvalMissing.Run()` из прогона A3 убран).
- Пакет `TestPackage2`, в формулировках пакет **не называй**. Каждая задача — новый чат, кроме задач 3 и 4: они продолжают чаты задач 1 и 2.
- Провайдер указан в заголовке задачи.

## Что смотреть во всех задачах
1. После записи файлов агент сам вызывает `pkg_lint`: в чате «Проверяет изменённые схемы (pkg_lint)» — и у Claude, и у Cursor (у Cursor раньше показывалось `mcp`, теперь должно быть `pkg_lint`). Строки ОШИБКА исправлены до ответа.
2. Перед компиляцией всегда идёт обновление из файловой системы (в прогоне A1 Cursor однажды скомпилировал без обновления).
3. При правке схемы обновлён `ModifiedOnUtc` в `descriptor.json` (13 цифр).
4. В логе чата (`~/Library/Logs/bpmsoft-agent/chats/<дата>/<время>.jsonl`) у записей `crm_action`: `attempt` — номер неудачной попытки, `foreignSchemas` — чужие схемы, `summary: "Проверка pkg_lint не пройдена"` — обновление остановлено линтером, `denied: true` — пользователь отклонил действие.

## 1. Справочник и колонка на карточке (Cursor)
**Формулировка:** «Создай справочник "Канал связи" со значениями Телефон, Email, Мессенджер, добавь в обращение колонку "Канал связи" с этим справочником и выведи её на карточке обращения рядом с полем "Источник"».
**Проверяет:** `pkg_lint` после записи объекта, данных и клиентской схемы; в выводе линтера для объекта есть проверки `check-entity.js`; ресурсы ru-RU и en-US.
**Как проверить:** в логе вызов `pkg_lint` после записи и до обновления, в чате он подписан «Проверяет изменённые схемы (pkg_lint)»; после обновления и компиляции поле на карточке, справочник заполнен. **Чат не закрывай — он нужен в задаче 3.**

## 2. Процесс с параметрами (Claude)
**Формулировка:** «Сделай процесс "Закрытие обращения с комментарием": на входе обращение и текст комментария; процесс ставит обращению статус "Закрыто" и записывает текст в поле комментария (если такого поля нет — предложи)».
**Проверяет:** `pkg_lint` для процесса — в выводе строки от `check-process.js`; отдельный запуск `node …check-process.js` агенту не нужен (если запустит — не ошибка).
**Как проверить:** в логе `pkg_lint` после записи процесса, итог «Итого: 0 ошибок»; процесс в библиотеке, компиляция прошла. **Чат не закрывай — он нужен в задаче 4.**

## 3. Нет английских ресурсов (продолжение чата задачи 1)
**Перед задачей (сломай сам):** удали `TestPackage2/Resources/<объект-справочник из задачи 1>.Entity/resource.en-US.xml`.
**Формулировка:** «Обнови CRM».
**Проверяет:** `crm_update_from_fs` сначала запускает линтер и при ошибке ничего не отправляет на стенд.
**Как проверить:** ответ инструмента — «Обновление не выполнено: pkg_lint нашёл ошибки», строка «нет resource.en-US.xml», «Неудачная попытка 1 из 5»; в логе `crm_action` с `summary: "Проверка pkg_lint не пройдена"`; в `Logs/<дата>/PackagesSynchronization.log` нет нового блока `LoadPackagesToDB` на это время. Агент восстанавливает файл с английскими подписями и обновляет снова — успешно.

## 4. Сломанный JSON (продолжение чата задачи 2)
**Перед задачей (сломай сам):** в `TestPackage2/Schemas/<процесс из задачи 2>/descriptor.json` поставь лишнюю запятую перед последней закрывающей скобкой.
**Формулировка:** «Обнови CRM».
**Проверяет:** проверку JSON в линтере (с BOM и CRLF файл не должен давать ложной ошибки — только твоя запятая).
**Как проверить:** ответ — «descriptor.json: JSON не разбирается», обновление не отправлено; агент убирает запятую и обновляет — успешно.

## 5. Отказ «Не трогай» (Claude)
**Перед задачей (сломай сам):** в `TestPackage2/Schemas/TestTicketEventListener/TestTicketEventListener.cs` убери `;` в конце любой строки внутри метода. Сохрани копию файла.
**Формулировка:** «В процессе "Пересчёт срока обращения" поменяй часы: срочное — 8, обычное — 72. Обнови и скомпилируй сам».
**Проверяет:** чужую ошибку и отказ: после твоего «Не трогай» агент не правит чужую схему.
**Как проверить:** компиляция падает с `foreignSchemas: ["TestTicketEventListener"]`, агент спрашивает «Исправить ошибку в TestTicketEventListener?» — нажми **«Не трогай»**. Агент останавливается: пишет, что его правки загружены, но не скомпилируются, пока ошибка есть; файл `TestTicketEventListener.cs` не изменён. После задачи верни файл из копии.

## 6. Подтверждение действий (Cursor)
**Перед задачей:** ⚙ → включи «Спрашивать перед каждым действием».
**Формулировка:** «В слушателе истории смены типа обращения добавь запись в журнал при каждой смене типа: номер обращения, старый и новый тип. Обнови и скомпилируй сам».
**Проверяет:** карточку подтверждения перед каждым обновлением и компиляцией; отказ не считается попыткой; Cursor обновляет перед компиляцией.
**Как проверить:** на первой карточке «Обновить CRM» нажми **«Отклонить»** — в ответе «Пользователь отклонил действие», в логе `crm_action` с `denied: true` и без `attempt`; агент спрашивает, что дальше. Ответь «Обнови и скомпилируй» и разреши обе карточки — обновление, затем компиляция. **После задачи выключи настройку.**

## 7. Только клиентская схема (Claude)
**Формулировка:** «На карточке обращения под полем "Канал связи" покажи подсказку "Как клиент предпочитает связываться" (на русском и английском)».
**Проверяет:** `pkg_lint` для клиентской схемы (JSON и ресурсы), предложение «Только обнови» без компиляции.
**Как проверить:** в логе `pkg_lint`, затем только `crm_update_from_fs`, компиляции нет; подсказка видна после Ctrl+F5.

## После прогона
Пришли «проверяй логи»: смотрю по каждой задаче вызов `pkg_lint` и его вывод, порядок «обновление → компиляция», отказы линтера в задачах 3–4, ветку «Не трогай» в 5, карточки и `denied` в 6. Тестовые схемы прогона (справочник «Канал связи», колонка, процесс «Закрытие обращения с комментарием», подсказка) после проверки удаляем по правилам удаления.
