# Задачи для проверки агента — прогон 7 (клиентская сторона и встроенный браузер)

Проверка последовательности на клиенте: правка клиентской схемы → только «Обновить из файловой системы» (без компиляции) → агент сам открывает страницу во встроенном браузере → проверяет, что элемент появился (текст, при необходимости снимок) → смотрит консоль и сеть → при ошибке находит причину, исправляет, снова обновляет и перепроверяет.

## Перед прогоном
- Перезапусти приложение.
- ⚙ → включены «Действия агента в CRM», «Встроенный браузер CRM» и «Доступ агента к БД CRM»; адрес `<адрес CRM>`, верный пароль; бейджи «CRM» и «БД» зелёные. «Спрашивать перед каждым действием» — выключено.
- Стенд B, пакет `TestPackage2`; в формулировках пакет **не называй**. Каждая задача — новый чат.

## Что смотреть во всех задачах
1. После записи клиентской схемы агент предлагает обновить CRM и выбирает только обновление — компиляции в логе нет («⚙️ Обновление CRM…» есть, «⚙️ Компиляция…» нет).
2. После обновления агент сам открывает страницу во встроенном окне («Открывает страницу CRM …»), окно видно.
3. Проверка результата — текстом страницы (`crm_browser_text`), консолью (`crm_browser_console`), при надобности сетью (`crm_browser_network`); снимок — только когда нужно увидеть вёрстку.
4. Клики — только для навигации и проверки, каждый с карточкой подтверждения; данные агент не сохраняет и не меняет.
5. Итог агента опирается на то, что он увидел в браузере (цитирует текст, ошибки консоли или ответ сервера), а не на «должно работать».
6. В `.md`-логе строки «🌐 Браузер CRM: …», base64 снимков в логе нет.

## 1. Поле на карточке и проверка в браузере (Claude)
**Формулировка для агента:** «На карточке обращения выведи поле "Дата создания" только для чтения, под полем "Дата ответа". Проверь сам в браузере, что оно появилось и ошибок в консоли нет».
**Проверяет:**
- правка только клиентской схемы карточки, затем только обновление;
- Id любого обращения агент берёт запросом к БД и открывает карточку `#CardModuleV2/TestTicketPage/edit/<Id>`;
- в тексте страницы есть подпись «Дата создания» и значение; консоль без ошибок; итог с цитатой из страницы.
**Как проверить:** после Ctrl+F5 поле видно под «Дата ответа» и недоступно для редактирования; в логе одно обновление без компиляции и вызовы браузера.

## 2. Кнопка с сообщением и клик в браузере (Cursor)
**Формулировка для агента:** «На карточке обращения добавь кнопку "Показать срок": по нажатию сообщение "Срок: <дата>" или "Срок не указан". Проверь кнопку сам в браузере».
**Проверяет:**
- кнопка и на карточке, и в совмещённом режиме раздела (правило «кнопка в двух схемах»), тексты — локализуемые строки ru/en;
- после обновления агент открывает карточку, находит кнопку в тексте страницы, кликает (карточка подтверждения — разреши) и читает текст появившегося сообщения;
- консоль без ошибок после клика.
**Как проверить:** в логе «🌐 Браузер CRM: crm_browser_click …» с твоим разрешением; агент цитирует текст сообщения; кнопка работает у тебя после Ctrl+F5.

## 3. Раздел не открывается — ошибка в консоли (Claude)
**Перед задачей (сломай сам):** в `TestPackage2/Schemas/TestTicketSection/TestTicketSection.js` найди строку `}, {subject: subject}, this);` и в следующей строке `},` удали запятую (останется `}`). Сохрани копию файла. Нажми «Обновить из файловой системы» в CRM сам или попроси агента в задаче.
**Формулировка для агента:** «Раздел "Обращения" перестал открываться. Разберись в браузере, в чём причина, и почини».
**Проверяет:**
- агент открывает раздел во встроенном браузере, читает консоль и находит ошибку загрузки модуля (`SyntaxError` / `Unexpected token` с файлом `TestTicketSection`);
- находит место в файле, объясняет, что строка сломана не в его правке, показывает план исправления (одна запятая) и ждёт «Делай» или чинит как исправление ошибки — по правилам промпта;
- после правки — только обновление, повторное открытие раздела, консоль без этой ошибки, реестр обращений виден в тексте страницы.
**Как проверить:** в логе первая проверка консоли с ошибкой, затем после обновления — без неё; запятая на месте.

## 4. Кнопка «Проверить» на карточке ничего не делает — ошибка сети (Cursor)
**Перед задачей (сломай сам):** в `TestPackage2/Schemas/TestTicketPage/TestTicketPage.js` в методе `onTestCheckClick` замени `ServiceHelper.callService("TestTicketService", "Check",` на `ServiceHelper.callService("TestTicketService", "CheckX",`. Сохрани копию. Обнови CRM из файловой системы.
**Формулировка для агента:** «На карточке обращения кнопка "Проверить" выдаёт ошибку вместо результата. Разберись в браузере и почини».
**Проверяет:**
- агент открывает карточку, кликает «Проверить» (подтверди), смотрит сеть (`crm_browser_network`) и видит запрос `…/TestTicketService/CheckX` с ошибкой (404 или 500) и тело ответа;
- сверяет с методами сервиса (`TestTicketService.cs` — метод `Check`) и с вызовом в разделе (там `Check`), исправляет имя метода в карточке;
- только обновление (сервис не менялся), повторный клик (подтверди) — запрос к `Check` без ошибки, агент цитирует результат проверки из сообщения.
**Как проверить:** в логе запрос с ошибкой при первом клике и успешный при втором; в файле снова `"Check"`.
