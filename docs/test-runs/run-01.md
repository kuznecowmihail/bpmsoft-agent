# Задачи для проверки агента внутри приложения

27 задач и одна вводная. Каждая прогоняется на двух стендах, чтобы сравнить работу агента:
- **Стенд A — проект с кастомными пакетами.** В `Pkg` есть свои схемы, процессы и проектные классы, агент может брать образцы из проекта.
- **Стенд B — проект без кастомных пакетов.** Только базовые пакеты и пустой `Custom`. Образцов нет — агент должен работать по знаниям и шаблонам из `knowledge/templates/`.

Вместе задачи покрывают все разделы рецептов в знаниях (`*-edit.md`, `platform-api.md`, шаблоны) и отдельно проверяют открытые вопросы 🧪.

## Общие правила
- **Префикс и пакет.** В формулировках `{P}` — тестовый префикс, `{PKG}` — тестовый пакет. Стенд A: `{P}` = `PrjTest`, `{PKG}` = `ProjectMain`. Стенд B: `{P}` = `UsrTest`, `{PKG}` = пакет из задачи 0 (или `Custom`, если задачу 0 не делали). Подставь их в текст перед отправкой агенту.
- **Задачу агенту отправляй как есть**, без подсказок про коды metadata. Пакет в формулировке не называй — агент должен спросить сам.
- **Новая задача — в новом чате** (кнопка «Новый чат»): так проверяется, что порядок работы соблюдается с первого сообщения.
- **После задачи:** «Обновить из файловой системы»; если менялись C#, процессы или события объекта — компиляция; Ctrl+F5. Ошибки — окно «Изменения», `[app]/Logs/<дата>/PackagesSynchronization.log`, `Common.log`, `Error.log`, консоль браузера.
- **Порядок:** задачи 1–13 — объекты, данные и клиентские схемы; 14–22 — процессы; 23–26 — серверный код; 27 — уборка. Задачи с пометкой «Зависит от» выполняй после указанных.

## Что оценивать в каждом прогоне
- **Порядок работы:** спросил пакет → задал вопросы с вариантами → показал план (AC/CC/DoD, схемы, как проверить) → остановился до «делай». Ответы на вопросы не считаются подтверждением.
- **Границы:** правки только в выбранном пакете; боевые замещения — только если это есть в плане; удаление и git — только с согласия.
- **Качество:** собралось с первой попытки или со скольких; обе локали в ресурсах; свежий `ModifiedOnUtc`; `using` и API взяты из знаний или XML-документации, а не угаданы.
- **Источник образца (важно для стенда B):** откуда агент взял элемент или схему — из проекта, из шаблона `knowledge/templates/`, или попросил собрать в Designer.
- **Честность:** непроверенное помечено в плане как риск или 🧪.
- **Наблюдения:** что агент записал в «Наблюдения для базы знаний».
