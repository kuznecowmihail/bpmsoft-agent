# Задачи для демонстрации агента

Шесть коротких задач из разных областей BPMSoft. Каждая занимает у агента 3–5 минут, от первого сообщения до проверки на стенде.

Время взято из прогонов эвалов на тех же задачах (провайдер Claude). Туда входят вопросы агента, план, запись файлов, `pkg_lint`, обновление стенда и компиляция. Ответы в эвалах приходят мгновенно, поэтому на живом показе прибавьте полминуты-минуту на свои ответы.

## Подготовка

- **Провайдер — Claude.** На этих задачах Cursor заметно медленнее: создание объекта с колонкой у него занимает 9–10 минут.
- **Тестовый пакет на стенде**, например `<тестовый пакет>`. Все схемы — с префиксом `Demo`, чтобы потом их легко найти и удалить.
- **Настройки:** включены «Доступ агента к БД CRM», «Действия агента в CRM» и «Встроенный браузер CRM». Бейджи «БД» и «CRM» в шапке — зелёные.
- **Проверка окружения:** на стартовом экране в блоке «Об устройстве» должно быть «всё готово». На стенде включена разработка в файловой системе (`fileDesignMode` и `UseStaticFileContent=false`), иначе приложение не откроет проект.
- **Каждая задача — в новом чате** («Новый чат»).
- **Проверьте, что задачи ещё нет на стенде.** Схемы `Demo…` из прошлого показа удалите заранее, иначе агент найдёт готовое и покажет меньше.

Ответы по ходу задачи у всех одинаковые:

| Вопрос агента | Ответ |
| --- | --- |
| В каком пакете делать? | `<тестовый пакет>` |
| Связывать пакеты, менять зависимости? | Не связывать: делай только в `<тестовый пакет>` |
| Подтверждаете план? | Делай |
| Обновить CRM сейчас? | Обнови и скомпилируй (для клиентских схем и SQL — «Только обнови») |
| Проверить реализацию в браузере? | Проверь сам |

## Рекомендуемый порядок

| № | Область | Задача | Время |
| --- | --- | --- | --- |
| 1 | Анализ без правок | Как устроена карточка контакта | 1–2 мин |
| 2 | Клиентская схема | Проверка поля при сохранении карточки | 2,5–3,5 мин |
| 3 | БД и SQL-скрипт | Подсчёт по базе и заполнение справочника | 2–3 мин |
| 4 | Бизнес-процесс | Процесс копирования контакта | 4–5 мин |
| 5 | C# и REST | Свой веб-сервис, который агент сам вызывает | 3 мин |
| 6 | Права доступа | Объект с правами по записям | 4,5 мин |

Если времени мало, оставьте задачи 1, 2, 3 и 5: в них есть вопрос без правок, клиентская схема, БД и проверка на стенде через REST.

## 1. Анализ проекта без правок

**Что показывает:** агент отвечает на вопрос об устройстве проекта сразу, без пакета, плана и подтверждения. Он опирается на базу знаний и на иерархию клиентских схем.

**Задача:**

> Объясни, как устроена карточка контакта ContactPageV2: из каких слоёв она собрана, в каких пакетах её замещают и откуда берутся поля в шапке.

**Время:** 1–2 минуты (оценка: такого кейса в эвалах нет).

**Что показать:** список слоёв карточки по пакетам и ответ без единой записи в файлы.

## 2. Клиентская схема: проверка при сохранении

**Что показывает:** вопросы кнопками, план с критериями приёмки, правку замещения карточки, сообщения на двух языках. Обновление без компиляции и проверку во встроенном браузере.

**Задача:**

> На карточке контакта ContactPageV2 запрети сохранять контакт с заполненным контрагентом, если не заполнено поле «Должность»: при сохранении показывай понятное сообщение на русском и английском.

**Время:** 2,5–3,5 минуты (эвал 03: 146–200 с).

**Что показать в CRM:** контакт с контрагентом и пустой должностью не сохраняется, появляется сообщение. После заполнения должности сохранение проходит.

**Запасной вариант той же области** (запрос к базе с клиента, 2–4 мин, эвал 09):

> На карточке контакта ContactPageV2 запрети сохранять контакт, если у другого контакта уже указан такой же e-mail (колонка Email). Проверку делай на клиенте при сохранении, запросом к базе, без нового серверного кода. Пустой e-mail не проверяй. Сообщение — на русском и английском.

## 3. БД и SQL-скрипт пакета

**Что показывает:** агент сам читает БД запросом SELECT, пишет SQL-скрипт пакета и после обновления проверяет результат в базе.

**Задача:**

> Посчитай по базе, сколько активностей (Activity) в каждом статусе, и заполни в справочнике статусов активностей колонку «Описание» текстом вида «Записей: N» — через SQL-скрипт пакета с именем DemoStatusDescription.

**Время:** 2–3 минуты (эвал 05: 122–193 с, один прогон — 313 с).

**Что показать:** запрос к БД в «Выполнено действий», скрипт в пакете. Справочник «Статусы активностей» с заполненным описанием.

## 4. Бизнес-процесс

**Что показывает:** процесс с нуля: параметры, чтение и добавление данных, формула, выходной параметр. `pkg_lint` с проверкой процесса, обновление и компиляцию.

**Задача:**

> Сделай процесс DemoCopyContactProcess («Копирование контакта (демо)»): на входе Id контакта; процесс создаёт новый контакт с тем же ФИО, типом и контрагентом, к ФИО добавляет приставку «Копия: » и возвращает текстом Id нового контакта.

**Время:** 4–5 минут (эвал 02: 254–311 с).

**Что показать:** процесс в дизайнере процессов. Запуск с Id любого контакта и новый контакт «Копия: …».

## 5. C# веб-сервис и самопроверка через REST

**Что показывает:** серверный код на C#, компиляцию. Агент сам вызывает сервис на стенде REST-запросом и приводит ответ.

**Задача:**

> Сделай веб-сервис в исходном коде DemoContactCountService (класс с тем же именем) с POST-методом GetCount без параметров: возвращает число контактов, которые видит текущий пользователь (выборка EntitySchemaQuery с учётом прав). После обновления и компиляции сам вызови сервис на стенде и пришли ответ, который он вернул.

**Время:** около 3 минут (эвал 16: 184 с).

**Что показать:** в ответе агента — код HTTP и число контактов, которое вернул сервис.

## 6. Права доступа по записям

**Что показывает:** новый объект, администрирование по записям и права по умолчанию, заложенные в пакет, — то, что обычно настраивают руками.

**Задача:**

> Сделай объект DemoDocument («Документ (демо)») с текстовой колонкой Name. Доступ к документам — по записям: автор видит, меняет и удаляет свои документы, а все сотрудники могут только читать документы, созданные сотрудниками. Раздачу прав по умолчанию заложи в пакет, чтобы она переносилась на другие стенды.

**Время:** около 4,5 минуты (эвал 12: 264–280 с).

**Что показать:** в «Конфигурации» объект с включённым администрированием по записям, в пакете — данные или скрипт с правами по умолчанию.

## После показа

Удалите всё, что создали задачи: схемы `Demo…` из `<тестовый пакет>`, процесс, сервис, SQL-скрипт и данные прав. Можно попросить агента в новом чате:

> Удали из пакета <тестовый пакет> все схемы с префиксом Demo, которые мы создали для демонстрации.

Агент проверит ссылки на эти схемы и спросит подтверждение перед удалением. Описания статусов активностей, заполненные в задаче 3, SQL-скрипт не откатит: очистите их отдельным запросом или оставьте, если стенд тестовый.
